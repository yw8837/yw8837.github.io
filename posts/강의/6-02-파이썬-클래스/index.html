이어드림스쿨 AI 과정 파이썬 중급 — 클래스(OOP) 정리입니다. “팀원·부서가 있는 IT 회사"를 코드로 만들어 보며 객체지향의 핵심을 처음 배우는 분도 이해하게 풀어 썼습니다. 🏢

📖 수업 내용#

01 · 클래스 = 설계도, 인스턴스 = 실제 물건#

클래스(Class) 는 물건을 찍어내는 설계도(붕어빵 틀) 이고, 그 틀로 만든 실제 붕어빵 하나하나가 인스턴스(객체) 입니다.

class TeamMember:   # 클래스 이름은 첫 글자 대문자(관례)
    pass            # 아직 내용 없는 빈 설계도

member1 = TeamMember()   # 설계도로 만든 실제 객체(인스턴스)
member2 = TeamMember()
print(member1 is member2)   # False — 서로 다른 객체

💡 “팀원"이라는 개념을 코드로 표현할 때: 속성(데이터) = 이름·직책·연봉, 메서드(행동) = 자기소개·연봉협상.

02 · __init__ 와 self — 객체가 태어날 때#

__init__은 인스턴스가 생성되는 순간 자동 실행되는 특별한 함수(생성자)입니다. 여기서 초기 속성을 정합니다. self는 “나 자신(이 객체)” 을 가리켜요.

class TeamMember:
    def __init__(self, name, role, salary):
        self.name = name       # self.속성 = 값  → 이 객체의 속성 저장
        self.role = role
        self.salary = salary

alice = TeamMember("Alice", "시니어 개발자", 6000)
print(f"{alice.name} / {alice.role} / {alice.salary}만원")
# Alice / 시니어 개발자 / 6000만원

💡 alice.name 처럼 객체.속성 으로 값을 꺼냅니다.

03 · 메서드 — 객체가 하는 “행동”#

클래스 안에 정의한 함수가 메서드입니다. 첫 번째 매개변수는 항상 self.

class TeamMember:
    def __init__(self, name, role, salary):
        self.name, self.role, self.salary = name, role, salary

    def introduce(self):                       # 메서드(행동)
        print(f"안녕하세요! {self.role} {self.name}입니다.")

    def negotiate_salary(self, amount):        # 연봉 올리기
        self.salary += amount
        print(f"{self.name}님 연봉이 {self.salary}만원이 됐습니다.")

alice = TeamMember("Alice", "주니어 기획자", 3000)
alice.introduce()              # 안녕하세요! 주니어 기획자 Alice입니다.
alice.negotiate_salary(2000)   # Alice님 연봉이 5000만원이 됐습니다.

💡 alice.introduce() — 객체 뒤에 .메서드(). self는 자동으로 alice가 들어가서 안 적습니다.

04 · 클래스 변수 vs 인스턴스 변수#

구분 설명 위치
인스턴스 변수 객체마다 다른 값 (이름·연봉) __init__ 안 self.x
클래스 변수 모든 객체가 공유하는 값 (회사명) 클래스 안, __init__ 밖 
class TeamMember:
    company_name = "이어드림"     # 클래스 변수 (모두 공유)
    total_members = 0            # 전체 인원 카운터

    def __init__(self, name):
        self.name = name         # 인스턴스 변수 (각자 다름)
        TeamMember.total_members += 1   # 새 객체마다 +1

a = TeamMember("Alice")
b = TeamMember("Bob")
print(TeamMember.total_members)   # 2
print(a.company_name)             # 이어드림 (공유)

05 · __str__ / __repr__ — 객체를 글자로#

객체를 print하면 기본은 <...object at 0x...> 처럼 어렵게 나와요. 이걸 보기 좋게 바꾸는 매직 메서드입니다.

class TeamMember:
    def __init__(self, name, role):
        self.name, self.role = name, role
    def __str__(self):                 # print() 할 때 — 사람이 읽기 좋게
        return f"{self.role} {self.name}"
    def __repr__(self):                # 디버깅용 — 정확한 표현
        return f"TeamMember('{self.name}', '{self.role}')"

alice = TeamMember("Alice", "개발자")
print(alice)         # 개발자 Alice

06 · 클래스 메서드 · 정적 메서드#

종류 데코레이터 첫 인자 쓰임
인스턴스 메서드 없음 self 객체 데이터 사용
클래스 메서드 @classmethod cls 클래스 변수 사용, 대체 생성자
정적 메서드 @staticmethod 없음 클래스와 관련된 독립 기능 
class TeamMember:
    total = 0
    def __init__(self, name): self.name = name; TeamMember.total += 1

    @classmethod
    def get_total(cls):                       # cls = 클래스 자신
        return cls.total

    @staticmethod
    def is_valid_salary(salary):              # self·cls 없음
        return 1000 <= salary <= 10000

print(TeamMember.is_valid_salary(6000))   # True

💡 @classmethod·@staticmethod 앞의 @는 데코레이터 — 함수에 기능을 “표시"하는 장치입니다. (자세한 건 아래 참고자료)

07 · 상속 (Inheritance) — 물려받기#

기존 클래스(부모)의 속성·메서드를 물려받아 새 클래스(자식)를 만듭니다. 공통은 부모에, 다른 점만 자식에 추가해요.

class Department:                 # 부모: 모든 팀의 공통
    def __init__(self, team_name):
        self.team_name = team_name
        self.members = []
    def add_member(self, m):
        self.members.append(m)

class DevTeam(Department):        # 자식: Department 상속
    def __init__(self, tech_stack):
        super().__init__("개발팀")    # 부모의 __init__ 호출
        self.tech_stack = tech_stack  # 개발팀만의 추가 속성

dev = DevTeam(["Python", "React"])
print(dev.team_name)   # 개발팀 (물려받음)

💡 super()는 부모 클래스를 가리킵니다. super().__init__(...)로 부모의 초기화를 그대로 실행해요.

08 · 오버라이딩 · 다형성 (Polymorphism)#

  • 오버라이딩: 부모 메서드를 자식이 자기 방식대로 다시 정의
  • 다형성: 같은 메서드 이름을 호출해도 객체(팀)마다 다르게 동작
class Department:
    def team_meeting(self):
        print(f"{self.team_name} 회의 시작")

class DevTeam(Department):
    def team_meeting(self):                  # 오버라이딩
        print("개발팀: 스프린트 계획 회의")

class SalesTeam(Department):
    def team_meeting(self):
        print("영업팀: 매출 현황 회의")

# 다형성 — 같은 호출, 다른 결과
for team in [DevTeam(), SalesTeam()]:
    team.team_meeting()
# 개발팀: 스프린트 계획 회의
# 영업팀: 매출 현황 회의

09 · isinstance() · issubclass() 🔜 예습 (아직 안 배움 · 배운 뒤 보강)#

⏳ 이 부분은 수업에서 아직 안 다뤘어요. 흐름상 함께 알아두면 좋아 짧게만 적어둡니다. 정식 정리는 배운 뒤 보강할게요.

객체가 어떤 클래스에서 나왔는지 확인하는 함수입니다.

isinstance(dev, DevTeam)        # True  — dev가 DevTeam의 인스턴스인가?
isinstance(dev, Department)     # True  — 부모 타입으로도 True
issubclass(DevTeam, Department) # True  — DevTeam은 Department의 자식인가?

📚 참고자료#

수업에 없던 내용을 Python 공식 문서에서 보충했습니다.

super() 더 알기#

자식이 부모의 메서드를 그대로 쓰고 싶을 때 super().메서드(). 다중 상속에서도 호출 순서를 똑똑하게 정리해 줍니다.

매직 메서드(던더 메서드)#

__init__, __str__처럼 앞뒤 밑줄 2개(__)인 메서드. 파이썬이 특정 순간에 자동 호출해요. __len__(len() 동작), __eq__(== 비교), __add__(+ 연산) 등. → 데이터 모델 문서

데코레이터(@)란?#

함수/메서드 위에 @이름 을 붙여 기능을 더하는 장치. @classmethod, @staticmethod, @property가 대표적. “함수를 감싸 추가 동작을 입히는 포장지"라고 보면 됩니다.

캡슐화 — _, __ 관례#

  • _name : “외부에서 직접 쓰지 마세요"라는 약속(관례)
  • __name : 이름이 살짝 바뀌어(name mangling) 외부 접근을 더 막음

파이썬은 강제 private이 없고 관례로 표현합니다.

마무리#

클래스는 설계도, 객체는 그 설계도로 만든 실제 물건. 데이터(속성)와 행동(메서드)을 한 덩어리로 묶고(캡슐화), 공통은 부모에 두고 물려받으며(상속), 같은 명령에 다르게 반응하게(다형성) 만드는 것 — 이게 객체지향(OOP) 의 핵심입니다.

처음엔 self가 낯설지만, “객체.메서드() 하면 그 객체가 self로 들어간다"만 기억하면 술술 풀립니다. 직접 팀원·팀을 만들어 보세요! 💪
