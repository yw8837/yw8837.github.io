이어드림스쿨 AI 과정 파이썬 라이브러리 활용 정리입니다. 남이 만든 강력한 도구를 가져다 쓰는 법부터, 내가 만든 코드를 PyPI에 실제로 배포하는 전 과정까지 배웁니다. 📦🌍

📖 수업 내용#

01 · 라이브러리·모듈·패키지·프레임워크#

코딩을 하다 보면 비슷한 말이 자꾸 나옵니다. 한 번 정리하고 넘어가요.

구분 정의 비유
모듈(Module) 함수·클래스·변수를 담은 파이썬 파일 하나(.py) 책 한 권
패키지(Package) 여러 모듈을 폴더로 묶은 것 (__init__.py 포함) 책장 하나
라이브러리(Library) 패키지를 포함해 문서·매뉴얼까지 갖춘 배포 단위 “상품화된” 도서 세트
프레임워크(Framework) 여러 사람이 함께 만드는 더 큰 공동 개발 구조 도서관 전체

💡 라이브러리 = 누군가 미리 만들어 둔 코드 묶음. 바퀴를 다시 발명하지 않고 가져다 쓰는 게 핵심이에요. 시각화·크롤링·AI 같은 고급 기능은 기본 문법만으로는 한계가 있어서 라이브러리가 필수입니다. 도서관 비유로 보면: 필요한 책만 골라 빌리듯, 필요한 라이브러리만 골라 씁니다.

표준 라이브러리 vs 외부 라이브러리:

구분 설명 예시
표준 라이브러리 파이썬에 기본 내장 (설치 불필요) math, random, datetime, os, json
외부 라이브러리 PyPI에서 따로 설치 numpy, pandas, requests, matplotlib

대표적인 외부 라이브러리:

  • numpy — 수치·배열 계산 / pandas — 표 데이터 분석
  • matplotlib·seaborn — 그래프 시각화 / requests — 웹 요청
  • scikit-learn — 머신러닝 / BeautifulSoup — 크롤링

💡 전 세계 개발자가 만든 외부 라이브러리는 PyPI (Python Package Index)라는 거대한 창고에 모여 있어요. 여기서 내려받고, 여기에 올립니다.

02 · 라이브러리 고르기 — 좋은 도구 판별법#

아무 라이브러리나 쓰면 안 됩니다. GitHub / PyPI에서 이걸 확인하세요.

  • 유지보수 여부 — 최근에도 업데이트가 되고 있나? (오래 방치된 건 위험)
  • 호환성 — 내 파이썬 버전·의존성과 맞나?
  • 대중성 — “나만 쓰는 라이브러리"보다 활발하고 많이 쓰는 프로젝트가 안전

💡 라이브러리를 쓸 때는 버전 확인이 습관이 되어야 합니다. 문서·검색·AI 답변이 모두 “특정 버전 기준"으로 안내하기 때문이에요. 버전이 다르면 경고가 뜨거나 오작동할 수 있어요.

import pandas as pd
print(pd.__version__)        # 예: 2.2.0

import matplotlib as mpl
print(mpl.__version__)

03 · 라이브러리 설치·사용 — pip 그리고 uv#

pip = 파이썬 패키지 설치 도구.

pip install pandas            # 설치
pip install pandas==2.2.0     # 특정 버전
pip install --upgrade pandas  # 업그레이드
pip list                      # 설치 목록

가상환경 + requirements.txt (전통적인 팀 협업 방식):

pip freeze > requirements.txt     # 현재 설치 목록을 파일로 저장
pip install -r requirements.txt   # 그 목록대로 한 번에 설치

⚠️ pip install -r requirements.txt는 느릴 수 있습니다. 구형 PC에선 수십 분이 걸린 사례도 있어요. 그래서 우리 과정은 uv를 씁니다 — 같은 일을 훨씬 빠르게 처리해요.

uv add pandas      # 패키지 추가 (pyproject.toml에 기록됨)
uv sync            # pyproject.toml / uv.lock 대로 환경 맞추기

설치한 라이브러리는 import로 불러옵니다.

import pandas as pd            # 관례적 별칭(as)
import numpy as np

df = pd.DataFrame({"이름": ["Alice", "Bob"], "점수": [95, 82]})
print(df["점수"].mean())       # 88.5

arr = np.array([1, 2, 3, 4])
print(arr.mean())              # 2.5

💡 import 라이브러리 as 별칭은 관례예요 (pandas→pd, numpy→np). 공식 문서·예제도 이 별칭을 씁니다. 막히면 공식 문서를 보는 습관을 들이세요. 💡 가상환경을 쓰면 프로젝트마다 라이브러리 버전이 안 섞입니다. → 개발 환경 설정(uv)

04 · 왜 “배포"를 하나 — 오픈소스의 의미#

내 코드를 PyPI에 올리는 게 “배포(packaging)“입니다. 왜 굳이 공개할까요?

  • 커뮤니티 기여 — 내가 만든 도구를 남들이 쓰고, 남들이 개선해줍니다.
  • 포트폴리오·명성 — 취업 경쟁력. “잘 배우겠습니다"라는 말보다, 실제로 배포한 패키지가 훨씬 확실한 증거예요.
  • GitHub Issues 생태계 — 사용자가 버그 제보·기능 제안을 하고, 개발자가 대응하며 라이브러리가 발전합니다.

💡 강사님 권장: 개발자 지망이라면 작은 라이브러리 1개를 만들어 배포해보세요. src 레이아웃 + pytest 통과 + 버전을 조금씩 올려가며(0.0.1 → 0.0.2 …) 키우는 경험이 그대로 포트폴리오가 됩니다.

05 · ★ 실전: 내 패키지를 PyPI에 배포하기 (mathlib-evanjjh)#

이번 수업에서 실제로 다룬 패키지 **mathlib-evanjjh**를 예로 전 과정을 봅니다. 이 패키지는 정말로 PyPI에 올라가 있어서 누구나 pip install mathlib-evanjjh로 받을 수 있어요(설치 시 0.1.5 버전 확인). 배포본에는 arithmetic, geometric, trigonometry 세 모듈이 들어 있습니다.

ℹ️ 수업 중 라이브 배포 시연은 실패했습니다. 새 디바이스 인증 메일이 안 와서요. 하지만 패키지 자체는 사전/이후에 실제로 배포되어 PyPI에 존재합니다(0.1.5). 그래서 이 글은 “흐름 설명 + 실제 결과물” 기준으로 정리합니다.

① PyPI 계정 · API 토큰#

  1. pypi.org 회원가입
  2. 계정 설정 → API tokens → “Add API token”
  3. 토큰 이름(예: mathlib-evanjjh), scope는 전체 계정
  4. 발급된 토큰은 pypi-...로 시작하며 딱 한 번만 표시됩니다 → 즉시 안전하게 보관

② GitHub repo 만들기#

항목 값
이름 mathlib-evanjjh
공개 Public

③ src 레이아웃 구조#

mathlib-evanjjh/
├─ src/
│  └─ mathlib_evanjjh/
│     ├─ __init__.py
│     ├─ arithmetic.py
│     ├─ geometric.py        # 실제 배포본에 포함
│     └─ trigonometry.py     # 실제 배포본에 포함
├─ tests/
│  ├─ __init__.py
│  └─ test_arithmetic.py
├─ pyproject.toml
└─ README.md

⚠️ 배포명 vs import명이 다릅니다. 배포명은 하이픈 mathlib-evanjjh, 하지만 파이썬은 import에 하이픈을 못 쓰므로 폴더(import 이름)는 언더스코어 mathlib_evanjjh로 만듭니다.

④ uv로 초기화 + 개발 도구 설치#

uv init .                          # pyproject.toml 등 기본 골격 생성
uv add --dev pytest twine          # 테스트·업로드 도구를 개발용으로 추가

💡 --dev는 “개발할 때만 필요한 도구"라는 뜻. pytest(테스트)와 twine(업로드)은 패키지를 쓰는 사람에겐 필요 없으니 개발 의존성으로 분리합니다.

⑤ pyproject.toml — 빌드 설정(hatchling)#

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "mathlib-evanjjh"
version = "0.1.0"
authors = [{ name = "EvanJJH", email = "you@example.com" }]
description = "A class-based Python utility package for arithmetic, geometric sequences, and trigonometry"
readme = "README.md"
requires-python = ">=3.8"

💡 [build-system]에 hatchling을 빌드 백엔드로 지정합니다. version은 곧 보게 될 “지속 업데이트"의 핵심이에요.

⑥ .pypirc — 인증 정보 (🔒 절대 git 커밋 금지)#

홈 디렉터리에 ~/.pypirc를 만들어 토큰을 넣습니다.

[pypi]
username = __token__
password = pypi-...        # ②에서 발급받은 토큰 (자리표시자)

🔒 .pypirc는 git에 절대 커밋하지 마세요. 토큰이 노출되면 누구나 여러분 이름으로 패키지를 올릴 수 있습니다. .gitignore에 포함됐는지 꼭 확인하세요. 💡 vi로 작성 시: i(입력 모드) → 내용 작성 → Esc → :wq(저장 후 종료).

⑦ Arithmetic 클래스 작성#

# src/mathlib_evanjjh/arithmetic.py
class Arithmetic:
    def __init__(self, a, b):
        self.a = a
        self.b = b

    def add(self):
        return self.a + self.b

    def subtract(self):
        return self.a - self.b

    def multiply(self):
        return self.a * self.b

    def divide(self):
        if self.b == 0:
            raise ValueError("0으로 나눌 수 없습니다.")
        return self.a / self.b

ℹ️ geometric(등비수열)·trigonometry(삼각함수) 모듈도 실제 배포본에 포함되지만, 수업 자료에 소스가 없어 여기서는 다루지 않습니다. 사용법은 실습 코드 노트에서 시그니처·출력만 확인하세요.

⑧ pytest로 검증 — 통과 후 배포#

# tests/test_arithmetic.py
import pytest
from mathlib_evanjjh.arithmetic import Arithmetic

class TestArithmetic:
    def test_add(self):
        assert Arithmetic(3, 2).add() == 5

    def test_divide_by_zero(self):
        with pytest.raises(ValueError):
            Arithmetic(5, 0).divide()

uv run pytest        # 통과 확인 후에만 배포로 진행

💡 테스트를 통과한 코드만 배포하는 게 기본 관행입니다. pytest.raises는 “이 코드가 정말 에러를 내는지"까지 검증해줘요.

⑨ ★ 버전을 올리며 twine으로 업로드 (핵심 개념)#

배포의 진짜 핵심은 버전을 계속 올리는 것입니다.

uv run twine upload dist/*
  • 기능을 추가/수정할 때마다 pyproject.toml의 version을 올립니다. 개념상 예시: 0.1.0 → 0.2.0 → 0.3.0 …
  • 같은 버전은 다시 올릴 수 없습니다. 무언가 바꿨다면 반드시 버전을 bump 해야 해요.
  • 이번 mathlib-evanjjh는 실제로 0.1.5까지 올라갔습니다 — 수업 중 점진적 버전 업이 실제로 일어났다는 증거예요.

💡 “개념 설명용 예시 버전(0.1.0→0.2.0→0.3.0)“과 “실제 배포가 도달한 버전(0.1.5)“은 다른 얘기입니다. 핵심은 숫자가 아니라 **“바꿀 때마다 버전을 올린다”**는 원칙이에요.

💡 참고: uv 없이 표준 도구만 쓰려면 pip install build twine → python -m build → twine upload dist/* 흐름도 가능합니다. 이번 수업의 메인은 uv + hatchling + twine입니다. 처음엔 TestPyPI에 먼저 올려 연습하는 걸 권장 — 실수해도 안전해요.

06 · 한눈에 정리#

단계 명령 · 설정 핵심
고르기 GitHub/PyPI 확인 유지보수·호환성·대중성
설치 uv add 이름 / pip install 이름 uv가 pip보다 빠름
사용 import 이름 as 별칭 __version__로 버전 확인 습관
구조 src/패키지_언더스코어/ 배포명(하이픈)≠import명(언더스코어)
빌드 pyproject.toml (hatchling) uv init + uv add --dev pytest twine
인증 ~/.pypirc 🔒 git 커밋 절대 금지
검증 uv run pytest 통과 후 배포
배포 uv run twine upload dist/* 버전 bump 필수 (0.1.0→…→0.1.5)

📚 참고자료#

수업에 더해 공식 문서로 보충: PyPI · 패키징 가이드 · uv 문서 · pytest 문서

모듈/패키지 vs 라이브러리#

  • 모듈 = .py 파일 하나 / 패키지 = 모듈 담은 폴더(__init__.py) / 라이브러리 = 패키지(들)을 묶어 배포한 것. → 모듈과 패키지

버전 표기 (시맨틱 버저닝)#

major.minor.patch (예: 0.1.5). 큰 변화=major, 기능 추가=minor, 버그 수정=patch. 같은 버전은 재업로드 불가 → 바꿨으면 무조건 올린다.

.pypirc가 노출되면?#

토큰이 들어 있어 누구나 내 이름으로 배포 가능. 즉시 PyPI에서 토큰 폐기(revoke) 후 재발급. 애초에 .gitignore로 커밋을 막는 게 1순위.

마무리#

라이브러리는 “남이 만든 도구를 가져다 쓰는 것”, 배포는 “내 도구를 세상에 내놓는 것”. 핵심은 거창한 기능이 아니라 작게 시작해 버전을 꾸준히 올리는 습관이다. mathlib-evanjjh도 0.1.0에서 시작해 0.1.5까지 자랐다.

numpy·pandas 같은 도구를 매일 가져다 쓰면서, 동시에 내 작은 패키지를 PyPI에 올려보는 경험은 그 자체로 강력한 포트폴리오가 됩니다. 🚀
