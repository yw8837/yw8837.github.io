어제(6/11)까지는 JOIN으로 테이블을 가로로 잇고 서브쿼리로 쿼리 안에 쿼리를 품었다. 오늘은 통계·분석 쿼리의 두 기둥을 세운다 — 윈도우 함수(순위·누적·이전/이후 참조를 원본 행을 줄이지 않고 계산)와 그룹 함수(소계·총계를 더하는 ROLLUP/CUBE/GROUPING SETS). 그런데 실제 수업은 자료 목차대로 흐르지 않았다. 강사님은 어제 이어 이탈고객 분석 실전으로 몸을 풀고 → 윈도우 함수를 한참 파고 → 마지막에 그룹 함수와 classicmodels 실전을 붙였다. 이 글은 그 라이브 진행순서 그대로 따라가는 복습 노트다. 그리고 함정도 어제와 같다 — 이론 슬라이드는 Oracle/MariaDB 기준인데 실습은 SQLite라 일부 기능이 다르게 동작한다.

📖 수업 내용#

오늘의 실제 진행 흐름은 이랬다.

  1. 이탈고객(Churn) 분석 실전 — 어제 서브쿼리·JOIN 복습 겸, 마지막 주문일 + 날짜 차이로 떠난 고객 찾기
  2. 윈도우 함수 시작 — “GROUP BY는 행을 압축하지만 윈도우 함수는 원본 행을 유지한다"는 핵심 개념
  3. 윈도우 함수 실습 행진 — 순위(RANK 계열) → PARTITION BY → 서브쿼리 vs 윈도우 → 누적합 → FIRST/LAST_VALUE → LAG/LEAD → 비율(PERCENT_RANK·NTILE)
  4. ⚠ GrandTotal 출제 오류 정정 — 전체합은 SUM() OVER() 말고 스칼라 서브쿼리로
  5. 그룹 함수 — ROLLUP/CUBE/GROUPING SETS 개념 + SQLite는 UNION으로 대체
  6. classicmodels 실전 — territory별 매출 순위, 각 지역 1등 뽑기, 재주문 간격으로 이탈 위험군 탐지

📌 DB가 2종이라 코드마다 라벨을 단다 — 컬럼 이름 규칙이 다르다.

  • chinook — 음악 스토어 샘플 DB. 컬럼이 CustomerId, Total처럼 PascalCase.
  • classicmodels — 자동차 모형 판매 샘플 DB. 컬럼이 customerNumber, orderDate처럼 camelCase.

둘을 섞으면 컬럼명 때문에 바로 에러가 나니, “이 쿼리는 어느 DB?“를 항상 먼저 본다. 그리고 윈도우 함수는 SQLite 3.25.0 이상에서만 된다(SELECT sqlite_version();으로 확인).

01 · 워밍업 — 이탈고객(Churn) 분석 실전#

수업은 윈도우 함수가 아니라 어제 배운 서브쿼리·JOIN의 실전 응용으로 시작했다. 주제는 이탈고객 분석 — 마케팅·쇼핑몰 분석에서 가장 자주 나오는 문제다. “한동안 안 산 고객"을 어떻게 SQL로 골라낼까?

DB: classicmodels / 출처: 노션 Day04-answers [답5] ✅ 노션 정답

핵심 아이디어는 세 단계다.

  1. 고객별 마지막 주문일을 구한다 → MAX(orderDate)
  2. 기준일과의 날짜 차이를 구한다 → julianday(기준일) - julianday(마지막 주문일)
  3. “오래 안 산” 고객만 필터한다 → HAVING
SELECT
    c.customerName,
    c.country,
    MAX(o.orderDate) AS LastOrderDate,                       -- 고객별 마지막 주문일
    CAST(
        julianday('2005-05-31') - julianday(MAX(o.orderDate))
    AS INTEGER) AS DaysSinceLastOrder                         -- 기준일과의 일수 차
FROM customers c
INNER JOIN orders o ON c.customerNumber = o.customerNumber
GROUP BY c.customerNumber, c.customerName, c.country
HAVING MAX(o.orderDate) < '2005-01-01'                       -- 2005-01-01 이후 구매 없음 = 이탈 후보
ORDER BY DaysSinceLastOrder DESC
LIMIT 15;
  • 기준일 2005-05-31 : 주문 테이블에서 가장 마지막 주문일(데이터의 “오늘”). 실제 오늘 날짜가 아니라 데이터 안의 마지막 시점을 기준으로 잡는 게 포인트다.
  • julianday : SQLite에서 날짜를 숫자(율리우스일)로 바꿔 빼면 일수 차이가 나온다.
  • HAVING MAX(o.orderDate) < '2005-01-01' : 2005년 들어 한 번도 안 산 고객만 = 이탈 후보. 그룹 집계 결과에 거는 조건이라 WHERE가 아니라 HAVING이다.

💡 팁: 강사님은 이어서 약 60줄짜리 종합 쿼리(셀프조인 + EXISTS + 인라인뷰 서브쿼리 총망라)도 보여줬다. “전체 이탈자"가 아니라 같은 국가 안에서 상대 비교해 “진짜 이탈자"만 더 정밀하게 거르는 버전이다. 다만 “이건 풀라고 낸 게 아니라 현업에서 마주칠 쿼리의 길이·복잡도를 체감하라고 보여주는 것"이라고 했다. (전체 코드는 코드 노트 참고.)

02 · 윈도우 함수란 — 행을 줄이지 않고 통계를 옆에 붙이기#

이제 오늘의 본론. 강사님이 윈도우 함수를 한 문장으로 요약했다.

“GROUP BY는 결과를 압축(행이 줄어듦)하지만, 윈도우 함수는 집계를 해도 원본 행 수를 그대로 유지한다.”

무슨 뜻일까? 예를 들어 “부서 평균 급여"를 구한다고 하자.

  • GROUP BY: 부서당 한 줄로 압축된다. 개별 직원 정보는 사라지고 부서별 평균만 남는다.
  • 윈도우 함수: 직원 한 명 한 명 그대로 두고, 그 옆에 “네 부서의 평균은 이거야"라는 컬럼을 하나 더 붙인다.

즉 윈도우 함수는 “행과 행 사이의 관계"를 정의해 순위·누적·이전값 같은 걸 계산하면서도 원본 데이터를 통째로 보존한다. 그래서 “각 고객의 구매액 + 전체 순위”, “각 달 매출 + 누적합“처럼 개별 + 통계를 한 화면에 보여줄 때 압도적으로 편하다.

기본 문법#

SELECT 윈도우함수(인수)
OVER ( [PARTITION BY 컬럼] [ORDER BY 절] [WINDOWING 절] )
FROM 테이블명;
구성요소역할비유
OVER윈도우 함수임을 알리는 필수 키워드“이건 창문 너머로 본다”
PARTITION BY전체를 소그룹으로 나누는 기준칸막이를 친다
ORDER BY소그룹 안에서의 정렬칸막이 안에서 줄 세우기
WINDOWING(프레임)계산에 포함할 행의 범위어디서 어디까지 볼지
  • PARTITION BY : 강사님 표현으로 “칸막이를 치고 그 안에서 다시 계산”. 없으면 전체가 하나의 그룹.
  • WINDOWING(ROWS 절) : UNBOUNDED PRECEDING(맨 첫 행) / CURRENT ROW(현재 행) / UNBOUNDED FOLLOWING(맨 마지막 행)을 조합해 “창의 범위"를 정한다. 이 범위에 따라 결과가 크게 달라진다(누적합 절에서 확인).

💡 팁: 윈도우 함수는 MySQL 8.0.22+, MariaDB 10.2.0+, SQLite 3.25.0+ 부터 지원한다. 실습 전에 SELECT sqlite_version();으로 버전부터 확인하는 습관을 들이자.

03 · 순위 함수 — RANK / DENSE_RANK / ROW_NUMBER#

윈도우 함수 첫 실습은 순위 매기기다. 세 함수가 비슷해 보이지만 동률(같은 값)을 처리하는 방식이 다르다. 이게 시험에도 잘 나오는 핵심.

함수동률 처리예시 (값이 같을 때)
RANK같은 순위 부여, 다음 순위는 건너뜀1, 2, 3, 3, 5
DENSE_RANK같은 순위 부여, 건너뛰지 않음1, 2, 3, 3, 4
ROW_NUMBER동률이어도 무조건 고유 번호1, 2, 3, 4, 5

DB: chinook / 출처: Day05_lecture_chinook.sql [문제1] ✅ 강사 정답

SELECT
    c.CustomerId,
    c.FirstName || ' ' || c.LastName  AS CustomerName,
    c.Country,
    ROUND(SUM(i.Total), 2)            AS TotalPurchase,
    RANK()       OVER (ORDER BY SUM(i.Total) DESC) AS Rank,
    DENSE_RANK() OVER (ORDER BY SUM(i.Total) DESC) AS DenseRank,
    ROW_NUMBER() OVER (ORDER BY SUM(i.Total) DESC) AS RowNumber
FROM   customers c
JOIN   invoices  i ON c.CustomerId = i.CustomerId
GROUP BY c.CustomerId, c.FirstName, c.LastName, c.Country
ORDER BY TotalPurchase DESC
LIMIT 10;

여기서 강사님이 강조한 패턴이 있다. “먼저 GROUP BY로 고객별 구매액을 집계한 뒤, 그 결과 위에 윈도우 함수로 순위 컬럼만 얹는다.” 집계 결과를 해치지 않고 순위 컬럼 하나만 더하는 것 — 이게 윈도우 함수의 전형적인 사용법이다.

💡 팁: 외우는 법 — RANK는 건너뛰고(레이스 순위: 공동 3위면 4위 없이 5위), DENSE_RANK는 촘촘하게(3위 다음 4위), ROW_NUMBER는 무조건 줄번호. “동점자 처리를 어떻게?“라는 질문에 답하는 게 순위 함수다.

04 · PARTITION BY — 칸막이를 치고 그 안에서 다시 순위 매기기#

위 [문제1]은 전체 고객 중 순위였다. 그런데 “국가별로 1등, 2등을 다시 매기고 싶다"면? 여기서 PARTITION BY가 등장한다.

DB: chinook / 출처: Day05_lecture_chinook.sql [문제2] ✅ 강사 정답

SELECT
    c.Country,
    c.FirstName || ' ' || c.LastName  AS CustomerName,
    ROUND(SUM(i.Total), 2)            AS TotalPurchase,
    RANK() OVER (
        PARTITION BY c.Country               -- 국가별로 칸막이
        ORDER BY SUM(i.Total) DESC           -- 칸막이 안에서 구매액 내림차순
    ) AS CountryRank
FROM   customers c
JOIN   invoices  i ON c.CustomerId = i.CustomerId
GROUP BY c.Country, c.CustomerId, c.FirstName, c.LastName
ORDER BY c.Country, CountryRank;
  • OVER (ORDER BY ...) 만 쓰면 → 전체 데이터 기준 순위 (앞 [문제1]).
  • OVER (PARTITION BY 국가 ORDER BY ...) → 국가마다 1위부터 다시 매김.

강사님 비유 그대로 “국가별로 칸막이를 치고, 그 칸 안에서만 순위를 다시 센다.” 그러니 각 국가마다 CountryRank = 1이 하나씩 나온다.

💡 팁: PARTITION BY는 GROUP BY와 헷갈리기 쉬운데 결정적 차이는 행이 안 줄어든다는 것. GROUP BY는 국가당 한 줄로 압축하지만, PARTITION BY는 모든 고객을 그대로 두고 “네 국가 안 순위"만 옆에 붙인다.

05 · 서브쿼리 vs 윈도우 함수 — 같은 결과, 더 간결한 길#

“각 청구서 옆에 그 나라의 평균 청구금액을 붙이기"를 두 가지 방법으로 비교했다. 어제 배운 스칼라 서브쿼리로도 되지만, 윈도우 함수가 훨씬 짧다.

DB: chinook / 출처: Day05_lecture_chinook.sql [문제3] ✅ 강사 정답

-- (방법 A) 서브쿼리 방식 — 행마다 서브쿼리 재실행
SELECT
    i.InvoiceId,
    i.BillingCountry,
    i.Total,
    (SELECT ROUND(AVG(Total), 2)
     FROM   invoices i2
     WHERE  i2.BillingCountry = i.BillingCountry) AS CountryAvgTotal
FROM   invoices i
ORDER BY i.BillingCountry, i.Total DESC;

-- (방법 B) 윈도우 함수 방식 — 한 줄로 끝
SELECT
    InvoiceId,
    BillingCountry,
    Total,
    ROUND(AVG(Total) OVER (PARTITION BY BillingCountry), 2) AS CountryAvgTotal
FROM   invoices
ORDER BY BillingCountry, Total DESC;

두 쿼리는 같은 결과를 낸다. 하지만 (A)는 행마다 서브쿼리를 다시 돌리는 연관 서브쿼리라 길고 느릴 수 있고, (B)는 AVG(Total) OVER (PARTITION BY BillingCountry) 한 줄이면 끝이다.

💡 팁: 일반 집계함수(SUM/AVG/MAX/MIN/COUNT)도 OVER만 붙이면 윈도우 함수가 된다. “각 행 옆에 그룹 통계를 붙이고 싶다"면 서브쿼리보다 집계함수() OVER (PARTITION BY ...)를 먼저 떠올리자.

06 · 누적합(Running Total) — 창의 범위가 결과를 바꾼다#

이번엔 WINDOWING(프레임)이 주인공. 누적합(running total)은 “첫 행부터 현재 행까지 다 더한 값"이다.

DB: chinook / 출처: Day05_lecture_chinook.sql [문제4] ✅ 강사 정답

SELECT
    InvoiceId,
    InvoiceDate,
    Total,
    ROUND(SUM(Total) OVER (), 2)               AS GrandTotal,        -- 전체합(⚠ 아래 정정 참고)
    ROUND(SUM(Total) OVER (
        ORDER BY InvoiceDate
        ROWS BETWEEN UNBOUNDED PRECEDING        -- 맨 첫 행부터
             AND CURRENT ROW                    -- 현재 행까지
    ), 2)                                      AS RunningTotal       -- 누적합
FROM   invoices
ORDER BY InvoiceDate
LIMIT 20;
  • ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW : “맨 처음부터 지금 행까지” = 누적합.
  • 강사님이 직접 실험한 포인트 — 프레임을 CURRENT ROW AND UNBOUNDED FOLLOWING(현재 행부터 끝까지)으로 바꾸면 값이 **잔여합(뒤에서부터 더한 형태)**으로 완전히 달라진다. 그래서 “창(window)의 너비·범위 개념을 잡는 게 중요“하다고 강조했다.

💡 팁: “누적”, “전월 대비” 같은 키워드가 문제에 나오면 윈도우 함수를 떠올리면 된다. 누적합의 정석 프레임은 ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW. 통째로 외워두면 편하다.

07 · FIRST_VALUE / LAST_VALUE — 그룹의 첫 값·마지막 값#

행 순서 함수 첫 번째. FIRST_VALUE(정렬 후 가장 먼저 나온 값), LAST_VALUE(가장 나중 값)로 국가별 최소·최대 청구금액을 한 줄에 붙인다.

DB: chinook / 출처: Day05_lecture_chinook.sql [문제5] ✅ 강사 정답

SELECT
    InvoiceId,
    BillingCountry,
    Total,
    FIRST_VALUE(Total) OVER (
        PARTITION BY BillingCountry
        ORDER BY Total ASC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING   -- 창 전체 명시!
    ) AS CountryMinTotal,
    LAST_VALUE(Total) OVER (
        PARTITION BY BillingCountry
        ORDER BY Total ASC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING   -- 창 전체 명시!
    ) AS CountryMaxTotal
FROM   invoices
ORDER BY BillingCountry, Total;

🚨 LAST_VALUE의 함정 — 프레임을 반드시 명시하라. ORDER BY만 쓰면 기본 프레임이 “첫 행 ~ 현재 행까지“라서, LAST_VALUE가 “마지막 값"이 아니라 “현재 행 값"을 돌려준다(= 최대값이 안 나옴). 그래서 ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING으로 창 전체를 명시해야 의도대로 마지막 값이 나온다.

💡 팁: Total ASC(오름차순)로 정렬했으니 FIRST_VALUE = 최소, LAST_VALUE = 최대. 정렬 방향을 바꾸면 의미도 뒤집힌다. FIRST_VALUE는 프레임에 덜 민감하지만 LAST_VALUE는 거의 항상 프레임을 명시해야 한다고 기억하자.

08 · LAG / LEAD — 이전 행·다음 행을 옆 컬럼으로#

행 순서 함수의 핵심. LAG(이전 N번째 행 값), LEAD(이후 N번째 행 값)는 “앞뒤 행을 끌어와 옆에 붙이는” 함수다. 전월 대비, 주문 간격, 이동평균 등 시계열 분석의 단골이다.

DB: chinook / 출처: Day05_lecture_chinook.sql [문제6] ✅ 강사 정답

SELECT
    InvoiceId,
    InvoiceDate,
    Total,
    LAG(Total,  1) OVER (ORDER BY InvoiceDate) AS PrevInvoiceTotal,   -- 이전 청구액
    LEAD(Total, 1) OVER (ORDER BY InvoiceDate) AS NextInvoiceTotal    -- 다음 청구액
FROM   invoices
ORDER BY InvoiceDate
LIMIT 20;
  • LAG(Total, 1) : 한 행 앞의 Total을 가져온다. 맨 첫 행은 앞이 없어 NULL.
  • LEAD(Total, 1) : 한 행 뒤의 Total을 가져온다. 맨 마지막 행은 뒤가 없어 NULL.

💡 팁: “이전/이후 값을 옆에 붙이고 싶다” = LAG/LEAD. 경계(첫·마지막 행)는 NULL이 나오니, 뒤에서 계산(증감액 등)할 때 NULL 처리를 염두에 둬야 한다. 4-6교시에 강사님이 “누적/전월 대비 키워드가 나오면 윈도우 함수“라고 못 박았다.

09 · 비율 함수 — RATIO_TO_REPORT / PERCENT_RANK / CUME_DIST / NTILE#

마지막 윈도우 함수 묶음은 비율·분위 계열이다. 문법 위주로 빠르게 소개됐다.

함수의미비고
RATIO_TO_REPORT파티션 전체 합 대비 내 비율Oracle 전용. SQLite/MariaDB는 값/SUM()OVER()로 대체
PERCENT_RANK순위 백분율 [0, 1], 최고=0
CUME_DIST누적 백분율 (0, 1]나보다 작거나 같은 비율
NTILE(N)정렬 후 N등분 그룹 번호등급 나누기

(1) RATIO_TO_REPORT는 SQLite에 없다 → 직접 나눈다.

-- SQLite/MariaDB 대체: 값 / 전체합
SELECT
    ID, NAME, SALARY,
    SUM(SALARY) OVER() TOTAL_SALARY,
    (SALARY / SUM(SALARY) OVER()) RATIO_TO_REPORT
FROM EMPLOYEE;

(2) PERCENT_RANK / CUME_DIST — chinook 상위 10고객 (출처: chinook.sql [문제9] ✅ 강사 정답)

SELECT
    c.CustomerId,
    c.FirstName || ' ' || c.LastName  AS CustomerName,
    ROUND(SUM(i.Total), 2)            AS TotalPurchase,
    ROUND(PERCENT_RANK() OVER (ORDER BY SUM(i.Total) DESC), 4) AS PctRank,
    ROUND(CUME_DIST()    OVER (ORDER BY SUM(i.Total) DESC), 4) AS CumeDist
FROM   customers c
JOIN   invoices  i ON c.CustomerId = i.CustomerId
GROUP BY c.CustomerId, c.FirstName, c.LastName
ORDER BY TotalPurchase DESC
LIMIT 10;

(3) NTILE(3) — 직원을 고용일 기준 3그룹으로 (출처: chinook.sql [문제10] ✅ 강사 정답)

SELECT
    EmployeeId,
    FirstName || ' ' || LastName AS EmployeeName,
    Title,
    HireDate,
    NTILE(3) OVER (ORDER BY HireDate) AS HireGroup     -- 고용일순 3등분
FROM   employees
ORDER BY HireDate;

💡 팁: 강사님 학습법 권장 — 모르는 함수(예: NTILE)는 ① 공식 문서부터 → ② 그래도 안 되면 LLM에 질문 순서로 익히라고 했다. “코드를 통째로 외우기"보다 용어·개념을 알고 문제를 정의하는 능력이 더 중요하다는 점을 거듭 강조했다.

10 · ⚠ 강사 정정 — GrandTotal(전체합)은 스칼라 서브쿼리로#

여기서 반드시 짚어야 할 정정 공지가 있었다. 4-6교시에 강사님이 직접 출제 오류를 인정한 부분이다.

🚨 GrandTotal 출제 오류 정정 (라이브 4-6교시): 앞의 [문제4]·[문제8]에서 전체합(GrandTotal)을 SUM(Total) OVER ()로 구했는데, GROUP BY로 이미 묶인 결과 위에 다시 SUM() OVER()를 쓰면 값이 의도와 다르게 나오는 문제가 있었다. 강사님은 이를 출제 오류로 인정하고, 대안으로 전체합은 스칼라 서브쿼리 (SELECT SUM(...) FROM ...)로 따로 구해 분모로 쓰는 방법을 권장했다.

문제가 됐던 [문제8](국가별 매출비율)을 보자.

DB: chinook / 출처: Day05_lecture_chinook.sql [문제8] ✅ 강사 정답(단, GrandTotal은 정정 권장)

SELECT
    BillingCountry,
    ROUND(SUM(Total), 2)                           AS CountryTotal,
    ROUND(SUM(Total) OVER (), 2)                   AS GrandTotal,      -- ⚠ 이 부분이 문제
    ROUND(SUM(Total) / SUM(Total) OVER (), 4)      AS RevenueRatio
FROM   invoices
GROUP BY BillingCountry
ORDER BY CountryTotal DESC;

GROUP BY BillingCountry로 이미 국가별로 묶인 상태에서 SUM(Total) OVER ()를 쓰면, “전체 원본 합"이 아니라 “국가별 합들의 합” 같은 의도치 않은 값이 될 수 있다. 안전한 방법은 전체합을 스칼라 서브쿼리로 분리하는 것이다.

-- 정정 권장 형태: 전체합을 스칼라 서브쿼리로
SELECT
    BillingCountry,
    ROUND(SUM(Total), 2)                                   AS CountryTotal,
    (SELECT ROUND(SUM(Total), 2) FROM invoices)            AS GrandTotal,
    ROUND(SUM(Total) / (SELECT SUM(Total) FROM invoices), 4) AS RevenueRatio
FROM   invoices
GROUP BY BillingCountry
ORDER BY CountryTotal DESC;

💡 팁: 윈도우 함수로 꼭 처리하려면 인라인뷰(서브쿼리로 한 번 감싸기) 등으로 복잡해진다. 비율의 분모처럼 “전체에 대한 단일 값"이 필요할 땐 스칼라 서브쿼리가 단순하고 안전하다 — 강사님 결론. 모순처럼 보이지만 “윈도우 함수가 만능은 아니다"라는 좋은 교훈이다.

11 · 그룹 함수 — ROLLUP / CUBE / GROUPING SETS (SQLite는 UNION 대체)#

윈도우 함수를 마치고 그룹 함수로 넘어왔다. 그룹 함수는 GROUP BY 집계에 소계·중계·총계 같은 집계 레벨을 더하는 기능이다. “장르별 트랙 수"뿐 아니라 “전체 합계 행"까지 한 번에 뽑고 싶을 때 쓴다.

함수만드는 집계 레벨SQLite 대체
ROLLUP(A, B)(A,B) + (A) + 전체 = 3레벨 (소계+총계)UNION ALL
CUBE(A, B)(A,B) + (A) + (B) + 전체 = 4레벨 (모든 조합)UNION
GROUPING SETS(A, B)A별 + B별 = 2레벨 (각각 개별 통계)UNION ALL

🚨 SQLite 제약 — ROLLUP/CUBE/GROUPING SETS 미지원. 슬라이드는 Oracle/MariaDB 문법으로 설명하지만, 실습 SQLite에서는 이 함수들을 쓸 수 없다. 대신 각 집계 레벨을 따로 구해 UNION/UNION ALL로 합치는 방식이 정답이다(코드가 길어진다). 그룹 함수 자체 실습은 Elice 플랫폼 예제를 참고하라고 안내했다.

예를 들어 ROLLUP을 SQLite에서 흉내 내기 — (장르,미디어타입) 조합 + 장르별 소계 + 전체를 UNION ALL로 쌓는다.

DB: chinook / 출처: Day05_lecture_chinook.sql [문제12] ✅ 강사 정답 (SQLite UNION 대체)

-- (1) (장르, 미디어타입) 조합
SELECT g.Name AS Genre, mt.Name AS MediaType,
       COUNT(t.TrackId) AS TrackCount, ROUND(AVG(t.UnitPrice), 2) AS AvgPrice
FROM   tracks t
JOIN   genres g ON t.GenreId = g.GenreId
JOIN   media_types mt ON t.MediaTypeId = mt.MediaTypeId
GROUP BY g.Name, mt.Name

UNION ALL

-- (2) 장르별 소계 (MediaType = NULL)
SELECT g.Name, NULL, COUNT(t.TrackId), ROUND(AVG(t.UnitPrice), 2)
FROM   tracks t
JOIN   genres g ON t.GenreId = g.GenreId
GROUP BY g.Name

UNION ALL

-- (3) 전체 합계 (둘 다 NULL)
SELECT NULL, NULL, COUNT(TrackId), ROUND(AVG(UnitPrice), 2)
FROM   tracks

ORDER BY Genre, MediaType;
  • (1) 조합 + (2) 소계 + (3) 전체 세 쿼리를 UNION ALL로 세로로 쌓으면 ROLLUP과 같은 결과 모양이 된다.
  • 소계·전체 행은 빠진 컬럼을 NULL로 채워 컬럼 수를 맞춘다(UNION은 컬럼 수·순서가 같아야 한다).
  • CUBE는 여기에 “미디어타입별 소계"까지 추가(UNION 하나 더), GROUPING SETS는 소계 두 개만(UNION ALL).

💡 팁: 이게 어제 배운 UNION의 실전 활용이다. “ROLLUP = 소계+총계”, “CUBE = 모든 조합”, “GROUPING SETS = 각각 따로"라는 의미만 잡으면 SQLite에서는 그 의미대로 쿼리를 UNION으로 쌓으면 된다. Oracle을 쓰면 함수 한 줄로 끝나지만, SQLite의 한계를 우회하는 법을 익히는 셈.

12 · classicmodels 실전 — 지역별 순위와 1등 뽑기#

이제 classicmodels DB(camelCase 주의!)로 실전 쿼리를 다뤘다. 5개 테이블 JOIN + 윈도우 함수 조합이다.

DB: classicmodels / 출처: Day05_lecture_classicmodels_lecture.sql [실전1] ✅ 강사 정답

SELECT e.firstName || ' ' || e.lastName          AS SalesRep,
       off.territory,
       COUNT(DISTINCT c.customerNumber)          AS CustomerCount,
       ROUND(SUM(od.quantityOrdered * od.priceEach), 2) AS TotalSales,
       RANK() OVER (
           PARTITION BY off.territory                                    -- 지역(NA/EMEA/APAC)별 칸막이
           ORDER BY SUM(od.quantityOrdered * od.priceEach) DESC
       )                                         AS TerritoryRank
FROM   employees   e
JOIN   offices     off ON e.officeCode = off.officeCode
JOIN   customers   c   ON e.employeeNumber = c.salesRepEmployeeNumber
JOIN   orders      o   ON c.customerNumber = o.customerNumber
JOIN   orderdetails od ON o.orderNumber = od.orderNumber
WHERE  e.jobTitle LIKE '%Sales Rep%'
  AND  o.status = 'Shipped'
GROUP BY e.employeeNumber, e.firstName, e.lastName, off.territory
ORDER BY off.territory, TerritoryRank;

영업사원별 매출을 구해 지역(territory: NA/EMEA/APAC)별로 순위를 매긴다. 그럼 “각 지역 1등만” 뽑으려면? 윈도우 함수 결과는 SELECT 단계에서 계산되므로 같은 레벨의 WHERE로는 못 거른다. 그래서 **인라인뷰로 한 번 감싼 뒤 WHERE rank = 1**을 건다.

DB: classicmodels / 출처: 노션 Day05 변형 ✅

SELECT *
FROM (
    SELECT e.firstName || ' ' || e.lastName AS SalesRep,
           off.territory,
           ...
           RANK() OVER (PARTITION BY off.territory
                        ORDER BY SUM(od.quantityOrdered * od.priceEach) DESC) AS TerritoryRank
    FROM employees e
    JOIN offices off ON e.officeCode = off.officeCode
    ... (위 실전1과 동일)
) a
WHERE a.TerritoryRank = 1;          -- 인라인뷰로 감싼 뒤 1등만 필터

💡 팁: “윈도우 함수 결과로 필터링하려면 인라인뷰/서브쿼리로 감싸야 한다” — 오늘의 중요한 패턴이다. 윈도우 함수는 WHERE보다 나중 단계에 계산되기 때문에, 그 결과(순위 등)를 조건으로 쓰려면 한 겹 감싸서 그 바깥에서 WHERE를 걸어야 한다.

13 · classicmodels 실전 — 재주문 간격으로 이탈 위험군 탐지#

오늘의 마지막. 첫 시간 이탈고객 분석과 수미상관을 이룬다 — 이번엔 **윈도우 함수(LAG)**로 “고객이 얼마 만에 다시 주문했나”(재주문 간격)를 구해 이탈 위험군을 찾는다.

DB: classicmodels / 출처: Day05_lecture_classicmodels_lecture.sql [시계열2] ✅ 강사 정답

SELECT customerName, country, orderDate, orderRevenue, prevOrderDate,
       CAST(
           julianday(orderDate) - julianday(prevOrderDate)
       AS INTEGER) AS DaysSincePrevOrder              -- 직전 주문과의 간격(일)
FROM (
    SELECT c.customerName, c.country, o.orderDate,
           ROUND(SUM(od.quantityOrdered * od.priceEach), 2) AS orderRevenue,
           LAG(o.orderDate, 1) OVER (
               PARTITION BY c.customerNumber          -- 고객별로
               ORDER BY o.orderDate                   -- 주문일순
           ) AS prevOrderDate                          -- 직전 주문일
    FROM   customers c
    JOIN   orders o       ON c.customerNumber = o.customerNumber
    JOIN   orderdetails od ON o.orderNumber = od.orderNumber
    WHERE  o.status = 'Shipped'
    GROUP BY c.customerNumber, c.customerName, c.country, o.orderNumber, o.orderDate
) order_gap
WHERE  prevOrderDate IS NOT NULL                       -- 첫 주문은 비교 대상 없음 → 제외
ORDER BY DaysSincePrevOrder DESC
LIMIT 20;
  • LAG(o.orderDate, 1) OVER (PARTITION BY 고객 ORDER BY 주문일) : 고객별로 직전 주문일을 끌어온다.
  • julianday(이번 주문) - julianday(직전 주문) : 두 주문 사이의 간격(일수).
  • WHERE prevOrderDate IS NOT NULL : 고객의 첫 주문은 직전 주문이 없어 LAG 결과가 NULL → 비교 대상에서 제외.

💡 팁: 주문 간격이 유독 긴 고객이 이탈 위험군·리텐션 마케팅 대상이다. 1교시의 이탈 분석(MAX(orderDate) + 날짜차 + HAVING)이 “마지막 주문 기준"이라면, 이건 LAG로 주문 사이 간격을 본다 — 같은 이탈 문제를 윈도우 함수로 푸는 또 다른 각도다.

14 · 강사님이 강조한 포인트 (정리)#

  • 윈도우 함수 = 행을 줄이지 않고 통계 컬럼을 옆에 붙인다. GROUP BY는 압축(행 감소), 윈도우는 원본 행 유지. 기본형 OVER(PARTITION BY ... ORDER BY ... [ROWS ...]).
  • 순위 3종: RANK(건너뜀 1,2,3,3,5) / DENSE_RANK(촘촘 1,2,3,3,4) / ROW_NUMBER(고유 1,2,3,4,5). 동률 처리 방식이 핵심.
  • PARTITION BY = 칸막이. 그 안에서 순위·집계를 다시 계산하되 행은 보존.
  • 누적합 = ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW. 프레임을 바꾸면 결과가 크게 달라진다 — “창의 범위” 개념이 중요.
  • LAST_VALUE는 프레임 명시 필수(UNBOUNDED PRECEDING ~ UNBOUNDED FOLLOWING). 안 그러면 최대값이 안 나온다.
  • LAG/LEAD = 이전/이후 행 참조. 경계는 NULL. “누적/전월 대비” 키워드 = 윈도우 함수.
  • ⚠ 전체합(GrandTotal)은 SUM() OVER() 대신 스칼라 서브쿼리 (SELECT SUM(...) FROM ...)로(강사 출제오류 정정).
  • SQLite 제약: 윈도우 함수는 3.25+. ROLLUP/CUBE/GROUPING SETS는 미지원 → UNION/UNION ALL 대체.
  • 윈도우 결과로 필터링하려면 인라인뷰로 감싼 뒤 WHERE rank=1.
  • 학습법: 모르는 함수는 공식 문서 → LLM 순. 코드 암기보다 개념·문제 정의 능력.
  • 시험 공지: 다음 주 월요일 윈도우 함수 중심 “라이트” 테스트, 화요일 종합시험. 서브쿼리보다 오늘 범위(윈도우) 위주 출제 예고.

마무리#

오늘은 통계·분석 SQL의 두 기둥을 세웠다. 윈도우 함수는 “GROUP BY와 달리 원본 행을 줄이지 않고 통계 컬럼을 옆에 붙인다"는 한 문장으로 요약된다 — 순위(RANK 계열), 누적합(ROWS BETWEEN), 첫/마지막 값(FIRST/LAST_VALUE), 이전/이후 참조(LAG/LEAD), 비율·분위(PERCENT_RANK/NTILE)까지. 그룹 함수(ROLLUP/CUBE/GROUPING SETS)는 소계·총계를 더하지만, SQLite에선 UNION으로 우회한다는 게 핵심. 수업이 자료 목차가 아니라 이탈고객 분석 → 윈도우 함수 → 그룹 함수 → 실전 순으로 흐른 덕에, “윈도우 함수로 무슨 문제를 푸는가"가 자연스럽게 잡혔다. 그리고 잊지 말 것 — 전체합은 SUM() OVER()가 아니라 스칼라 서브쿼리로(강사 정정), SQLite 차원집계는 UNION으로. 다음 주는 오늘 범위(윈도우 함수) 중심 시험이다.
