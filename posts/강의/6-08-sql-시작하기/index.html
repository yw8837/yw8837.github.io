01 · 데이터베이스란? — 그리고 왜 SQLite로 배우나#

**데이터베이스(DB)**를 한 마디로 하면 **“여러 사람이 공유해 사용할 목적으로 통합해서 관리하는 데이터의 모음”**이다. 우리가 쓰는 거의 모든 서비스(쇼핑몰, SNS, 은행) 뒤에는 DB가 있다.

DB는 종류가 정말 많다. MariaDB, Oracle, Amazon Redshift… 하지만 강사님이 분명히 못 박았다 — 세상의 모든 DB를 다 알 필요는 없다. 종류에 따라 사용법이 조금씩 다를 뿐, 검색·분석에 쓰는 기본 사용법은 DB 종류와 상관없이 거의 같기 때문이다. 그 공통분모가 바로 우리가 배울 내용이다.

그럼 왜 하필 SQLite로 배울까?

DB 엔진특징학습 적합성
Oracle, MySQL 등강력하지만 설치가 무겁고 환경 충돌 위험비대면·다양한 PC 환경엔 부담
SQLite가볍고 설치 부담이 낮음 (파일 하나가 곧 DB)기초 SQL 학습에 최적

SQL 문법은 DB마다 미세하게 다르지만, 기본 CRUD 개념은 공통이라 어떤 DB로 시작해도 옮겨가기 쉽다.

💡 팁: 실습 플랫폼(엘리스)의 DB 엔진은 SQLite가 아닐 수 있다(MariaDB 등). 세미콜론 처리 등 일부 문법이 미세하게 다를 수 있으니, “문법은 환경마다 조금씩 다르다"는 걸 염두에 두자.

02 · SQL과 CRUD — 데이터를 다루는 4가지 동작#

SQL은 Structured Query Language(구조화 질의 언어)의 약자로, **“데이터베이스에 접근하고 조작하기 위한 표준 언어”**다. 쉽게 말해 DB에게 일을 시키는 명령어다.

SQL로 할 수 있는 일은 많지만, 핵심은 딱 4가지 CRUD로 요약된다.

약자영어하는 일대표 SQL
CCreate데이터를 만든다(삽입)INSERT
RRead데이터를 읽는다(조회)SELECT
UUpdate데이터를 수정한다UPDATE
DDelete데이터를 삭제한다DELETE

강사님이 강조한 포인트: 어려운 건 CRUD 자체가 아니다. CRUD 명령어는 단순하다. 진짜 어려움은 여러 테이블을 조합하거나, 조회 조건을 어떻게 설계하느냐에서 나온다(이건 6/9에 본격적으로 다룬다).

쿼리(명령문)의 기본 구조는 **“명령 + 대상”**이다.

DESC Employees;   -- 명령(DESC) + 대상(Employees). 테이블 구조 확인용

💡 팁: 여기 나온 DESC(테이블 구조 보기)는 나중에 배울 ORDER BY ... DESC(내림차순 정렬)와 이름만 같고 기능이 완전히 다르다. 헷갈리지 말 것.

03 · 관계형 데이터베이스 — 테이블 = 컬럼 + 레코드#

DB 종류 중 가장 많이 쓰는 게 **관계형 데이터베이스(RDB)**다. “하나 이상의 테이블로 이루어지며, 서로 연결된 데이터를 가진” DB이고, SQL로 제어한다.

테이블은 컬럼(Column)과 레코드(Record)로 이루어진 표다. 엑셀 시트를 떠올리면 쉽다.

사번이름성별
001홍길동남성
002김철수남성
003김영희여성
  • 컬럼(세로): 사번, 이름, 성별 같은 항목(속성)
  • 레코드(가로): 한 줄 한 줄, 즉 개별 데이터 한 건

모든 테이블은 고유한 이름으로 구분된다.

💡 팁: 실무에서는 “컬럼"을 **“필드(field)”**라고도 부른다. 강의자료는 “컬럼"을 쓰지만 둘은 같은 말이니 혼동하지 말자.

04 · 실습 환경 세팅 — “1차 관문” 통과하기#

오늘 오전의 진짜 미션은 실습 환경을 직접 세팅하는 것이었다. 강사님은 이걸 **“1차 관문”**이라 불렀다. 통과 기준은 명확하다 — SQLite 연결 테스트에서 “Successfully connected” 메시지를 보는 것.

① VS Code 확장 3종 설치 (Ctrl+Shift+X로 Extensions 열기)

확장역할
SQLToolsSQL을 VS Code에서 실행하는 핵심 도구
SQLTools SQLiteSQLTools가 SQLite와 연결되게 해주는 드라이버
SQLite ViewerDB 파일 내용을 눈으로 확인

② (Windows) Node.js 설치 권장 — 일부 PC에서 SQLTools/SQLite 연동 시 런타임 요구 메시지가 뜰 수 있어 사전 방지용. 설치 시 Add to PATH 체크, 설치 후 재부팅 권장.

node -v   # 설치 확인 (버전이 나오면 성공)
npm -v

③ 커넥션 생성 — SQLTools 패널 → Add New Connection → 타입 SQLite → 이름 임의 → Database File에 DB 파일 경로 입력 → Test Connection → “Successfully connected” 확인 → Save → Connect.

  • 경로 주의: Windows는 역슬래시 \, Mac은 슬래시 /

④ 편의 설정 2가지

  • 단축키 변경: 선택한 쿼리 실행을 **Ctrl+Enter**로 바꾸면 편하다.
  • 레이아웃: View → Editor Layout → Two Rows로 결과창을 아래에 배치.

💡 팁: 쿼리가 바로 실행 안 되면 실행할 부분을 드래그(선택)한 뒤 실행하자. 전체 실행과 부분 실행이 헷갈려서 생기는 문제가 많다. “table이 없다"는 메시지는 데이터를 아직 안 넣은 상태일 수 있으니, 스크립트를 위에서부터 순서대로 실행하자.

05 · chinook 구조 읽기 — ERD와 Crow’s Foot 표기법#

쿼리를 치기 전에, 테이블들이 서로 어떻게 연결돼 있는지를 그림으로 읽는 법을 짚었다. 이게 **ERD(개체-관계 다이어그램, Entity-Relationship Diagram)**다. 내일 배울 JOIN의 토대이기도 하다.

ERD는 세 가지로 이루어진다.

구성요소ERD에서 모습의미
개체(Entity)박스 하나테이블 (예: tracks, albums)
속성(Attribute)박스 안 항목컬럼 + 자료형(INTEGER, NVARCHAR 등)
관계(Relationship)박스를 잇는 선테이블 간 연결, 선 끝 기호가 수 관계(카디널리티)

Crow’s Foot(까마귀발) 표기법 — 선 끝 기호 읽기#

관계선의 양 끝에 붙는 기호로 “몇 대 몇” 관계인지 읽는다. 기호는 **바깥쪽(최대 수)**과 안쪽(최소 수) 두 자리로 본다.

  • 바깥쪽(테이블 쪽) = 최대: |(막대)=정확히 하나 / <(까마귀발)=다수(many)
  • 안쪽(선 쪽) = 최소: |(막대)=최소 하나(필수) / O(동그라미)=0 가능(선택)

조합하면 이렇게 읽힌다.

기호의미
`
`O`
`<`
O<0 또는 다수 (선택 다중) — 1:N 관계에서 가장 흔함

💡 팁: O<(0 또는 다수)가 실무에서 제일 자주 보인다. “한 앨범에 트랙이 0개일 수도, 여러 개일 수도"처럼 대부분의 1:N이 이 모양이다.

chinook DB는 3개 영역으로#

오늘 실습할 chinook(음악 판매 샘플 DB)의 구조를 ERD로 보면 크게 세 덩어리다.

영역테이블관계
음악 카탈로그artists → albums → tracks1:N (아티스트 1명이 앨범 다수, 앨범 1개에 트랙 다수)
플레이리스트playlists ↔ playlist_track ↔ tracksN:M — 중간 정션 테이블(playlist_track)로 연결
판매customers → invoices → invoice_items계층 구조(고객 1명이 인보이스 다수, 인보이스 1건에 항목 다수)

💡 팁: N:M(다대다)은 직접 못 잇는다. 한 플레이리스트에 여러 트랙이 들고, 한 트랙도 여러 플레이리스트에 들어가니, 그 사이에 playlist_track 같은 정션(중간) 테이블을 둔다. JOIN 실습에서 “왜 중간 테이블을 거치지?“가 바로 이거다.

참고: ERD·Crow’s Foot·chinook 영역 구분은 강사님 라이브 정리(노션)에 정리된 내용으로 보강했다. SQLite 입문 자료는 SQLite Tutorial 샘플 DB 페이지에 chinook ERD가 그림으로 있으니 함께 보면 좋다.

06 · SELECT 기초 — 데이터를 골라 보기 (chinook DB)#

이제 본격적으로 조회다. 실습 DB는 chinook(음악 판매 샘플 DB — albums, artists, tracks, customers, invoices 등의 테이블).

기본형은 SELECT 컬럼 FROM 테이블; = “어떤 컬럼을(SELECT) 어느 테이블에서(FROM) 가져와라”.

SELECT Title FROM albums;        -- albums에서 Title 컬럼만
SELECT * FROM artists;           -- * = 모든 컬럼
SELECT * FROM tracks LIMIT 10;   -- LIMIT 10 = 앞 10건만

*는 “전체 컬럼”, LIMIT n은 “데이터가 많을 때 앞 n개만 보기"다.

DISTINCT — 중복 제거#

DISTINCT(“뚜렷한"이라는 뜻)는 뒤에 오는 컬럼의 중복을 없애고 보여준다.

SELECT DISTINCT Country FROM customers;       -- 나라 종류만 (중복 제거)
SELECT DISTINCT City, Country FROM customers; -- City+Country 조합 기준 중복 제거

💡 팁: DISTINCT 뒤에 컬럼을 2개 이상 쓰면 조합 기준으로 중복을 판단한다. 한쪽이 같아도 다른 쪽이 다르면 다른 행으로 취급한다.

WHERE — 조건 걸기#

WHERE는 **“검색할 데이터의 조건을 설정”**한다.

연산자의미
> <초과 / 미만
>= <=이상 / 이하
=같다
!=같지 않다
SELECT * FROM customers WHERE Country = 'USA';      -- 문자열은 따옴표!
SELECT * FROM tracks WHERE UnitPrice > 0.99 LIMIT 10;
SELECT * FROM invoices WHERE Total >= 10;

💡 팁: 문자열을 비교할 땐 'USA'처럼 작은따옴표로 감싸야 한다. 숫자는 따옴표 없이 쓴다.

복합 조건 — AND / OR / NOT#

조건을 여러 개 묶을 때 쓴다. AND(둘 다), OR(또는), NOT(아닌 것).

SELECT * FROM customers WHERE Country = 'USA' AND State = 'CA';
SELECT * FROM customers WHERE Country = 'USA' OR Country = 'Canada';
SELECT * FROM customers WHERE NOT Country = 'USA';  -- = WHERE Country != 'USA'

💡 팁: 강사님은 여러 나라를 OR로 길게 나열하기보다 다음에 배울 IN(...)을 쓰는 게 더 깔끔하다고 안내했다.

기타 연산자 — BETWEEN / IN / NOT IN#

SELECT * FROM invoices WHERE Total BETWEEN 5 AND 10;            -- 5~10 (경계 포함)
SELECT * FROM customers WHERE Country IN ('USA', 'Canada', 'Brazil');     -- 목록 포함
SELECT * FROM customers WHERE Country NOT IN ('USA', 'Canada', 'Brazil'); -- 목록 제외

BETWEEN A AND B는 A와 B를 포함한다는 점에 주의.

LIKE — 패턴으로 찾기#

특정 문자가 포함된 문자열을 찾을 때 쓴다. 와일드카드 %의 위치가 핵심이다.

패턴의미
'K%'K로 시작
'%K'K로 끝남
'%K%'K 포함
SELECT * FROM albums WHERE Title LIKE 'Rock%';   -- 'Rock'으로 시작
SELECT * FROM albums WHERE Title LIKE '%Live';   -- 'Live'로 끝남
SELECT * FROM tracks WHERE Name LIKE '%Love%' LIMIT 10;  -- 'Love' 포함

ORDER BY — 정렬#

ORDER BY는 결과를 정렬한다. ASC=오름차순(작은 값부터), DESC=내림차순(큰 값부터).

SELECT Name, UnitPrice FROM tracks ORDER BY UnitPrice DESC LIMIT 10;  -- 비싼 순 10개
SELECT * FROM invoices ORDER BY Total DESC LIMIT 5;                   -- 결제액 큰 순 5건
SELECT Title FROM albums ORDER BY Title ASC LIMIT 10;                 -- 제목 알파벳 순

💡 팁: 앞서 말한 대로 여기 DESC는 내림차순 정렬이고, 1장에서 본 DESC 테이블명(구조 보기)과는 완전히 다른 기능이다.

07 · DML — 데이터를 추가·수정·삭제하기 (book 테이블)#

조회(Read)를 익혔으니 이제 C·U·D다. 이걸 데이터를 다룬다는 뜻에서 **DML(데이터 조작어)**라 부른다.

중요한 원칙: 실습용 chinook DB를 직접 건드리지 않는다. 대신 book이라는 테이블을 새로 만들어 거기서 INSERT·UPDATE·DELETE를 연습했다(실수로 원본 데이터를 망치지 않기 위함).

먼저 테이블을 만들고 데이터를 채운다(코드 전문은 실습 노트 참고).

DROP TABLE IF EXISTS book;   -- 이미 있으면 지우고 새로 → 몇 번 실행해도 에러 없음

CREATE TABLE book (
    id       INTEGER PRIMARY KEY,
    title    TEXT,
    category TEXT,
    price    REAL,
    rating   INTEGER,
    stock    INTEGER
);

DROP TABLE IF EXISTS는 재실행 가능한 스크립트를 만드는 패턴이다. 이미 테이블이 있어도 에러 없이 새로 만든다.

INSERT — 행 추가#

-- 컬럼명 명시
INSERT INTO book (id, title, category, price, rating, stock)
VALUES (13, 'It''s Only the Himalayas', 'Travel', 45.17, 2, 19);

-- 컬럼명 생략 (테이블 정의 순서대로 값 입력)
INSERT INTO book VALUES (14, 'Set Me Free', 'Young Adult', 17.46, 5, 19);

💡 팁: 컬럼명을 생략하면 테이블을 만들 때 정한 순서대로 값이 들어간다. 그리고 문자열 안에 작은따옴표가 있으면(It's) **두 번 연속('')**으로 써서 이스케이프한다. 컬럼 수와 값 개수가 안 맞으면 에러가 난다.

UPDATE — 값 수정#

UPDATE book SET price = 39.99 WHERE title = 'Soumission';      -- 특정 책 가격 변경
UPDATE book SET stock = stock + 5 WHERE category = 'Poetry';   -- 기존 값 기반 연산

SET 컬럼 = 값으로 수정하고, WHERE로 어떤 행을 바꿀지 지정한다. stock = stock + 5처럼 기존 값을 활용한 연산도 가능하다.

DELETE — 행 삭제#

DELETE FROM book WHERE rating = 1;    -- 평점 1점인 책 삭제
DELETE FROM book WHERE stock < 16;    -- 재고 16권 미만 삭제

⚠️ 가장 중요한 주의: UPDATE와 DELETE에서 WHERE를 빼먹으면 테이블 전체가 수정·삭제된다. 예를 들어 DELETE FROM book;은 book의 모든 행을 삭제한다. 실무에서 가장 무서운 실수다.

참고: 판서 기록의 과제 표현(“재고=15 삭제”)과 정답 SQL의 stock < 16(재고 16 미만) 사이에 표현 차이가 있다. 결과적으로는 거의 같으나, 본 정리는 **정답 파일 기준 stock < 16**으로 서술했다 [원문 확인 필요].

08 · 강사님이 강조한 포인트 (정리)#

오늘 반복해서 강조된 내용을 모았다.

  • CRUD가 DB 기초의 핵심. 어려움은 CRUD가 아니라 테이블 조합·조건 설계에서 온다.
  • ERD(테이블 관계도) 보는 훈련을 반복하라. “강사 화면 따라 치기” 금지 — ERD를 보고 컬럼·테이블을 확인한 뒤 직접 작성.
  • DML은 별도 DB(book)에서. 원본(chinook) 손상 방지. 동시에 여러 DB를 연결하면 헷갈리니 하나만 연결 유지(나머지 Disconnect).
  • WHERE 누락 = 전체 수정/삭제 위험(UPDATE·DELETE 공통).
  • 직무별 활용도(강사 의견): 데이터 분석 직무는 임의 삭제·수정이 위험해 실무에선 제한적, 개발 직무는 CRUD가 필수.
  • 운영 공지: 화~금 6교시 시험 예고, 답지는 매일 공유, 다음날부터 시험은 classicmodels DB 사용 예고.

마무리#

오늘은 데이터를 다루는 첫 삽을 뜬 날이다. 큰 그림은 단순하다 — 데이터베이스는 데이터의 모음이고, 그걸 다루는 표준 언어가 SQL이며, 핵심 동작은 CRUD 네 가지다. SELECT로 원하는 데이터를 조건 걸어 골라내고(WHERE·DISTINCT·LIKE·ORDER BY), DML로 추가·수정·삭제한다. 무엇보다 잊지 말 것 — WHERE 없는 UPDATE·DELETE는 전체를 날린다. 내일은 여기에 **함수와 여러 테이블 결합(JOIN)**이 더해진다.
