01 · 데이터 로드 & 구조 점검#

데이터를 읽었으면 분석 전에 규모·스키마·분포부터 본다. “이 표가 몇 행 몇 열인지, 각 열이 무슨 타입인지, 값이 어떻게 퍼져 있는지"를 모르고 분석에 들어가면 사고가 난다. pandas는 이걸 한 묶음의 메서드로 제공한다.

메서드 무엇을 보나
shape (행, 열) 튜플 — shape[0]=행 수, shape[1]=열 수
info() 열 이름·dtype·비결측 개수·메모리 (object는 보통 문자열)
describe() 수치형 요약(개수·평균·표준편차·사분위). 범주형은 describe(include='object')
dtypes / columns.tolist() 열별 타입 / 컬럼명 리스트
head(n) / tail(n) 앞·뒤 n행 미리보기
sample(n, random_state=42) 무작위 n행 (시드 고정 시 재현 가능) 
print(df_srv.shape)            # (11000, 15)        [문제1]
df_sup.info()                  # 스키마 + 메모리      [문제2]
df_wel.describe()              # 수치형 요약          [문제3]
df_sup.memory_usage(deep=True).sum()   # 1729533바이트  [문제8]
df_wel.sample(5, random_state=42)      # 재현 가능 표본 [문제9]

💡 random_state=42의 의미. sample은 무작위 추출이라 돌릴 때마다 결과가 달라지는데, 시드를 고정하면 매번 같은 5행이 나온다(재현성). 어제 NumPy의 default_rng(42)와 같은 원리다.

💡 SQL과 pandas의 관계. 강사는 “groupby 같은 가공 논리는 SQL과 거의 같고 문법만 다르다“고 짚었다. 현실에선 운영 DB에서 SQL로 필요한 데이터만 추출한 뒤, 그걸 pandas로 가져와 분석하는 구조가 흔하다. 어제 배운 SQL이 여기서 연결된다.

02 · 핵심 이론 — DataFrame vs Series, loc vs iloc#

코드를 치기 전에 두 가지 개념을 깔고 간다. 강사가 4-6교시 내내 반복해서 물어본 부분이다.

DataFrame vs Series#

Series DataFrame
차원 1차원 (index + value) 2차원 (index + 복수 column)
비유 표의 한 줄(열) 표 전체
언제 생기나 단일 컬럼 추출 df['col'] 복수 컬럼 df[['col1','col2']]

💡 혼동되면 type()으로 확인. “단일 컬럼을 고르면 보통 Series, 복수 컬럼·복수 값 구조면 DataFrame"이 기본 직관이다. 클래스가 다르면 같은 메서드(value_counts() 등)도 결과 형태가 달라지므로 지금 구분을 손에 익혀야 한다. df['col'](대괄호 1개)은 Series, df[['col']](대괄호 2개)은 DataFrame이다.

loc vs iloc — 행·열을 고르는 두 방식#

loc iloc
기준 라벨(이름)·Boolean 정수 위치(순서)
입력 예 'a', ['a','c'], 'a':'c', 불리언 마스크 4, [4,3,0], 1:7
슬라이싱 끝 포함 ('a':'c'는 c까지) 미포함 (파이썬 규칙)

💡 초심자는 loc 중심으로. 강사는 “혼란 방지를 위해 처음엔 loc만으로 학습하라"고 권했다. 분석 목적이면 loc만으로 충분하고, iloc은 위치 기반이라 자동화·속도(개발·대용량)에 유리하다. df.컬럼명 같은 점 표기도 가능하지만 한 방식으로 통일하기 위해 지양하고, 선택한 결과는 copy()로 따로 저장하길 권한다.

03 · 행·열 선택#

위 개념을 코드로 옮긴다. 핵심은 loc[행, 열] 형태 — 첫 인자가 행, 둘째 인자가 열이다.

df_srv.loc[:, ['server_id','location','cpu_usage']].head()   # 모든 행 + 특정 열  [문제11]
df_sup[['item_name','category','stock_level']].head()        # [] 로 열 선택      [문제12]
df_srv.iloc[0, :]                  # 첫 행 → Series             [문제14]
df_sup.iloc[:5, :3]                # 앞 5행 · 앞 3열(끝 미포함)   [문제15]
df_sup.iloc[100:105]               # 중간 구간                  [문제18]

💡 단일 컬럼 df['col']은 Series, 컬럼 리스트 df[['col']]은 DataFrame (§02 재확인). iloc 슬라이싱 :3은 끝 미포함이라 0·1·2 세 개만 나온다 — 어제 NumPy 슬라이싱과 똑같은 규칙이다.

04 · 조건 필터링 ★당일 비중이 컸던 부분#

오늘 라이브에서 가장 많은 시간을 쓴 곳. “조건에 맞는 행만 골라내기” 다. 원리는 어제 NumPy의 불리언 마스킹과 100% 동일하다 — 비교 연산이 True/False(Boolean) Series를 만들고, 그걸 loc에 넣으면 True인 행만 남는다.

단일 조건#

df_srv.loc[df_srv['issue_category'] == '디스크', :].head()    # 이슈가 '디스크'인 행  [문제19]
df_srv.loc[df_srv['cpu_usage'] > 40, :].head()                # CPU 40 초과         [문제25]

value_counts로 최빈값 기준 필터#

top_r = df_wel['region'].value_counts().index[0]   # 가장 많은 지역 = .index[0]
df_wel.loc[df_wel['region'] == top_r, :].head()                                  # [문제21]

복합 조건 — 비트 연산자 & · | 와 괄호#

# AND — 두 조건 모두 만족
df_srv.loc[(df_srv['fix_required']==1) & (df_srv['issue_detected']==1), :].head()   # [문제22]

💡 and/or가 아니라 &/|, 그리고 각 조건은 반드시 괄호로. 어제 NumPy에서 강조한 것과 똑같다. (조건1) & (조건2)처럼 쓰지 않으면 연산자 우선순위 때문에 엉뚱하게 계산되거나 에러가 난다. 강사 팁 — 괄호로 틀을 먼저 만들고 그 안에 조건을 채워 넣어라. 문법 오류(괄호·연산자 누락)는 자연스러운 과정이고 반복하면 줄어든다.

isin — 여러 값 중 하나#

df_srv.loc[df_srv['check_type'].isin(['일간','주간']), :].head()              # [문제23]
df_srv.loc[df_srv['issue_category'].isin(['CPU과부하','디스크']), :].head()    # [문제24]

💡 긴 (==A) | (==B) | (==C)를 isin([A,B,C]) 한 줄로 줄인다. 부정(“이 값들 빼고”)은 앞에 ~를 붙인다.

★ 컬럼 간 비교 — 값이 아니라 다른 열과 비교#

# 재고가 재발주 기준보다 낮은 행 (열 vs 열)
df_sup.loc[df_sup['stock_level'] < df_sup['reorder_threshold'], :].head()       # [문제26]

💡 “상수와 비교"만이 아니라 “열과 열을 비교"할 수 있다. 강사는 iris로 Sepal.Width > Petal.Length처럼 행 단위로 두 열을 한 번에 비교 → True/False 한 줄로 축약되는 걸 시연했다. “재고 < 재발주 기준” 같은 실무 조건이 이 형태다.

구간 조건 — 그리고 ★원본 예제의 오류 정정#

# 원본 문제27 — 정신건강 점수 60~80 구간
df_wel.loc[(df_wel['mental_wellbeing_score']>=60) & (df_wel['mental_wellbeing_score']<=80), :].head()  # [문제27]

이 코드를 그대로 돌리면 빈 표(Empty DataFrame) 가 나온다. 에러가 아니라, 조건에 맞는 행이 0개라서다.

💡 왜 빈 결과인가 — 정직하게 짚고 간다. mental_wellbeing_score의 실제 분포는 1~10 수준의 한 자리 수다(아래 §06 문제39에서 rank별 중앙값이 12로 나오는 것으로 확인된다). 그러니 60~80 구간에 해당하는 행은 애초에 없다. **라이브에서도 강사가 “6080 vs 6~8을 재확인해야 한다"고 언급**했다 — 즉 의도한 구간은 6~8이고, 원본 문제의 60~80은 오타(오류)일 가능성이 높다. 데이터에 맞추려면 이렇게 고쳐야 한다.

# 의도에 맞춘 정정 버전 — 6~8 구간
df_wel.loc[(df_wel['mental_wellbeing_score']>=6) & (df_wel['mental_wellbeing_score']<=8), :].head()

교훈: 필터 결과가 비었을 때 코드 탓만 하지 말고 “내가 건 조건이 실제 데이터 분포 안에 있나"를 describe()·value_counts()로 먼저 확인하라. 빈 결과는 버그가 아니라 종종 데이터에 대한 오해의 신호다.

필터 후 인덱스 정리#

df_srv.loc[df_srv['temp_abnormal_flag']==1, :].reset_index(drop=True).head()    # [문제28]

💡 필터링하면 원래 인덱스(예: 3, 17, 42…)가 듬성듬성 남는다. reset_index(drop=True)로 0부터 다시 매기고, 결과를 계속 쓸 거면 copy()로 따로 저장하길 권한다. 실습은 28번까지 진행하고 29~31번은 자율 과제로 넘겼다.

05 · 정렬#

sort_values(컬럼, ascending=, na_position=) — 기본은 오름차순. 다중 키는 리스트로 주고, 키마다 방향을 다르게 줄 수도 있다(ascending=[True, False]). “상위 n개"는 head와 조합한다.

df_srv.sort_values('cpu_usage', ascending=False).head(8)         # CPU 높은 순 (최대 100.0)  [문제29]
df_sup.sort_values('requested_quantity').head(8)                 # 요청량 적은 순            [문제30]
df_srv.sort_values(['location','check_date']).head(8)            # 다중 키 (지역→날짜)       [문제32]

💡 다중 키 정렬은 “지역으로 먼저 묶고, 같은 지역 안에서 날짜로 다시 정렬"하는 식이다. SQL의 ORDER BY a, b와 같다.

06 · GroupBy 집계 ★4-6교시 핵심#

오늘 pandas 파트의 정점. “범주별로 묶어서 요약하기” 다 — “지역별 평균 CPU”, “카테고리별 총 요청량” 같은 질문에 답한다. 동작 원리는 세 글자로 요약된다.

Split-Apply-Combine#

전체 데이터 ──Split──▶ 그룹들로 쪼갬 ──Apply──▶ 그룹마다 집계 ──Combine──▶ 하나로 합침

문법은 한 줄이다 — df.groupby(그룹컬럼)[수치컬럼].집계함수().

df_srv.groupby('location')['log_id'].count().sort_values(ascending=False).head(10)  # 지역별 점검 건수  [문제33]
df_srv.groupby('issue_category')['cpu_usage'].mean()                  # 이슈별 평균 CPU    [문제34]
df_wel.groupby('facility_type')['satisfaction_score'].mean()          # 시설유형별 만족도  [문제38]

agg — 한 번에 여러 집계#

df_srv.groupby('check_type')['fix_duration_hours'].agg(['mean','max'])   # [문제35]

출력:

                mean    max
check_type
월간          2.983514  11.56
일간          3.016626  11.79
주간          2.998414  11.47

💡 agg(['mean','max'])처럼 집계가 여러 개면 결과가 복수 컬럼 → DataFrame이 된다. 집계 하나면 Series, 여럿이면 DataFrame — §02의 구분이 여기서 다시 나온다. 자주 쓰는 집계: count, sum, min, max, mean, median, std, var, quantile, first, last.

다중 그룹 + unstack#

df_wel.groupby(['region','facility_type'])['satisfaction_score'].mean().head(15)  # 다중 그룹  [문제40]

두 개 컬럼으로 묶으면 결과 인덱스가 다중(MultiIndex) 이 되어 한눈에 안 들어온다. 이때 unstack() 으로 한 축을 열로 펼쳐 표 형태로 만든다.

df_wel.groupby(['region','facility_type'])['satisfaction_score'].mean().unstack()
# region을 행, facility_type을 열로 펼친 교차표 → 이후 .loc로 특정 조합 조회

💡 unstack = MultiIndex를 피벗 테이블로. 세로로 길게 쌓인 다중 인덱스 결과를 가로로 펼쳐 가독성·조회 편의를 높인다. 펼친 뒤엔 loc[행, 열]로 “A지역 × 체육시설” 같은 특정 조합 값을 바로 꺼낼 수 있다.

💡 groupby 결과 자체는 DataFrame이 아니다. df.groupby('x')만 하면 DataFrameGroupBy라는 중간 객체일 뿐이고, 뒤에 집계 함수를 붙여야 결과가 나온다. 그리고 그룹 컬럼은 아무 열이나 되는 게 아니다 — 고유값이 너무 많은 연속형(예: total_bill)은 부적절하고, 범주형(지역·요일)이나 값 종류가 제한된 수치(예: size) 가 적합하다.

💡 §06 문제39가 §04의 정정을 뒷받침한다. df_wel.groupby('rank')['mental_wellbeing_score'].median()를 돌리면 병장·상병·이병 2.0, 일병 1.0 이 나온다 — 정신건강 점수가 한 자리 수임을 직접 보여준다. 그래서 문제27의 60~80 필터가 빈 결과였던 것이다.

07 · (자료 제공) 결측·문자열·시계열·결합#

📎 여기부터는 라이브 당일이 아닌 자료 제공/후속 진행분이다. 예제 노트북 70제 중 §06 이후 범위로, 같이 정리해 둔다. 코드·출력은 코드 노트에서 확인할 수 있다.

결측·중복#

df_srv.isna().sum()                              # 열별 결측 개수(이 데이터는 모두 0)  [문제43]
df_sup.duplicated().sum()                        # 중복 행 수(0)                     [문제45]
df_sup.drop_duplicates(subset=['supply_id']).shape[0]   # 키 기준 중복 제거(11000)   [문제46]

수치열 결측은 중앙값 대체(fillna(median())), 범주형은 fillna('Unknown') 식으로 채운다 — 어제 §05에서 본 “결측치 처리엔 정답이 없다, 비교 실험으로 고른다"가 여기 코드로 이어진다.

문자열 (str 접근자)#

df_sup['item_name'].str.upper().head()                            # 대문자화      [문제49]
df_srv['location'].str.contains('사단', na=False).sum()   # '사단' 포함 수(9617)  [문제50]

💡 str.contains(..., na=False)의 na=False가 중요하다 — 결측값을 만나면 에러 대신 False로 처리해 준다.

시계열 (to_datetime · .dt)#

pd.to_datetime(df_srv['check_date']).dt.year.value_counts()       # 연도별 건수(2024:11000)  [문제54]
df_srv.loc[pd.to_datetime(df_srv['check_date']) >= '2024-10-01', :].head()              # [문제56]
pd.to_datetime(df_wel['date']).dt.dayofweek.value_counts()        # 요일별(월=0…일=6)        [문제57]

💡 CSV에서 날짜는 보통 문자열(object) 로 읽힌다. to_datetime으로 날짜 타입으로 바꿔야 .dt.year·.dt.dayofweek 같은 추출이 가능하다. errors='coerce'를 주면 깨진 값은 NaT(결측 날짜)로 처리된다.

결합 — merge / concat / pivot, 그리고 ★두 번째 정정#

m = df_sup.merge(df_wel, on='unit_code', how='inner', suffixes=('_sup','_wel'))   # [문제61]
m.shape    # (0, 33)  ← 0행!

inner merge 결과가 (0, 33) — 열은 33개로 합쳐졌는데 행이 0개다. 또 에러는 아니다.

💡 왜 0행인가 = merge 키 정합성 문제. inner는 양쪽 키가 일치하는 행만 남기는데, 두 테이블의 unit_code 값 도메인이 서로 다르다 — 군수품은 31A·18A 같은 코드형, 복지는 17사단·14사단 같은 명칭형이다. 겹치는 값이 하나도 없으니 교집합이 0행. 이건 버그가 아니라 “merge 전에 두 키의 값이 같은 형식인지 반드시 확인하라” 는 산 교훈이다. df_sup['unit_code'].unique()와 df_wel['unit_code'].unique()를 찍어보면 도메인 불일치가 바로 보인다.

정상적으로 붙는 merge는 그룹 평균을 원본에 되붙이는 패턴이다.

loc_cpu = df_srv.groupby('location', as_index=False)['cpu_usage'].mean()
df_srv.merge(loc_cpu, on='location', how='left', suffixes=('','_locmean')).head()   # [문제63]
merge how 의미
inner 양쪽 키 교집합 (일치하는 행만)
outer 합집합 (한쪽만 있어도 포함, 빈 곳은 NaN)
left / right 왼쪽 / 오른쪽 테이블 기준

concat은 단순 이어붙이기(axis=0 상하, axis=1 좌우), pivot_table은 엑셀 피벗(values/index/columns/aggfunc)에 대응한다.

08 · (자료 제공) 벡터화 — 루프 대신 배열 연산#

📎 별도 노트북 vectorization.ipynb 분량. 어제 NumPy에서 “가장 중요"라 한 벡터화를 pandas/실데이터에 적용한다.

핵심은 어제와 같다 — 행마다 for로 도는 대신, 열 전체에 한 번에 연산한다. 실제로 얼마나 빠른지 측정한 결과:

n = 50_000
a = rng.random(n); b = rng.random(n)
# 루프:   for i in range(n): out_loop[i] = a[i]*b[i] + np.sqrt(a[i])
# 벡터화: out_vec = a*b + np.sqrt(a)
# 결과 → loop: 17.3 ms / vector: 0.4 ms / speedup: 39.4x

💡 같은 계산이 약 39배 빠르다. 루프는 파이썬 인터프리터가 5만 번 도는 반면, 벡터화는 내부 C 루프로 한 번에 처리한다. (난수·환경에 따라 절대 수치는 달라질 수 있다 — speedup의 자릿수가 핵심이다.) 실데이터에선 군수품 재고/사용량 = stock_runway_days, 서버 mean(axis=1) 자원부하, 복지 min-max 정규화, 엑셀 z-score 같은 파생변수 대량 생성이 전부 이 벡터화 패턴으로 만들어진다.

💡 0으로 나누기 방지 패턴. 파생변수에서 분모가 0이 될 수 있는 곳마다 clip(lower=eps)나 np.where(denom<1e-9, 1.0, denom)로 막는다 — 실무 디버깅의 단골이다.

여기부터는 개념을 넓게 훑는 시간이다. 실제 차트 코딩(matplotlib/seaborn/plotly/streamlit)은 §14에서 후속 차시로 예고만 한다. 출처는 Fundamentals of Data Visualization(Claus Wilke)의 한글 번안 교안이다.

09 · 시각화의 중요성 — “왜 표가 아니라 그림인가”#

플로렌스 나이팅게일 — Rose Diagram#

나이팅게일(1820~1910)은 간호사이자 통계학자였다. 크림전쟁의 사망 데이터를 숫자 표가 아니라 Rose Diagram(장미도표, polar area chart) 으로 그려 영국 의회·육군 수뇌부를 설득했다.

  • 색으로 사인을 구분 — 파란색=예방 가능한 전염병, 붉은색=전상(Wounds), 검은색=기타.
  • 두 시기를 나란히 — 위생 개혁 전(1854–55) vs 후(1855–56) 를 비교해, 정책 개입의 효과를 한눈에 보여줬다.

💡 핵심 메시지 — “데이터가 아니라 전달 방식의 차별화.” 같은 사망 통계라도 숫자 표로는 의원들을 움직이지 못했지만, 면적으로 본 그림은 예방 가능한 죽음이 압도적임을 즉각 전달했다. 어제 §06에서 본 “데이터 커뮤니케이션 — 읽는 사람에 맞춰 전달하라"의 역사적 원조다.

앤스컴 콰르텟 (Anscombe’s Quartet)#

4개의 데이터셋(I~IV)이 있는데, 기술통계량이 전부 똑같다 — x 평균 9, y 평균 7.50, 상관 0.816, 회귀선 y=3.00+0.500x, R²=0.67. 그런데 그래프로 그리면 네 개가 완전히 다르다(하나는 직선, 하나는 곡선, 하나는 이상치 하나에 끌려간 형태…).

💡 “수치 통계만 믿지 말고 반드시 그려봐라.” 평균·상관계수가 같아도 분포·패턴은 천차만별일 수 있다. 어제 데이터 리터러시에서 “상관 ≠ 인과"를 조심하라 했듯, 여기선 “요약 통계 ≠ 데이터의 진짜 모습” 이다. 시각화가 분석의 필수 단계인 결정적 이유.

10 · 시각화의 원리 — 삭제 > 분리 > 강조 > 배열#

Gene Zelazny의 『Say it with Charts』가 제시한 순서. 무엇을 그릴지보다 무엇을 지울지가 먼저다.

순서 원리 설명
1 삭제(Delete) 필수 데이터만 남기고, 의미 없는 차트·요소는 지운다
2 분리(Divide) 한 차트에 욱여넣지 말고 논리 단위로 나눠 별도 차트로
3 강조(Highlight) 핵심은 강조, 부가 정보는 약하게/숨김 (대조로 시선 유도)
4 배열(Arrange) 영역별로 묶고, 영역 간·영역 내를 논리 순서로 구조화

💡 §10은 §13의 디자인 원칙과 한 몸이다 — “잉크를 데이터에 쓰고, 장식에 낭비하지 마라"는 큰 줄기.

11 · 시각화 기초 — 미학 요소 · 좌표계 · 색상#

좋은 시각화의 3대 문제와 목표#

좋은 그래프는 세 가지를 통과해야 한다 — 심미적(매력적인가) · 지각적(명확한가, 정보 과다는 아닌가) · 수학적(축·면적을 임의 조정해 수치를 왜곡하지 않았나). 목표는 한 단어씩 — 명확(Clear) · 정직(Honest) · 간결(Concise).

미학 요소(Aesthetics) — 데이터를 시각으로 매핑하기#

데이터의 각 변수를 위치·길이·색상·형태·크기 같은 시각 속성에 대응(매핑)시키는 게 시각화의 본질이다.

💡 가장 중요한 변수일수록 위치·길이로. 인간은 위치와 길이를 가장 정밀하게 인식하고, 면적·색상·각도는 덜 정확하다. 그러니 핵심 변수를 위치/길이에 먼저 배치하고 색상은 보조로 쓴다.

  • 일대일 매핑(가역성): 값 ↔ 시각요소가 1:1이어서, 그림만 보고 원래 값을 역추정할 수 있어야 한다.
  • 접근성(CVD): 색각이상을 고려해 색만으로 구분하지 말고 모양·패턴을 병행한다.
  • 단순성: 한 그래프에 미학 요소는 3개 이내 — 그 이상은 인지 부하가 된다.

좌표계 — 같은 데이터도 좌표계가 의미를 바꾼다#

좌표계 특징 / 쓸 곳
직교(Cartesian) 표준 2D. 단위가 같으면 종횡비 1:1(정사각 격자)
로그(Log) 한 칸=고정 배수(곱셈). 비율·넓은 범위에 유용. 0·음수 불가(기준 1), 로그임을 명시
극(Polar) 각도θ·거리r. 주기 데이터(연 기온·24시간)에 유용. 파이차트=극좌표 stacked bar
지도 투영 3D→2D는 필연적 왜곡. 면적·형태·거리·방향 중 trade-off (Mercator=각도보존, Goode=면적보존, Robinson=절충)

💡 실무 체크: 물리 단위가 같으면 종횡비 1:1, 막대그래프는 0에서 시작(축 절단 금지), 산점도·선그래프는 0에서 시작할 필요 없음.

색상 스케일 — 용도가 셋이다#

용도 스케일 종류 예
구분(Distinguish) Qualitative(질적) Okabe-Ito — 순서 없는 범주, 시각 강도 균등
값 표현(Represent) Sequential(순차) / Diverging(발산) Blues(밀도) / PiYG·PuOr(중립점 기준 편차)
강조(Highlight) Accent 회색조 배경 + 강렬한 강조색

💡 무지개색(Rainbow/Jet)을 피하라. 밝기가 단조롭게 변하지 않아 순서를 왜곡하고 인위적 경계를 만든다. 대신 Viridis·Magma·Inferno 같은 지각적 균등 스케일을 쓴다.

💡 CVD(색각이상) 고려. 남성 약 8%가 적록색맹이다. 빨강-초록 대비를 피하고, 명도 차이를 함께 주며, 안전 팔레트(Viridis, Okabe-Ito)를 쓴다. 색상은 8색 이상 넘어가면 구분이 어려워진다.

12 · 목적별 차트 유형#

“무엇을 보여주려는가"가 차트 종류를 결정한다. 목적별로 정리하면.

목적 대표 차트 핵심 포인트
양(Amounts) Bar / Dot / Heatmap 막대는 0 시작, 의미 있는 정렬, 라벨 길면 수평 막대. Grouped vs Stacked
분포(Distributions) Histogram / KDE / Boxplot / Violin / ECDF / Q-Q 히스토그램=bin 너비 민감, KDE=대역폭 민감, ECDF=정보 손실 없음, Q-Q=정규성·꼬리 비교
비율(Proportions) Pie / Stacked bar / Treemap / Mosaic 부분-전체 관계
관계(Relationships) Scatter / Line / Connected scatter / Correlogram 시계열=Line+Direct Labeling, 추세=이동평균·LOESS
지리(Geospatial) Choropleth / Cartogram 단계구분도는 비율(rate) 로, 면적 왜곡·투영 주의
불확실성(Uncertainty) Error bar / Confidence band / Quantile dotplot 오차막대는 SD/SE/CI 명시 필수, “100명 중 5명” 빈도 프레이밍

💡 분포 비교 도구 고르기. Boxplot(요약통계·이상치) vs Violin(밀도·다봉성) vs Strip(개별점+지터링) vs Sina(둘의 하이브리드) vs Ridgeline(능선·시간 변화). 보여주려는 게 “요약"이냐 “전체 모양"이냐로 고른다.

💡 오버플로팅 해결. 점이 너무 겹치면 → 부분 투명도 / 지터링 / 2D 히스토그램·헥사곤·등고선. 시계열에선 범례 대신 선 끝에 직접 라벨(Direct Labeling) 을 붙여 시선 왕복(Eye Tennis)을 줄인다.

13 · 디자인 원칙 — 정직하게 그리기#

비례 잉크 원칙 (Proportional Ink)#

💡 음영 면적은 수치에 정비례해야 한다 (Value ∝ Area). 그래서 선형축 막대는 반드시 0에서 시작한다. 축을 잘라내면(truncation) 작은 차이가 거대하게 과장된다 — 어제 §06 “영점 없는 막대그래프가 차이를 부풀린다"가 바로 이 원칙의 위반이다. 작은 차이를 보여주고 싶으면 막대 대신 Dot Plot을 쓴다. (로그축 막대는 기준선이 1)

그 외 핵심#

  • Redundant Coding(중복 코딩): 색만 쓰지 말고 색+모양/선종류를 병행 — 흑백 인쇄·CVD에서도 구분된다.
  • Small Multiples: 같은 축 범위를 공유하는 작은 그래프 여러 개로 비교(어제 본 axis 공유와 통한다).
  • Compound Figures: 이질적 차트를 합칠 땐 일관된 시각 언어 + 패널 라벨(a, b, c).
  • 명확성: 3D 효과 지양, 라벨 크게, 데이터-맥락 균형.

  • matplotlib + seaborn (10–11일차): seaborn은 pandas DataFrame에서 통계 그래프(회귀선 등)를 쉽게 그려준다. matplotlib으로 틀을 잡고 세부를 조정하는 2단 구조. 세부 수정엔 결국 matplotlib 지식이 필요.

마무리#

오늘은 데이터를 깎는 손(pandas) 과 데이터를 보여주는 눈(시각화) 을 한 번에 잡았다. 1부 pandas에선 — 데이터를 읽으면 먼저 shape·info·describe로 점검하고, DataFrame vs Series(대괄호 1개 vs 2개)와 loc(라벨)·iloc(위치) 를 구분하며, 조건 필터링(불리언 마스크 + &/| + 괄호 + isin + 컬럼 간 비교)으로 행을 골라내고, sort_values 로 정렬한 뒤, 핵심인 groupby(Split-Apply-Combine) + agg + unstack 으로 범주별 요약을 만들었다. 자료 제공분으로 결측·문자열·시계열·merge(키 정합성!)·벡터화(39.4배) 까지 이어졌다. 특히 문제27(60~80 빈 결과) 과 문제61(merge 0행) 은 원본 예제의 빈틈을 정직하게 정정하면서 “빈 결과는 버그가 아니라 데이터에 대한 질문"임을 배웠다. 2부 시각화에선 — 나이팅게일·앤스컴 콰르텟으로 “왜 그려야 하는가”, 삭제>분리>강조>배열의 원리, 미학 요소·좌표계·색상 스케일(CVD-safe), 목적별 차트, 비례 잉크 원칙까지 이론을 훑고 도구 실습을 예고했다. 한 줄로 — pandas로 데이터를 가공하고, 정직한 시각화로 그 데이터가 스스로 말하게 한다.
