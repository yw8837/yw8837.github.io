📖 수업 내용#

01 · 네트워크 개요#

네트워크(Network) 란 노드(Node)들이 통신 기술을 이용해 서로 연결된 망이다.
컴퓨터·스마트폰·서버 등이 케이블이나 무선으로 연결되어 데이터를 주고받는 구조 전체를 가리킨다.

네트워크의 장단점#

구분 내용
장점 파일·프린터 등 자원 공유, 원거리 통신 가능, 유지보수 비용 절감
단점 보안 취약점 발생, 바이러스·악성코드 전파 위험, 관리 복잡도 증가

전송매체 종류#

매체 특징
동축 케이블 구형 케이블 TV·인터넷용, 내부 도체 + 외부 차폐 구조
이더넷 케이블 LAN에서 가장 많이 쓰이는 유선 케이블 (UTP/STP)
광섬유 빛 신호로 전송, 장거리·고속, 간섭 없음
라디오파 Wi-Fi·블루투스 등 단거리 무선
마이크로파 위성·기지국 등 장거리 무선

네트워크 토폴로지(Topology)#

노드들이 서로 어떻게 연결되어 있는지 그 물리적·논리적 구조를 나타낸다.

종류 구조 특징
Star 중앙 허브에 모든 노드 연결 중앙 집중, 장애 시 해당 노드만 영향
Bus 하나의 선에 모든 노드 연결 구축 간단, 케이블 단선 시 전체 장애
Ring 노드들이 원형으로 연결 데이터 순환 전송, 한 노드 장애 시 전체 영향
Mesh 일부 노드 상호 연결 부분 이중화
Fully Connected 모든 노드 상호 연결 최고 안정성, 비용 큼

네트워크 유형#

유형 범위 예시
PAN (Personal Area Network) 개인 기기 간 (~10m) 블루투스, USB
LAN (Local Area Network) 건물·캠퍼스 내 Wi-Fi, 이더넷
MAN (Metropolitan Area Network) 도시 규모 케이블TV망, 도시 광역망
WAN (Wide Area Network) 국가·대륙 이상 인터넷, 전용선

IP 주소#

구분 설명
IPv4 32비트, 4옥텟(예: 192.168.0.1), 약 42억 개 주소
IPv6 128비트, 16진수 8그룹(예: 2001:0db8::1), 사실상 무제한
MAC 주소 네트워크 인터페이스의 물리적 고유 주소 (48비트)
서브넷 마스크 IP 주소에서 네트워크/호스트 영역 구분
NAT 사설 IP ↔ 공인 IP 변환 기술

IP 클래스

클래스 첫 번째 옥텟 범위 용도
A 1 ~ 126 대형 네트워크
B 128 ~ 191 중형 네트워크
C 192 ~ 223 소형 네트워크
D 224 ~ 239 멀티캐스트
E 240 ~ 255 연구용 예약

통신 방식#

방식 설명
유니캐스트 1:1 통신, 특정 한 노드에만 전송
멀티캐스트 1:N 통신, 특정 그룹에 전송
브로드캐스트 1:전체 통신, 네트워크 내 모든 노드에 전송

OSI 7계층#

네트워크 통신을 7개 계층으로 분리한 표준 모델. 각 계층은 독립적으로 역할을 수행한다.

계층 이름 주요 프로토콜
7 응용 계층 (Application) HTTP, SMTP, FTP, DNS
6 표현 계층 (Presentation) SSL/TLS, JPEG, ASCII
5 세션 계층 (Session) SSL/TLS, NetBIOS
4 전송 계층 (Transport) TCP, UDP
3 네트워크 계층 (Network) IP, ICMP, ARP
2 데이터링크 계층 (Data Link) Ethernet, MAC, Wi-Fi
1 물리 계층 (Physical) 케이블, 허브, 리피터

🔑 라우팅 : 목적지까지의 최적 경로를 판단하는 동작

02 · 인터넷과 HTTP#

TCP/IP 4계층 vs OSI 7계층#

TCP/IP 계층 OSI 대응 설명
응용 계층 5·6·7 계층 HTTP, FTP, SMTP, DNS
전송 계층 4 계층 TCP, UDP
인터넷 계층 3 계층 IP, ICMP
네트워크 액세스 계층 1·2 계층 이더넷, Wi-Fi

인터넷 · 인트라넷 · 엑스트라넷#

구분 접근 범위 설명
인터넷 공개 전 세계 컴퓨터를 연결한 공개 통신망, 쌍방향
인트라넷 내부 전용 기업·조직 내 사설망
엑스트라넷 한정 공개 파트너사 등 특정 외부에 일부 개방한 내부망

프로토콜(Protocol)#

통신의 형식·약속·규칙. 서로 다른 장치들이 데이터를 교환하기 위한 표준.

프로토콜의 3요소

요소 의미
Syntax (구문) 데이터 형식·코딩·신호 수준
Semantics (의미) 각 비트 패턴의 의미, 오류 제어 방법
Timing (타이밍) 전송 속도, 순서 제어

주요 프로토콜 기능: 단편화, 캡슐화, 연결 제어, 순서 결정, 주소 설정, 동기화

캡슐화(Encapsulation) / 역캡슐화(Decapsulation)#

[보내는 쪽] 데이터 → 세그먼트 → 패킷 → 프레임 → 비트열
                  (각 계층에서 헤더 추가)

[받는 쪽]  비트열 → 프레임 → 패킷 → 세그먼트 → 데이터
                  (각 계층에서 헤더 제거)

HTTP(HyperText Transfer Protocol)#

웹에서 HTML 등 하이퍼텍스트 문서를 전송하기 위한 프로토콜.
무상태(Stateless) — 서버는 이전 요청을 기억하지 않는다.
클라이언트-서버 모델 — 클라이언트가 요청, 서버가 응답.

HTTP 메시지 구조#

구성 요소 내용
Start Line 메서드 + URL + HTTP 버전 (요청) / 버전 + 상태코드 (응답)
Header 메타 정보 (Content-Type, Authorization 등)
Empty Line 헤더와 바디 구분
Message Body 실제 전송 데이터

HTTP 메서드(CRUD 대응)#

메서드 CRUD 동작
GET Read 데이터 조회
POST Create 데이터 생성
PUT Update 데이터 전체 수정
DELETE Delete 데이터 삭제

HTTP 상태 코드#

코드 의미
2xx 성공 (200 OK, 201 Created)
3xx 리다이렉션 (301 Moved Permanently)
4xx 클라이언트 오류 (400 Bad Request, 404 Not Found)
5xx 서버 오류 (500 Internal Server Error)

03 · 주요 프로토콜#

IP(Internet Protocol)#

네트워크 계층에서 패킷 주소 지정 및 경로 설정 담당.

특성 설명
비신뢰성 패킷 전달 보장 안 함
비연결형 연결 설정 없이 전송
주소 지정 출발지·목적지 IP 주소 기록
경로 설정 라우팅을 통해 최적 경로 선택

DNS(Domain Name System)#

도메인 이름 → IP 주소 변환 서비스.
예: www.google.com → 142.250.x.x

DNS 질의 방식

방식 설명
재귀적 질의 DNS 서버가 대신 다른 서버에 질의하고 최종 결과 반환
반복적 질의 클라이언트가 직접 각 DNS 서버에 순차적으로 질의

DHCP(Dynamic Host Configuration Protocol)#

IP 주소·서브넷 마스크·게이트웨이 등을 자동으로 할당하는 프로토콜.

클라이언트 → (Discover) → DHCP 서버
클라이언트 ← (Offer)    ← DHCP 서버
클라이언트 → (Request)  → DHCP 서버
클라이언트 ← (Ack)      ← DHCP 서버

TCP(Transmission Control Protocol)#

연결형·신뢰성 전송 프로토콜. 데이터 순서·오류·흐름을 제어한다.

3-way Handshake (연결 수립)#

클라이언트 → SYN      → 서버
클라이언트 ← SYN/ACK  ← 서버
클라이언트 → ACK      → 서버

4-way Handshake (연결 종료)#

클라이언트 → FIN  → 서버
클라이언트 ← ACK  ← 서버
클라이언트 ← FIN  ← 서버
클라이언트 → ACK  → 서버

Full-Duplex : 양방향 동시 통신 지원

UDP(User Datagram Protocol)#

비연결형·고속 전송 프로토콜. 신뢰성보다 속도가 중요한 경우 사용.

구분 TCP UDP
연결 방식 연결형 비연결형
신뢰성 높음 (재전송 보장) 낮음 (손실 허용)
속도 상대적으로 느림 빠름
오류 제어 있음 체크섬만
사용 예 HTTP, 이메일, 파일 전송 동영상 스트리밍, DNS, 게임

FTP / SFTP#

구분 FTP SFTP
정의 File Transfer Protocol SSH File Transfer Protocol
보안 평문 전송 SSH 기반 암호화
포트 21 (제어), 20 (데이터) 22
모드 Active / Passive -

Active 모드 : 서버가 클라이언트에 데이터 연결 시도
Passive 모드 : 클라이언트가 서버에 데이터 연결 요청 (방화벽 환경에 유리)

04 · 보안#

인증(Authentication) vs 인가(Authorization)#

구분 인증 (Authentication) 인가 (Authorization)
목적 신원 검증 (“당신이 누구냐?”) 권한 확인 (“무엇을 할 수 있냐?”)
과정 로그인, 비밀번호, OTP, 생체인식 자원 접근 권한 검사
순서 먼저 수행 인증 후 수행
예시 비밀번호 입력, 지문 인식 관리자 페이지 접근 허용 여부

암호화#

평문(PlainText) → 암호화 → 암호문(CipherText)

종류 설명 예시
단방향 암호화만 가능, 복호화 불가 해시 함수
양방향 암호화·복호화 모두 가능 AES, RSA

해시(Hash)#

임의의 데이터를 고정 길이의 해시값으로 변환하는 단방향 암호화 함수.

해시 알고리즘#

알고리즘 해시 길이 특징
MD5 128 bit 빠르나 충돌 취약점 있어 보안용 비권장
SHA-1 160 bit MD5보다 안전하나 현재 비권장
SHA-2 224~512 bit 현재 가장 많이 사용 (SHA-256, SHA-512)
SHA-3 224~512 bit Keccak 알고리즘 기반, 최신 표준

해시 함수의 특징#

특징 설명
단방향성 해시값으로 원본 데이터 역산 불가
충돌 저항성 같은 해시값을 가진 두 데이터 찾기 불가
제1 역상 저항성 해시값 → 원본 복원 불가
제2 역상 저항성 같은 해시를 만드는 다른 입력 찾기 불가
압축 효과 어떤 크기의 입력이든 고정 길이 출력
눈사태 효과 입력 1비트 변경 시 출력 절반 이상 변경

해시 함수 활용#

활용 내용
무결성 검증 파일·메시지 전송 전후 해시값 비교로 변조 여부 확인
전자서명 생성·검증 작고 안전한 크기의 해시값으로 서명 생성
패스워드 검증 비밀번호 해시값 저장 → 유출돼도 원본 노출 없음

쿠키(Cookie)#

HTTP의 Stateless 특성을 보완하기 위해 서버가 클라이언트(브라우저)에 저장하는 작은 데이터.

쿠키의 특징#

  • 한 개당 최대 4KB, 최대 300개 저장 가능
  • 클라이언트(브라우저) 에 저장
  • 이름, 값, 만료날짜, 경로 정보 포함
  • 기본적으로 브라우저 종료 시 삭제

쿠키의 종류#

종류 설명
세션 쿠키 (Session Cookie) 브라우저 열려 있는 동안 유효, 종료 시 삭제
영구 쿠키 (Persistent Cookie) 하드디스크에 유효기간 동안 저장, 재방문 시 유지

쿠키 작동 원리#

1. 클라이언트 → HTTP 요청 → 서버
2. 서버 → 쿠키를 HTTP 헤더(Set-Cookie)에 담아 응답
3. 클라이언트가 쿠키 저장, 이후 요청마다 쿠키 포함
4. 서버 → 쿠키 업데이트 시 응답에 전달

쿠키의 장단점#

장점

  • 서버에 추가 저장 불필요 → 서버 Scale-out 부담 없음
  • 사용자 로컬 저장 → 빠른 속도

단점

  • 매 요청에 민감 정보 포함 → 보안 취약
  • 용량 제한으로 많은 정보 저장 불가
  • 브라우저마다 지원 방식 달라 공유 불가

세션(Session)#

서버 측에 사용자 정보를 저장하고, 클라이언트에는 세션 ID만 발급하는 방식.

1. 클라이언트 → 로그인 요청
2. 서버 → 세션 생성 + 세션 ID 쿠키로 전달
3. 클라이언트 → 이후 요청마다 세션 ID 전송
4. 서버 → 세션 ID로 사용자 정보 조회
구분 쿠키 세션
저장 위치 클라이언트 서버
보안 상대적으로 낮음 상대적으로 높음
서버 부하 없음 세션 저장 부하 발생
속도 빠름 서버 조회 필요

토큰(Token) & JWT#

토큰(Token) : 사용자 인증 정보를 담은 문자열. 서버에 저장하지 않아도 됨.

JWT(JSON Web Token)

[Header].[Payload].[Signature]
구성 내용
Header 토큰 타입(JWT), 서명 알고리즘
Payload 사용자 정보, 만료 시간 등 클레임(Claims)
Signature Header + Payload를 비밀키로 서명

JWT는 Stateless — 서버가 세션을 저장하지 않아 Scale-out에 유리하다.

마무리#

네트워크는 OSI 7계층 / TCP/IP 4계층이라는 모델 위에서 동작하며, 각 계층별 프로토콜이 역할을 분담한다.
HTTP의 Stateless 특성을 보완하기 위해 쿠키·세션·토큰이 등장했고, 보안 측면에서는 해시가 무결성과 패스워드 보호에 핵심적인 역할을 한다.
TCP의 3-way Handshake와 DNS의 도메인→IP 변환, DHCP의 자동 IP 할당은 인터넷을 움직이는 기본 뼈대다.
