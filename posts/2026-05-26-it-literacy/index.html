📖 수업 내용#

01 · 컴퓨터의 이해#

컴퓨터와 소통하는 방법 — 0과 1#

컴퓨터는 오직 0과 1, 두 가지 신호만 이해한다. 이를 기계어(Machine Language) 라고 한다.
TV를 켜고 끄는 것도, 에어컨을 조작하는 것도 결국 1(On)과 0(Off)의 조합이다.

우리가 일상에서 사용하는 모든 전자기기는 이 기계어로 동작하며, 엔지니어는 이 복잡한 기계어를 사람이 쉽게 다룰 수 있도록 인터페이스를 만들어 준다.

프로그래밍 언어 — 개발자와 컴퓨터 사이의 번역기#

기계어를 직접 다루는 건 너무 어렵기 때문에, 프로그래밍 언어가 등장했다.
JavaScript, Python, Java, C, Go, Swift, Kotlin, Rust 등 수십 가지 언어가 존재하며, 각 언어는 특정 목적에 최적화되어 있다.

개발자가 코드를 작성하면 인터프리터 또는 컴파일러가 이를 기계어로 번역하고, 컴퓨터가 인식해 실행한다.

Code 작성 → 인터프리터 / 컴파일러 → 기계어 번역 → 컴퓨터 인식

프로그래밍 언어는 기계와 얼마나 가까운지에 따라 두 종류로 나뉜다.

  • Low-level Language: 기계와 직접적으로 더 가까운 언어 (ex. C, Assembly). 속도는 빠르지만 작성이 어렵다.
  • High-level Language: 사람이 읽기 편한 언어 (ex. Python, JavaScript). 상대적으로 작성이 쉽고 실수하기 적다.

클라이언트와 서버 — Front-end와 Back-end#

프로그래밍의 세계는 크게 클라이언트(Client) 와 서버(Server) 로 나뉜다.

구분역할대응 개념
클라이언트사용자가 보는 화면Front-end
서버데이터 처리·저장Back-end

배달앱을 예로 들면, 앱 화면이 클라이언트(프론트엔드)이고, 주문 처리 및 음식점 연결이 서버(백엔드)다.

운영체제 — 컨트롤이 다른 이유#

운영체제(OS, Operating System) 는 컴퓨팅 기계를 쉽게 다루기 위한 시스템 소프트웨어다.
같은 앱이라도 iOS와 Android에서 느낌이 다른 이유가 바로 운영체제가 다르기 때문이다.

  • 데스크탑: Windows, macOS, Linux
  • 모바일: iOS (아이폰), Android (안드로이드)

운영체제는 하드웨어에 접근할 수 있는 코드를 개발자에게 제공한다. 예를 들어 카메라 앱을 만들 때, iOS와 Android는 카메라에 접근하는 코드가 서로 달라 운영체제별로 따로 개발해야 한다.

02 · 앱/웹 서비스를 위한 모든 것#

웹/앱 서비스의 구조#

디지털 명함 앱을 예로 들면, 서비스의 흐름은 다음과 같다.

명함 촬영 → 명함 사진 정보 전송 → DB 직접 입력 → 디지털 명함 생성

이처럼 모든 서비스는 사용자 행동 → 데이터 전송 → 서버 처리 → 결과 반환 의 흐름으로 동작한다.

HTTP — 웹 주소의 시작#

우리가 사용하는 웹 주소 앞에 붙는 http:// 또는 https://는 통신 규약(Protocol) 이다.

HTTP = HyperText Transfer Protocol

글자의미
HHyper
TText
TTransfer
PProtocol

HTTP가 특별한 이유는 기기, 운영체제, 웹 브라우저에 상관없이 누구나 같은 방식으로 통신할 수 있다는 것이다. 통신의 기본 원칙은 1요청, 1응답이다.

HTTP로 주고받는 데이터 형식:

  • JSON: {"id": 1, "name": "홍길동"} — 현재 가장 널리 쓰이는 형식
  • XML: <NAME>홍길동</NAME> — 예전부터 사용된 형식

Front-end의 주요 특징#

프론트엔드는 사용자가 서비스에서 처음 만나는 화면이다.

  1. UI/UX — 화면과 사용자 경험 구성
  2. 독립적인 기능들 — 서버 없이도 동작하는 기능 (카메라 촬영 등)
  3. 서버에 요청하기 위한 통신 기능
  4. Analytics — 사용자 패턴 분석

프론트엔드에서 서버와 통신할 때 쓰는 HTTP 함수들:

함수기능예시
GET정보를 읽어온다상품 목록 불러오기
POST새 정보를 서버에 전달회원가입, 주문하기
PUT / PATCH기존 정보를 수정비밀번호 변경
DELETE정보를 삭제계정 탈퇴

동기(Synchronous)와 비동기(Asynchronous)#

  • 동기: 요청한 작업이 완료될 때까지 기다린 후 다음 작업을 수행
  • 비동기: 요청을 보내놓고 기다리지 않고 다음 작업을 수행, 응답이 오면 그때 처리

웹에서 페이지를 새로고침하지 않고 데이터가 바뀌는 것(예: 카카오톡 새 메시지)이 비동기 처리 덕분이다.

Back-end와 API#

백엔드는 서버 측의 동작 코드, 비즈니스 로직(Business Logic)을 처리하는 영역이다. 사용자가 직접 보지 못하지만, 서비스의 핵심 기능(로그인 처리, 결제, 데이터 저장 등)이 모두 여기서 일어난다.

03 · 데이터베이스와 REST API#

데이터베이스란?#

데이터베이스(Database, DB) 는 데이터를 체계적으로 저장하고 관리하는 시스템이다.

우리 일상 곳곳에 데이터베이스가 쓰인다.

  • 은행 통장의 입출금 기록
  • 도서관에서 도서를 검색할 때
  • 쇼핑몰의 상품 목록과 재고 관리

데이터베이스의 구조 — 테이블#

데이터베이스는 테이블(Table) 형태로 데이터를 저장한다. 엑셀의 표처럼 행(Row)과 열(Column)로 구성된다.

상품번호상품종류가격매진
1상의50,000False
2청바지80,000False
3신발70,000True
4벨트10,000False

데이터베이스의 기본 기능 — CRUD#

모든 데이터베이스의 핵심 기능은 4가지다. 앞 글자를 따서 CRUD 라고 부른다.

  • Create (저장) — 새 데이터 추가
  • Read (검색) — 원하는 데이터 조회
  • Update (수정) — 기존 데이터 변경
  • Delete (삭제) — 데이터 제거

서버 오류의 주요 원인#

  1. 트래픽 과부하 — 너무 많은 요청이 한꺼번에 몰릴 때 (수강신청, 티켓팅)
  2. 백엔드 코드의 버그 — 잘못된 코드로 인한 오작동
  3. 데이터베이스 접속 오류 — DB 연결 실패

API — Application Programming Interface#

API는 프로그램과 프로그램이 서로 소통하는 인터페이스다.

레스토랑으로 비유하면, 손님(앱)이 웨이터(API)에게 주문하면, 웨이터가 주방(서버/DB)에 전달하고 결과를 가져오는 구조다.

쇼핑몰 로그인 API 예시
Endpoint: shoppingmall.com/login
방식: 아이디/비밀번호를 POST 방식으로 전송
처리: 서버가 DB에서 확인 후 로그인 성공/실패 응답

데이터베이스의 종류#

종류예시특징
관계형 DB (RDB)MySQL, PostgreSQL표 형태, 정형 데이터에 강함
비관계형 DB (NoSQL)MongoDB, Redis유연한 구조, 대용량 데이터에 강함

04 · 라이브러리와 프레임워크#

웹의 역사#

초기 웹은 단순했다. 웹 브라우저와 웹 서버가 HTML 파일을 주고받는 정적인 구조였다. 1998년과 2008년의 네이버만 비교해도 웹이 얼마나 빠르게 발전했는지 알 수 있다.

웹은 크게 3가지 언어로 구성된다.

  • HTML: 화면의 구조와 내용 (뼈대)
  • CSS: 색상, 폰트, 레이아웃 등 디자인 (피부)
  • JavaScript: 버튼 클릭, 애니메이션 등 동작 (근육)

라이브러리(Library)#

코드를 반복해서 작성하다 보면 자주 쓰는 기능 패턴이 생긴다. 이걸 함수로 묶어 재사용할 수 있게 만든 것이 라이브러리다.

마트에서 파는 밀키트처럼, 직접 재료를 다 준비하지 않아도 필요한 것만 꺼내서 쓰면 된다.

예시: passport.js — 로그인, 회원가입 관리를 쉽게 도와주는 라이브러리. 카카오·네이버 소셜 로그인도 간단하게 구현 가능하다.

라이브러리를 활용하면 프로젝트의 생산성 향상과 효율성 증진이 가능하다. 처음부터 모든 코드를 짤 필요가 없다.

프레임워크(Framework)#

프레임워크는 빵틀처럼 코드를 작성하기 위한 구조(틀)를 제시한다.

구분비유특징
라이브러리공구 세트내가 필요할 때 가져다 씀
프레임워크건물 골조구조가 이미 정해져 있고, 그 안에서 개발

대표 프레임워크 예시

분야프레임워크
Front-endReact, Vue, Angular
Back-end (Python)Django, FastAPI, Flask
Back-end (Node.js)Express, NestJS
모바일Flutter, React Native

05 · 검색엔진 최적화 SEO#

SEO란?#

SEO(Search Engine Optimization) 는 검색엔진에서 내 사이트가 상위에 노출되도록 최적화하는 작업이다. 유료 광고 없이도 검색을 통해 방문자를 늘릴 수 있다.

용어설명
색인(Indexing)모든 페이지를 색인해 내용과 위치(URL)를 분석
크롤링(Crawling)새 링크를 따라가거나 사이트맵을 통해 새 페이지를 찾는 과정
크롤러자동으로 크롤링하는 소프트웨어 (구글의 경우 Googlebot)

크롤링과 파싱#

크롤링은 웹의 정보를 자동으로 수집하는 기술이다.
파싱(Parsing) 은 수집한 HTML 데이터에서 필요한 정보만 추출하는 과정이다.

크롤링의 활용:

  • 시장가격 조사를 위한 데이터 수집
  • AI 훈련을 위한 데이터 확보 ← AI 과정에서 매우 중요!
  • 가격 비교 사이트 구축

크롤링의 이슈: 데이터의 가치가 크기 때문에 무분별한 크롤링은 법적 문제가 될 수 있다. 사이트의 이용약관을 반드시 확인해야 한다.

06 · 현업에서의 용어 노하우#

Version Control — Git#

버전 컨트롤(Version Control) 은 개발, 출시, 버그 수정 등 프로젝트의 모든 코드 변경 이력을 관리하는 방법이다. 현재 버전 컨트롤의 표준은 Git이며, 리눅스의 리누스 토발즈가 제작했다.

설탕 레시피로 비유하면 언제든 원하는 버전(1스푼, 2스푼, 3스푼)으로 되돌아갈 수 있다.

Git 기반 서비스: GitHub와 Bitbucket이 대표적.

기획과 플로우 차트#

서비스를 만들기 전에 플로우 차트(Flow Chart) 로 핵심 흐름을 시각화한다.

처음: 상품 페이지 접속 → 상품 구매 → 상품 배송
문제: 배송지 정보가 없다!
개선: 로그인 → 상품 페이지 → 구매 → 배송

오픈소스(Open Source)#

오픈소스는 프로젝트 전체 코드가 공개되어 누구나 활용할 수 있는 소스코드다. 무료로 사용 가능하지만 라이선스로 엄격하게 관리된다. 안드로이드 스마트폰도 오픈소스 운영체제 기반이다.

클라우드(Cloud)#

클라우드는 실물 서버 없이, 인터넷을 통해 서버와 소프트웨어를 활용하는 방식이다.

기존 서버클라우드
트래픽 증가 → 서버 직접 구매트래픽 증가 → 클릭 몇 번으로 증설
트래픽 감소 → 유지비 계속 발생트래픽 감소 → 즉시 축소, 비용 절감
초기 투자비용 큼사용한 만큼만 비용 지불

대표 클라우드 서비스: AWS(Amazon), GCP(Google), Azure(Microsoft)

SaaS — Software as a Service#

SaaS는 소프트웨어를 설치하지 않고 인터넷을 통해 바로 사용하는 클라우드 기반 서비스다. Google Docs, Notion, Figma, Slack, Zoom이 대표적이다. Adobe가 Figma를 28조 원에 인수하며 SaaS의 위력이 증명됐다.

📚 참고자료#

수업 내용과 함께 알아두면 좋을 IT 기초 지식을 추가로 정리했습니다.

인터넷은 어떻게 작동하나?#

IP 주소 — 인터넷 세상의 집 주소#

인터넷에 연결된 모든 기기(스마트폰, 노트북, 서버)에는 고유한 번호가 있다. 이걸 IP 주소(Internet Protocol Address) 라고 한다. 택배를 보낼 때 주소가 있어야 하듯, 인터넷에서 데이터를 주고받으려면 IP 주소가 있어야 한다.

예시 IP 주소: 192.168.0.1  또는  172.217.175.46 (구글 서버)

DNS — 인터넷 전화번호부#

구글에 접속할 때 우리는 172.217.175.46을 입력하지 않고 www.google.com을 입력한다. 어떻게 가능할까?

바로 DNS(Domain Name System) 덕분이다. DNS는 사람이 읽을 수 있는 도메인 이름을 컴퓨터가 이해하는 IP 주소로 변환해 주는 거대한 인터넷 전화번호부다.

www.google.com 입력
      ↓
DNS 서버가 IP 주소로 변환 (172.217.175.46)
      ↓
해당 서버에 접속 → 구글 화면 표시

이 모든 과정이 눈 깜짝할 사이(약 0.1초 이내)에 일어난다.

AI / 머신러닝 / 딥러닝 이해하기#

세 개념의 관계#

AI (인공지능)
 └── 머신러닝 (Machine Learning)
      └── 딥러닝 (Deep Learning)

가장 큰 개념이 AI이고, 그 안에 머신러닝, 그 안에 딥러닝이 포함된다.

AI — 인공지능#

AI(Artificial Intelligence) 는 사람처럼 생각하고 행동하는 컴퓨터 시스템을 만드는 기술 전반을 의미한다. 스팸 메일 필터, 넷플릭스 추천 알고리즘, 스마트폰 얼굴 인식, 네이버 지도 길찾기가 모두 AI다.

머신러닝 — 데이터로 학습하는 AI#

머신러닝(Machine Learning) 은 AI가 사람처럼 학습하는 방법 중 하나다. 데이터를 많이 보여줄수록 더 똑똑해진다.

강아지 훈련으로 비유하면, 수백 번 반복하면 결국 배우듯, 머신러닝도 수많은 예시 데이터를 보고 패턴을 스스로 학습한다.

딥러닝 — 뇌를 흉내 낸 AI#

딥러닝(Deep Learning) 은 인간의 뇌 신경망 구조를 모방한 인공신경망(Neural Network) 을 사용하는 머신러닝이다. 층층이 쌓인 신경망을 통해 더 복잡한 패턴을 학습할 수 있다.

구분머신러닝딥러닝
데이터 양비교적 적어도 됨대용량 데이터 필요
대표 활용가격 예측, 스팸 필터이미지 인식, 음성 인식, LLM

생성형 AI와 LLM#

생성형 AI(Generative AI) 는 기존 AI가 분류·예측에 집중했다면, 새로운 콘텐츠(글, 이미지, 코드)를 스스로 만들어낸다.

  • ChatGPT, Claude — 텍스트 생성
  • Midjourney, DALL-E — 이미지 생성
  • GitHub Copilot — 코드 자동 완성

LLM(Large Language Model) 은 엄청난 양의 텍스트 데이터로 학습한 초대형 딥러닝 모델이다. 인터넷에 존재하는 수백억 개의 문장을 읽고 학습했기 때문에, 질문에 자연스럽게 답하고 글을 쓰고 번역도 할 수 있다.

데이터와 개인정보 보호#

쿠키(Cookie)란?#

웹사이트를 방문하면 “쿠키 허용” 팝업이 뜬다. 쿠키는 웹사이트가 사용자의 브라우저에 저장하는 작은 텍스트 파일이다.

쿠키가 하는 일:

  • 로그인 상태 유지 (매번 다시 로그인 안 해도 되는 이유)
  • 장바구니 정보 기억
  • 내가 본 상품 기억 → 광고에 다시 표시
종류설명위험도
퍼스트파티 쿠키내가 방문한 사이트가 직접 저장낮음
서드파티 쿠키광고·분석 회사가 저장, 여러 사이트 이동 추적높음

개인정보 보호 체크리스트#

  • 앱 설치 시 불필요한 권한은 거부
  • 중요 계정은 2단계 인증 설정
  • 공용 Wi-Fi에서 중요 정보 입력 금지
  • 비밀번호는 사이트마다 다르게 설정
  • 주소창의 🔒 자물쇠(HTTPS) 확인 — 없으면 개인정보 입력 금지

HTTPS vs HTTP#

구분설명
https://데이터가 암호화되어 전송됨 (안전)
http://데이터가 평문으로 전송됨 (위험)

개인정보와 AI#

  • ChatGPT 등 AI에 민감한 개인정보(주민번호, 비밀번호 등)를 입력하지 말 것
  • AI가 생성한 내용이 사실과 다를 수 있음 (할루시네이션 현상)
  • 딥페이크 등 생성형 AI의 악용 사례 인지 필요

마무리#

컴퓨터는 0과 1로 동작하고, 개발자는 프로그래밍 언어로 그 기계와 대화하며,
그 결과물이 우리가 매일 사용하는 앱과 웹 서비스다.
그리고 AI는 그 위에서 데이터를 학습해 더 똑똑해지고 있다.

IT 리터러시는 개발자가 되기 위한 공부가 아니라, 디지털 세상을 이해하기 위한 언어를 배우는 것이다.
