📖 수업 내용#

01 · 운영체제 소개#

운영체제(OS, Operating System)는 하드웨어 리소스를 제어하고 프로그램이 실행될 수 있도록 관리하는 시스템 소프트웨어다. 우리가 앱을 클릭하면 OS가 CPU·메모리·저장장치를 적절히 배분해 실행해준다.

컴퓨터를 구성하는 세 가지 하드웨어#

구성 요소역할특징
CPU (중앙처리장치)데이터를 계산·처리하는 두뇌연산 속도 매우 빠름
메모리 (RAM)CPU가 처리할 데이터와 명령어를 임시 저장주소(0, 1, 2…)로 데이터를 찾음, 휘발성 (전원 끊기면 삭제)
주변장치입력(키보드·마우스), 출력(모니터·스피커), 보조기억장치(HDD·SSD)보조기억장치는 비휘발성 (전원 꺼져도 유지)

💡 리소스(Resource) 란 CPU 시간, 메모리 공간, 저장 공간처럼 프로그램이 동작하는 데 필요한 자원 전체를 뜻한다.

02 · 프로세스#

프로그램 vs 프로세스#

📄 프로그램 (Program)
   └─ 특정 작업을 수행하는 명령어들의 모음 (파일로 저장된 상태)

▶️ 프로세스 (Process)
   └─ 프로그램이 실행된 상태 = 실행 중인 프로그램

카카오톡 앱 파일 자체는 프로그램, 더블클릭해서 화면에 켜진 카카오톡은 프로세스다.

스레드(Thread)란?#

프로세스 안에서 실행되는 흐름 단위. 하나의 프로세스에는 하나 이상의 스레드가 존재하며, 스레드들은 같은 프로세스의 메모리를 공유한다.

비교프로세스스레드
메모리독립적인 메모리를 각자 할당받음프로세스가 받은 메모리를 공유
생성 비용상대적으로 무거움가볍고 빠름

프로세스의 메모리 구조#

프로세스는 메모리 안에서 4개의 영역으로 나뉜다:

영역설명특성
CodeCPU가 실행할 명령어(컴파일된 코드) 저장읽기 전용, 정적
Data전역 변수·정적 변수·배열 저장프로그램 시작~종료까지 유지
Heap동적으로 생성되는 데이터 저장사용자가 직접 관리, 메모리 누수 위험
Stack함수 호출·지역 변수·매개변수 저장함수 호출 시 할당, 완료되면 소멸 (LIFO)

⚠️ 메모리 누수(Memory Leak): Heap에 동적으로 할당된 메모리를 해제하지 않으면 점점 메모리가 쌓여 프로그램 성능이 저하된다.

정적 할당 vs 동적 할당#

정적 할당동적 할당
시점실행 전 에 미리 할당실행 중 에 필요할 때 할당
크기미리 고정실행 중 변할 수 있음
속도빠름상대적으로 느릴 수 있음
단점사용하지 않는 메모리 낭비 가능메모리 부족 시 프로그램 멈출 수 있음

03 · 메모리#

메모리 관리란?#

“프로그램들이 잘 실행될 수 있도록 메모리를 할당하고, 해제하는 작업”

OS가 메모리를 관리하는 이유는 두 가지다:

  • 각 프로그램의 리소스(메모리 공간)를 보호해야 하기 때문
  • 여러 프로세스가 동시에 실행될 수 있도록 공간을 제공해야 하기 때문

메모리 주소#

메모리의 각 칸에는 번호(주소)가 붙어 있다:

[ 0 ][ 1 ][ 2 ][ 3 ][ 4 ][ 5 ] … 
  ↑
프로세스 A가 주소 0~2번을 할당받아 사용

고정 분할 방식과 내부 단편화#

미리 방을 고정된 크기로 나눠 놓고 배분하는 방식. 방이 4칸인데 손님이 3칸만 쓰면 → 나머지 1칸이 낭비 (이를 내부 단편화라고 부름)

가상 메모리 (Virtual Memory)#

실제 메모리(RAM)가 부족할 때, 하드 디스크 일부를 메모리처럼 사용하는 기법.

논리적 주소 (프로세스가 바라보는 주소)
        ↕ 바인딩(Binding)
물리적 주소 (실제 RAM에서의 주소)

프로세스 C처럼 메모리에 올리기엔 너무 클 때 가상 메모리 덕분에 실행 가능해진다.

스와핑 (Swapping)#

“안 쓰는 프로세스는 잠시 하드 디스크에 넣어두기”

메모리가 꽉 찼을 때, 현재 사용하지 않는 프로세스를 디스크로 내보내고(swap out), 새 프로세스를 올린다(swap in).

04 · 파일 시스템#

파일(File)이란?#

“컴퓨터에서 정보를 담는 논리적인 저장 단위”

메모리(RAM)는 휘발성이지만, 파일은 비휘발성 기억장치(HDD·SSD) 에 저장되어 전원이 꺼져도 남는다.

하드 디스크의 구조#

    ┌─────────────────────┐
    │  플래터(Platter)     │
    │  ┌─────────────┐    │
    │  │ 트랙(Track)  │← 띠 모양 영역
    │  │  ┌───┐      │    │
    │  │  │섹터│ ←── 최소 기억 단위
    │  │  └───┘      │    │
    │  └─────────────┘    │
    └─────────────────────┘

디스크 할당 방식#

방식설명특징
연속 할당파일을 연속된 블록에 저장빠르지만 단편화 발생
연결 리스트블록끼리 다음 위치를 포인터로 연결파일을 분산 저장 가능
색인 할당 (Indexed)인덱스 블록에 파일 위치들을 기록직접 접근 가능, 효율적

링크 (Link)#

리눅스에서 파일에 대한 별명(바로가기)을 만드는 개념. 파일 시스템에서 마운트(Mount)는 저장장치를 특정 디렉토리에 연결하는 작업이다.

05 · 리눅스의 세계로#

왜 리눅스를 배우나?#

목표
리눅스의 개념을 이해한다
리눅스에 대한 지식이 왜 필요한지 알아본다
리눅스 기반의 CLI 환경에 친해진다

서버·클라우드 환경의 대부분은 리눅스로 동작한다. 개발자·데이터 분석가·DevOps 모두 리눅스 기초는 필수다.

리눅스의 구조#

┌─────────────────────────────────┐
│         응용 프로그램             │
│  ┌───────────────────────────┐  │
│  │         Shell             │  │ ← 사용자 명령 입력창
│  │  ┌─────────────────────┐  │  │
│  │  │       Kernel         │  │  │ ← OS의 핵심, 하드웨어 제어
│  │  │  ┌───────────────┐  │  │  │
│  │  │  │   하드웨어      │  │  │  │
│  │  │  └───────────────┘  │  │  │
│  │  └─────────────────────┘  │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
  • Kernel: OS의 핵심. 하드웨어를 직접 제어
  • Shell: 사용자가 명령어를 입력하면 Kernel에 전달해주는 인터페이스

왜 우분투(Ubuntu)를 사용하나?#

이유설명
개인용 PC 환경에 최적화설치·사용이 편리
간결하고 쉬움리눅스 입문에 적합
많은 사용자커뮤니티·자료 풍부
약 6개월 단위로 업데이트최신 기능 빠르게 반영

06 · 리눅스 파일 시스템#

리눅스 파일 시스템의 구성#

리눅스의 모든 것은 “파일” 이다

리눅스 파일 시스템
├── Directories (디렉토리) = 폴더
└── Files (파일)

디렉토리 구조 확인#

tree 명령어로 현재 위치의 디렉토리 구조를 볼 수 있다:

$ tree
├── examples.desktop
├── 공개
├── 다운로드
├── 문서
├── 바탕화면
├── 비디오
├── 사진
├── 음악
└── 템플릿

주요 리눅스 파일 시스템 개념#

개념설명
절대경로루트(/)부터 시작하는 전체 경로 ex) /home/user/문서
상대경로현재 위치 기준의 경로 ex) ./문서
숨김 파일.으로 시작하는 파일 (.bashrc, .ssh 등)

파일 권한 (Permission)#

ls -al 명령어로 파일 권한을 확인하고, chmod로 변경할 수 있다:

$ chmod 777 파일명
# -rwxrwxrwx (소유자·그룹·기타 모두 읽기·쓰기·실행 권한)

권한 숫자 의미: r(읽기)=4, w(쓰기)=2, x(실행)=1

07 · 알고 쓰는 리눅스 명령어#

정규표현식 (Regular Expression)#

“특정 규칙을 가진 문자열 집합을 표현하는 형식”

특수 문자들은 논리적 관계를 나타내는 기호, 나머지는 일반 문자를 뜻한다.

패턴의미예시
.임의의 문자 1개a.b → acb, a1b
*앞 문자가 0번 이상 반복ab* → a, ab, abb
[0-9]숫자 중 하나[0-9]+ → 숫자 포함 문자열
^문자열 시작^010 → 010으로 시작
$문자열 끝.txt$ → .txt로 끝남

grep 명령어#

파일에서 특정 패턴을 검색:

$ grep "찾을단어" 파일명
$ grep -n "error" log.txt   # 줄 번호 포함 출력

Standard Stream (표준 스트림)#

stdin  (표준 입력)  ← 키보드 입력
stdout (표준 출력)  → 화면 출력
stderr (표준 오류)  → 오류 내용 출력

File Redirection (파일 리다이렉션)#

출력을 파일로 저장하거나, 파일을 입력으로 사용:

$ ls > output.txt     # stdout을 파일에 저장
$ cat < input.txt     # 파일을 stdin으로 사용
$ ls >> output.txt    # 기존 파일에 추가(append)

Linux Pipe ( | )#

“앞 명령의 출력을 뒷 명령의 입력으로 연결”

$ head a.txt | grep [0-9]
# a.txt의 앞부분에서 숫자가 포함된 줄만 출력

$ ps -aux | grep nginx
# 실행 중인 프로세스 중 nginx만 찾기

파이프로 명령어들을 조합하면 복잡한 작업을 간단하게 수행할 수 있다.

08 · 프로세스와 네트워크#

리눅스에서의 프로세스 특징#

특징설명
1개 이상의 프로세스모든 프로그램은 실행 시 하나 이상의 프로세스를 가짐
병행 실행여러 프로세스가 동시에 실행 가능
부모/자식 관계프로세스는 다른 프로세스를 자식으로 생성 가능
커널 관리모든 프로세스는 커널에 의해 관리됨
PID프로세스마다 식별을 위한 고유 ID가 부여됨
소유자모든 프로세스에는 실행한 사용자(소유자)가 있음

프로세스 관련 명령어#

# 실행 중인 모든 프로세스 보기
$ ps -aux
USER   PID  %CPU  %MEM   COMMAND
root     1   0.0   0.2   /sbin/init
root     2   0.0   0.0   [kthreadd]

# 특정 프로세스 강제 종료
$ kill -9 [PID]

# 실시간 프로세스 모니터링
$ top

Job 관리#

$ command &      # 백그라운드에서 실행
$ jobs           # 현재 job 목록 확인
$ fg %1          # 백그라운드 job을 포그라운드로 가져오기
$ bg %1          # 멈춘 job을 백그라운드로 보내기

at과 cron — 예약 작업#

at: 특정 시간에 한 번만 실행

$ at 9:00 AM tomorrow
at> /home/user/backup.sh

cron / crontab: 반복적으로 실행되는 예약 작업

$ crontab -l      # 현재 등록된 작업 확인
$ crontab -e      # 작업 편집

# 형식: 분 시 일 월 요일 명령어
10 1 1 * *  /home/elice/test.sh     # 매월 1일 1시 10분에 실행
0,30 1 * * 0  /home/elice/backup.sh  # 매주 일요일 1시, 1시 30분에 실행

SSH — 원격 접속#

$ ssh 사용자명@서버주소
$ ssh user@192.168.0.1

SSH(Secure Shell)는 네트워크를 통해 다른 컴퓨터에 안전하게 원격 접속하는 프로토콜이다. 서버 관리나 클라우드 환경에서 필수적으로 사용된다.

운영체제#

  • 혼자 공부하는 컴퓨터구조+운영체제 — 강민철 저, 한빛미디어. 국내에서 가장 쉽게 풀어쓴 OS 입문서
  • Operating Systems: Three Easy Pieces — 무료 온라인 교재, 영문이지만 그림 설명이 풍부

리눅스#

  • Linux Journey — 리눅스 기초를 단계별로 배울 수 있는 무료 사이트
  • The Linux Command Line (무료 PDF) — CLI 명령어 완전 정복
  • Ubuntu 공식 문서 — 설치부터 활용까지 공식 튜토리얼

정규표현식#

  • regexr.com — 정규표현식을 실시간으로 테스트하고 설명을 볼 수 있는 도구
  • regex101.com — 패턴 매칭 시각화

프로세스 & 메모리 시각화#

  • OS Visualizations — 메모리 할당, 스케줄링 등을 시각적으로 볼 수 있는 도구
  • Explainshell.com — 리눅스 명령어를 붙여넣으면 각 옵션 설명을 보여줌
  • LabEx — The Shell — 브라우저에서 바로 리눅스 터미널을 실습할 수 있는 핸즈온 플랫폼 (설치 불필요)

마무리#

운영체제는 컴퓨터가 돌아가는 무대 뒤의 감독이고, 리눅스는 그 감독과 직접 대화할 수 있는 언어다. 오늘 배운 프로세스·메모리·파일 시스템·명령어는 모든 개발·서버·클라우드 환경의 공통 언어다.

운영체제를 이해한다는 건 단순히 컴퓨터 사용법을 배우는 게 아니라, 디지털 세상이 어떻게 돌아가는지 그 원리를 파악하는 것이다.
