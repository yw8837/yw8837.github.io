6/1 Git·GitHub 첫 실습 — 레포 만들고 push까지

Git·GitHub 첫 실습 — 레포 생성부터 clone, git config, add/commit/push, uv 가상환경 실행과 trampoline 에러 해결까지 초보자 눈높이로 정리했습니다

오늘은 코드를 GitHub에 올리는 첫 실습을 했습니다. 레포(저장소)를 만들고 → 내 컴퓨터로 가져와(clone) → 내 정보를 등록하고(config) → 변경사항을 올리는(add·commit·push) 한 흐름을 그대로 따라가 봅니다. 마지막에는 실습 중 자주 만나는 uv 실행 에러 해결법까지 정리했어요. 🐙

📌 git이 왜 필요하죠? git은 코드의 변경 이력을 저장하고 되돌릴 수 있게 해주는 도구이고, GitHub은 그 코드를 온라인에 보관·공유하는 공간입니다. “코드용 구글 드라이브 + 무한 되돌리기"라고 생각하면 쉬워요. git이 왜 필요한지에 대한 개념은 5/26 IT 리터러시에서 먼저 다뤘습니다.

📖 실습 내용#

01 · GitHub 레포(저장소) 만들기#

코드를 올려둘 창고부터 만듭니다. GitHub에 로그인한 뒤 진행하세요.

  1. 내 프로필 → Repositories → New 클릭
  2. 레포 이름 입력 (예: yeardream-practice)
  3. .gitignore: Python 선택 — 파이썬 프로젝트에서 굳이 올릴 필요 없는 파일(캐시 등)을 자동으로 제외해 줍니다
  4. License: MIT (교육·공유 목적엔 무난한 선택. 실제 회사/프로젝트에선 라이선스를 따로 검토해야 합니다)

💡 Private vs Public — 코드를 남에게 보이고 싶지 않으면 Private, 패키지처럼 공유가 목적이면 Public으로 만듭니다. 둘 중 하나를 고르면 돼요.

⚠️ 레포 이름은 본인이 정하는 예시입니다. 위 이름을 그대로 따라 쓸 필요 없어요.

02 · 내 컴퓨터로 가져오기 — git clone#

방금 만든 레포를 내 PC로 복사해 옵니다.

  1. 레포 페이지에서 Code 버튼 → HTTPS 탭 → 주소 복사
  2. 터미널(git-bash)에서 git clone 뒤에 붙여넣기
git clone https://github.com/yourname/yeardream-practice.git

💡 clone은 “온라인 레포를 통째로 내 컴퓨터에 복제한다"는 뜻입니다. 실행하면 레포 이름의 폴더가 생기고, 그 안에서 작업하게 됩니다.

작업 위치 안내

  • Windows: C: 드라이브 아래 (경로가 짧고 단순해 문제가 적어요)
  • macOS: 바탕화면(Desktop) — 터미널로 그 폴더로 이동한 뒤 clone

clone이 끝나면 그 폴더를 VS Code로 엽니다. 자동으로 안 열리면 VS Code에서 Open Folder로 직접 선택하세요.

03 · 내 정보 등록하기 — git config#

커밋(기록)에 “누가 올렸는지” 남기기 위해, 처음 한 번 내 이메일·이름을 등록합니다.

git config --global user.email "you@example.com"
git config --global user.name "Your Name"

⚠️ 가장 흔한 실수! 강사님이나 옆 사람의 이메일·이름을 그대로 따라 치지 마세요. 반드시 본인 GitHub 계정 정보로 입력해야 커밋이 내 것으로 기록됩니다.

💡 --global은 “이 컴퓨터 전체에 한 번만 등록"이라는 뜻입니다. 레포마다 다시 칠 필요 없어요.

04 · 변경사항 올리기 — add → commit → push#

코드를 GitHub에 올리는 3단계 핵심 흐름입니다. 파일을 만들거나 수정한 뒤 실행하세요.

git add .                      # 변경된 파일 전부를 올릴 목록에 담기
git commit -m "my first commit"  # 담은 내용을 하나의 기록으로 확정
git push                       # 확정한 기록을 GitHub에 업로드

🔍 한 줄씩 뜯어보기

  • git add . → 바뀐 파일들을 “이번에 올릴 것” 목록(스테이징)에 추가. .은 “현재 폴더 전부”
  • git commit -m "..." → 그 목록을 하나의 저장 지점으로 기록. -m 뒤 따옴표 안에 무엇을 바꿨는지 메모를 씁니다
  • git push → 로컬에 쌓인 커밋을 GitHub(온라인)로 전송

💡 add는 “장바구니 담기”, commit은 “주문 확정”, push는 “배송 보내기"로 비유하면 순서가 외워집니다.

잘 됐는지 확인하기#

  • GitHub 레포 페이지를 새로고침 → 방금 커밋한 내용·메시지가 보이면 성공
  • 터미널 출력에 빨간 에러·경고 없이 main 브랜치로 push가 끝났는지 확인

💡 에러가 나면? 개인 환경에서 생기는 오류는 원인이 제각각이라 한 번에 못 잡을 수 있어요. ① 에러 메시지를 검색하거나 도움을 요청해 해결을 시도하고, ② 그래도 안 풀리면 레포를 새로 만들어 처음부터 다시 진행하는 것도 방법입니다.

05 · uv 가상환경에서 실습 실행하기#

clone 받은 프로젝트에서 파이썬 실습을 돌리려면, uv로 가상환경을 맞추고 JupyterLab을 실행합니다.

uv sync                  # pyproject.toml 기준으로 패키지 설치 (가상환경 .venv 생성)
uv run jupyter lab       # 가상환경 안에서 JupyterLab 실행

📌 uv 설치와 기본 사용법은 따로 정리해 뒀어요. uv가 무엇인지, 설치·uv sync·라이브러리 확인 방법은 5/29 개발 환경 설정 (uv)에서 자세히 다룹니다. 여기서는 git 실습 흐름에 필요한 만큼만 짚었습니다.

06 · ⚠️ 트러블슈팅 — uv trampoline 에러#

uv run 을 했을 때 아래 같은 에러가 나는 경우가 있습니다.

error: uv trampoline failed to canonicalize script path

가상환경(.venv)이 꼬였을 때 나타나는 에러인데, git-bash에서 아래 4단계를 순서대로 실행하면 대부분 해결됩니다.

rm -rf .venv          # 1) 꼬인 가상환경 폴더 통째로 삭제
uv cache clean        # 2) uv 캐시 비우기
uv sync               # 3) 가상환경 새로 만들고 패키지 재설치
uv run jupyter lab    # 4) 다시 JupyterLab 실행

🔍 왜 이렇게 하나요? 망가진 .venv를 지우고(rm -rf .venv) → 잘못 저장된 캐시까지 비운(uv cache clean) 뒤 → 깨끗한 상태에서 다시 환경을 만드는(uv sync) 순서입니다. “껐다 켜기"의 환경 버전이라고 보면 돼요.

💡 그래도 로컬 실행이 계속 막히면, 실습 자체는 Google Colab으로 먼저 진행하고 로컬 환경은 나중에 점검해도 됩니다. (Colab 사용법은 5/29 개발 환경 설정 8번 참고)

📚 보충 — 자주 쓰는 git 명령#

명령역할
git clone <주소>온라인 레포를 내 PC로 복제
git config --global user.name/email커밋에 남길 내 정보 등록 (최초 1회)
git add .변경 파일을 올릴 목록에 담기
git commit -m "메모"담은 내용을 하나의 기록으로 확정
git push확정한 기록을 GitHub에 업로드

마무리#

레포 생성 → clone → config → add·commit·push. 이 한 흐름이 앞으로 모든 코드를 GitHub에 올리는 기본기입니다.

처음엔 명령어가 낯설지만, 며칠만 반복하면 손에 붙습니다. GitHub 세팅과 개발환경은 목요일 패키지 제작 실습의 토대가 되니, 매일 한 번씩 직접 쳐보며 익혀 두세요. 💪
