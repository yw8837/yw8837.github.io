🧰 0. 시작 전 준비 — VS Code 설치와 개발환경 셋업#

명령어를 치기 전에, 먼저 글을 쓰고 터미널을 띄울 도구부터 갖춰야 합니다. 오늘 수업의 1교시는 사실상 이 환경설정이 핵심이었어요. 한 번만 제대로 해두면 앞으로 계속 편합니다.

① VS Code 설치 — PATH 체크가 핵심#

code.visualstudio.com/Download 에서 내려받아 설치합니다. 설치 화면에서 반드시 체크해야 하는 옵션이 하나 있습니다.

✅ “PATH에 추가” 옵션을 꼭 체크하세요!
이걸 체크해야 나중에 터미널에서 code . 같은 명령으로 VS Code를 열 수 있습니다. (설치는 가급적 관리자 권한으로 실행하면 권한 문제를 줄일 수 있습니다.)

② PATH(환경변수)가 뭐길래?#

PATH는 컴퓨터에게 “명령어를 입력하면 이 폴더들에서 프로그램을 찾아 실행해” 라고 알려주는 일종의 주소록입니다.

  • PATH에 VS Code가 등록돼 있으면 → 터미널에 code 만 쳐도 실행됨
  • 등록이 안 돼 있으면 → command not found (그런 명령 없음) 에러

수업에서는 강사님이 일부러 PATH에서 항목을 지워서 code 명령이 안 먹히는 상태를 보여준 뒤, 다시 추가해 복구하는 시연을 했습니다.

⚠️ PATH를 새로 추가했는데도 바로 안 먹힐 때가 있습니다. 이럴 땐 터미널(또는 컴퓨터)을 재시작하면 반영됩니다.
Windows에서 직접 확인하려면: “시스템 환경변수” 검색 → Path 선택 → “편집” 으로 들어가면 됩니다.

③ 작업 폴더 열고 터미널 연동하기#

# 1) 바탕화면에 작업 폴더 만들기 (탐색기에서 만들어도 됨)
#    수업 기준 폴더 이름: 0528

# 2) 그 폴더에서 우클릭 → "Open Git Bash here" 로 터미널 열기

# 3) 터미널에서 현재 폴더를 VS Code로 열기
$ code .
  • code . 에서 . 은 “지금 이 폴더” 라는 뜻입니다. 즉 “현재 폴더를 VS Code로 열어줘” 라는 명령이에요.
  • 정상이면 VS Code 좌측 탐색기에 0528 폴더가 뜹니다. (안 뜨면 ② PATH 설정을 다시 확인)

④ VS Code 안에서 터미널 띄우기 (Git Bash 연동)#

VS Code 밖에서 터미널을 따로 열 필요 없이, VS Code 안에서 바로 띄울 수 있습니다.

  • 상단 메뉴 Terminal → New Terminal
  • 터미널 프로파일에서 Git Bash 선택 (Windows 기준 / macOS는 기본 bash·zsh 사용)

⑤ 자동 저장 켜기 — 저장 깜빡 방지#

Settings → Files: Auto Save → afterDelay

이렇게 설정하면 잠깐 멈추는 순간 자동으로 저장돼서, Ctrl+S 를 깜빡해도 작업이 날아가지 않습니다.

🗺️ 시작 전에 — 경로(Path)가 뭔지 딱 한 번만 짚고 가자#

리눅스를 처음 다루면 가장 먼저 헷갈리는 개념이 경로입니다.

경로란 파일이나 폴더가 어디에 있는지 알려주는 주소예요.
윈도우로 치면 C:\Users\최용우\Desktop\0528 이런 것처럼, 리눅스도 폴더가 깊이 중첩된 구조로 되어 있습니다.

표현뜻
/컴퓨터의 최상위 폴더 (뿌리)
~내 홈 폴더 (시작 지점, 예: /home/최용우)
.현재 내가 있는 폴더
..현재 폴더의 바로 위 폴더 (상위 폴더)

💡 절대 경로 vs 상대 경로

  • 절대 경로: 뿌리(/)부터 전체 주소를 다 쓰는 것 → /home/최용우/Desktop/0528
  • 상대 경로: 현재 위치 기준으로 쓰는 것 → ../Desktop (한 단계 위로 올라가서 Desktop 진입)

1. 지금 여기는 어디? 나는 누구? — 위치·계정 확인 및 이동#

탐색기를 열었을 때 “지금 내가 어느 폴더에 들어와 있지?” 를 확인하고, 다른 폴더로 이동하는 방법입니다.

📍 pwd — 내 현재 위치 확인하기#

마우스로 탐색기 상단 경로를 확인하는 것과 같습니다.
내가 있는 곳의 절대 경로(전체 주소)를 출력해 줍니다.

$ pwd
/c/Users/최용우/Desktop/0528

🙋 whoami — 지금 로그인한 사용자 확인하기#

지금 이 터미널을 누구 계정으로 쓰고 있는지 알려줍니다.

$ whoami
최용우

💡 whoami vs pwd 헷갈리지 마세요

  • whoami → “나는 누구냐” (계정/사용자 이름)
  • pwd → “나는 어디냐” (현재 폴더 경로)
    서버에 여러 사람이 접속해 일할 때, 내가 어떤 계정으로 작업 중인지 확인하는 용도로 자주 씁니다.

🏃 cd — 다른 폴더로 이동하기 (Change Directory)#

원하는 폴더로 들어가는 명령어입니다.

# 바탕화면으로 이동
$ cd ~/Desktop

# 작업 폴더로 이동
$ cd 0528

# 상위 폴더로 이동 (탐색기의 '뒤로 가기' 버튼)
$ cd ..

# 홈 폴더로 바로 이동
$ cd ~

💡 .. 은 ‘한 단계 위 폴더’를 뜻합니다. 탐색기의 뒤로 가기와 동일해요.

👀 ls — 현재 폴더 내용물 보기 (List)#

현재 폴더 안에 어떤 파일과 폴더가 있는지 목록을 보여줍니다.

# 기본 목록 보기
$ ls

# 숨김 파일 포함 + 날짜·용량 등 상세 정보까지 보기
$ ls -al

💡 -al 에서 -a는 숨김 파일 포함(all), -l은 상세 정보(long) 입니다. 붙여서 -al 로 씁니다.

🔑 수업 강사님 강조 습관: 파일을 만들거나·복사·이동·삭제한 직후엔 항상 ls 로 결과를 확인하세요. “내 명령이 진짜 먹혔나?“를 눈으로 바로 확인하는 게 실수를 줄이는 가장 좋은 버릇입니다.

2. 폴더(디렉터리) 만들기#

윈도우에서 우클릭 → ‘새 폴더’를 만드는 작업을 터미널에서 하는 방법입니다.

📁 mkdir — 새 폴더 만들기 (Make Directory)#

# 현재 위치에 'linux_practice' 폴더 만들기
$ mkdir linux_practice

💡 응용 (-p 옵션) — 폴더 안에 폴더를 한 번에 여러 단계로 만들고 싶을 때

$ mkdir -p linux_practice/src/utils

위 명령 한 줄이면 아래 구조가 한 번에 만들어집니다.

linux_practice/
└── src/
    └── utils/

3. 파일 만들기 및 내용 확인#

메모장을 열고 글을 써서 저장하는 과정을 터미널에서 하는 방법입니다.

📄 touch — 빈 파일 만들기#

우클릭 → ‘새 텍스트 문서’를 만드는 것과 같습니다.

# 작업 폴더로 이동한 뒤 빈 파일 생성
$ cd ~/Desktop/0528
$ touch hello.txt

✏️ echo — 파일에 내용 쓰기#

파일을 열지 않고도 터미널에서 바로 내용을 밀어 넣을 수 있습니다.

# hello.txt에 "hello, linux!" 쓰기 (덮어쓰기)
$ echo "hello, linux!" > hello.txt

# 기존 내용 아래에 한 줄 추가하기 (이어쓰기)
$ echo "두 번째 줄 추가" >> hello.txt

⚠️ 주의!
> 는 기존 내용을 싹 지우고 덮어씁니다.
>> 는 기존 내용 아래에 안전하게 이어 붙입니다.
실수로 중요한 데이터를 날릴 수 있으니 가급적 >> 를 사용하세요. 특히 서버 설정 파일에 > 를 잘못 쓰면 설정이 통째로 날아가 치명적이니, 강사님이 거듭 강조한 부분입니다.

📖 cat — 파일 내용 확인하기#

파일을 더블클릭해서 내용을 확인하듯, 터미널 화면에 파일의 전체 내용을 출력합니다.

$ cat hello.txt

🛠️ vi 편집기 — 터미널 안의 메모장#

마우스 없이 키보드만으로 파일을 편집할 수 있는 리눅스 기본 편집기입니다.

  • 기획자·비전공자 → 알아두면 좋지만 필수는 아님 (학습 과부하 방지)
  • 분석가 → 옵션 (알아두면 유리)
  • 개발자 지망생 → 서버 작업에 꼭 쓰게 되니 필수 역량으로 익혀두길 강력 추천

처음엔 “어떻게 나가지?” 로 당황하기 쉬우니, 이 6가지 키만 외워두세요.

키동작
i삽입 모드 진입 — 이 모드에서 글을 쓸 수 있음
ESC일반 모드 복귀 — 글쓰기를 멈추고 명령 대기 상태로
:w저장 (Write)
:q종료 (Quit)
:wq저장 후 종료 ← 가장 많이 쓰는 콤보!
:q!저장 없이 강제 종료 ← 잘못 수정했을 때 탈출용

수업에서 한 실제 루틴 — “열기 → 입력 → 저장 → 종료”

처음엔 욕심내지 말고 이 순서를 그대로 반복해 보세요. (1교시엔 vi memo.txt 로 열고 :q! 로 나오는 것만, 오후엔 저장까지 연습했습니다.)

# 1) 파일 열기 (없으면 새로 만들어짐)
$ vi hello.txt

# 2) i 를 누른다 → 화면 맨 아래에 -- INSERT -- 표시가 뜨면 입력 모드 진입 성공!
-- INSERT --

# 3) 원하는 내용을 타이핑한다

# 4) ESC 를 눌러 일반 모드로 빠져나온다 (-- INSERT -- 사라짐)

# 5) :wq 입력 후 Enter → 저장하고 종료

💡 vi의 가장 큰 함정은 “지금 입력 모드인지 일반 모드인지” 헷갈리는 것입니다. 글이 안 써지면 당황 말고 i 를 눌러 화면 아래 -- INSERT -- 가 떴는지부터 확인하세요. 반대로 명령(:wq 등)이 안 먹히면 먼저 ESC 를 눌러 일반 모드로 나와야 합니다.

4. 파일·폴더 복사, 이동, 삭제#

👯 cp — 복사해서 붙여넣기 (Copy)#

cp [원본] [복사본] 형식으로 씁니다.

# hello.txt를 복사해서 hello_backup.txt 만들기
$ cp hello.txt hello_backup.txt
$ ls    # 복사됐는지 바로 확인!

# 폴더 전체를 통째로 복사할 때는 -r 옵션 필수
$ cp -r linux_practice/ linux_practice_backup

💡 -r 은 recursive(재귀)의 약자로, 폴더 안의 하위 파일까지 모두 복사한다는 뜻입니다. 폴더를 복사할 땐 이 옵션이 없으면 안 됩니다.

🚚 mv — 이동 / 이름 바꾸기 (Move)#

잘라내기 후 붙여넣기와 같습니다. 같은 위치에서 사용하면 이름 변경 용도로 씁니다.

# 이름 바꾸기 (hello_backup.txt → hello_copy.txt)
$ mv hello_backup.txt hello_copy.txt

# 폴더 만들고 파일 그 안으로 이동 (수업 미션 실습)
$ mkdir archive
$ mv hello_copy.txt archive
$ ls          # archive 폴더가 생기고 파일이 빠졌는지 확인
$ cd archive
$ ls          # 파일이 잘 들어왔는지 확인

💡 리눅스에서는 이동과 이름 변경이 똑같은 mv 명령으로 처리됩니다. 목적지를 폴더로 주면 이동, 새 파일명을 주면 이름 변경이 되는 거예요.

🗑️ rm — 파일·폴더 삭제하기 (Remove)#

🚨 리눅스에서 삭제한 파일은 휴지통 없이 즉시 영구 삭제됩니다!
복구가 불가능하니 항상 신중하게 사용하세요.

# 파일 삭제
$ rm archive/hello_copy.txt

# 폴더 전체 삭제 (-r 옵션)
$ rm -r archive

🚨 rm -rf — 주의해서 쓰는 강제 삭제
-r(폴더째로) + -f(묻지도 따지지도 않고 강제로) 가 합쳐진 명령어입니다.
경로를 잘못 적으면 시스템이 통째로 날아갈 수 있습니다. 반드시 경로를 두 번, 세 번 확인하고 쓰세요.

$ rm -rf 폴더이름

⚠️ 자주 만나는 함정 — “삭제가 안 돼요 (busy)”
VS Code 등에서 그 폴더를 열어둔 상태면 삭제가 막힙니다(파일이 사용 중이라 “busy” 비슷한 메시지가 뜸).
이럴 땐 그 폴더를 열고 있는 프로그램을 닫은 뒤 다시 삭제하면 됩니다. 수업 중에도 많은 분이 이걸로 막혔던 부분이에요.

5. 모르는 명령어가 생겼을 때 — 스스로 찾는 법#

리눅스 명령어는 수백 개가 넘습니다. 전부 외울 필요 없어요.
“이 명령어 옵션이 뭐가 있지?” 싶을 때 스스로 찾는 법만 알면 됩니다.

📖 --help — 빠른 사용법 확인#

모든 명령어 뒤에 --help를 붙이면 간단한 사용법이 출력됩니다.

$ ls --help
$ cp --help
$ rm --help

📚 man — 명령어 공식 설명서 보기 (Manual)#

더 자세한 설명이 필요할 때는 man 을 씁니다. q 를 누르면 빠져나올 수 있습니다.

$ man ls

💡 영어라서 어렵게 느껴질 수 있지만, 옵션 설명을 확인할 때 유용합니다.

6. sudo — 관리자 권한으로 실행하기#

리눅스를 쓰다 보면 이런 오류를 자주 만납니다.

Permission denied

권한이 없어서 막힌 거예요. 이럴 때 명령어 앞에 sudo 를 붙이면 됩니다.

# 예시: 권한이 필요한 패키지 설치
$ sudo apt install 패키지명

⚠️ sudo 는 Super User DO 의 약자로, 관리자(root) 권한으로 실행하는 명령입니다.
강력한 만큼 잘못 쓰면 시스템에 영향을 줄 수 있으니, 확실히 필요할 때만 사용하세요.
비밀번호를 물어보면 내 컴퓨터 로그인 비밀번호를 입력하면 됩니다.

7. 파일 권한(Permission) 읽기#

ls -al 을 실행하면 이런 게 보입니다.

$ ls -al
drwxr-xr-x  2 최용우 staff   64 May 28 22:10 linux_practice
-rw-r--r--  1 최용우 staff   28 May 28 22:10 hello.txt

맨 앞의 drwxr-xr-x 가 뭔지 당황스럽죠? 규칙만 알면 읽을 수 있습니다.

d  rwx  r-x  r-x
│   │    │    │
│   │    │    └── 다른 사용자(others) 권한
│   │    └─────── 그룹(group) 권한
│   └──────────── 소유자(owner) 권한
└──────────────── d = 폴더 / - = 파일
문자의미
rread — 읽기 가능
wwrite — 쓰기 가능
xexecute — 실행 가능
-해당 권한 없음

예시: -rw-r--r-- → 파일(-), 소유자는 읽기+쓰기(rw-), 나머지는 읽기만(r--)
💡 권한은 소유자 / 그룹 / 그 외 사용자 세 묶음으로 나뉜다는 것만 우선 기억하세요. (숫자 표기 644 같은 건 지금 외울 필요 없습니다.)

8. 파일에서 원하는 내용 찾기 — grep#

파일이 길어서 특정 단어가 어디 있는지 찾고 싶을 때 씁니다.
Ctrl+F 로 문서 내 검색하는 것과 같은 역할입니다.

# hello.txt 파일에서 "linux" 라는 단어가 있는 줄 찾기
$ grep "linux" hello.txt

# 대소문자 구분 없이 찾기 (-i 옵션)
$ grep -i "linux" hello.txt

# 현재 폴더의 모든 파일에서 재귀 검색 (-r 옵션)
$ grep -r "linux" .

💡 grep 은 정규표현식(패턴) 으로 더 정교하게 검색할 수도 있습니다. 복잡한 패턴은 굳이 외우지 말고 LLM(챗봇)에 “이런 걸 찾는 grep 패턴 만들어줘” 하고 물어보는 것도 좋은 방법입니다.

9. 명령어 연결하기 — | 파이프 (Pipe)#

리눅스의 강력한 기능 중 하나입니다.
| (파이프)를 쓰면 앞 명령어의 결과를 뒤 명령어의 입력으로 넘길 수 있습니다.

# ls 결과 중 "txt" 가 들어간 항목만 필터링
$ ls | grep "txt"

# 명령어 이력 중 "cd" 가 들어간 것만 보기
$ history | grep "cd"

💡 파이프는 레고 블록처럼 명령어들을 이어붙이는 개념입니다.
복잡한 작업도 간단한 명령어 조합으로 처리할 수 있어 실무에서 매우 자주 씁니다.

10. 긴 파일 앞/뒤만 보기 — head / tail#

로그 파일처럼 내용이 수천 줄인 파일을 cat 으로 열면 화면이 넘쳐버립니다.
이럴 때 앞이나 뒤 일부만 확인할 수 있습니다.

# 파일의 앞 10줄만 보기 (기본값)
$ head hello.txt

# 파일의 앞 5줄만 보기
$ head -n 5 hello.txt

# 파일의 마지막 10줄만 보기
$ tail hello.txt

# 실시간으로 새로 추가되는 내용 계속 보기 (로그 모니터링)
$ tail -f 로그파일.log

💡 tail -f 는 서버 로그를 실시간으로 확인할 때 개발자들이 가장 많이 쓰는 명령어 중 하나입니다.

11. 한 걸음 더 — 프로세스·예약작업·원격접속 (개요)#

여기부터는 수업에서 “개념만 가볍게” 짚고 넘어간 부분입니다. 지금 다 외울 필요는 없고, “이런 게 있구나” 정도로만 알아두면 나중에 서버를 다룰 때 큰 도움이 됩니다.

⚙️ ps / kill — 실행 중인 프로그램(프로세스) 다루기#

컴퓨터에서 돌아가고 있는 프로그램 하나하나를 프로세스(Process) 라고 부르고, 각 프로세스는 PID(프로세스 번호) 라는 고유 번호를 가집니다.

# 현재 실행 중인 프로세스 목록 보기 (출력은 환경마다 조금 다름)
$ ps

# PID 번호로 특정 프로세스 강제 종료
$ kill 1234

💡 프로세스는 부모-자식 관계의 계층 구조로 이어져 있습니다. 서버에서 멈춰버린(응답 없는) 프로그램을 끌 때 kill 을 자주 쓰게 됩니다.

⏰ at / cron — 작업 예약하기 (스케줄링)#

정해진 시간에 컴퓨터가 알아서 명령을 실행하게 예약할 수 있습니다.

명령용도
at한 번만 실행할 작업 예약 (예: 오늘 밤 11시에 한 번)
cron주기적으로 반복 실행할 작업 예약 (예: 매일 새벽 3시마다)

💡 예를 들어 “매일 정해진 시간에 블로그 글을 자동 업로드"하는 식의 반복 작업을 cron 으로 돌릴 수 있습니다. (백그라운드에서 알아서 돌아가게 하는 개념입니다.)

🔐 ssh — 멀리 있는 서버에 접속하기#

내 컴퓨터에서 멀리 떨어진 원격 서버에 안전하게 접속할 때 쓰는 명령입니다.

# 사용자명@서버주소 형태로 접속
$ ssh 사용자명@서버주소
  • 접속받는 원격 서버 쪽에 SSH 서버(OpenSSH 등) 가 설치·실행되어 있어야 합니다.
  • macOS·Linux는 터미널에 ssh 가 기본 내장돼 있고, Windows는 PuTTY 같은 프로그램을 써도 됩니다.

💡 우리가 앞으로 클라우드 서버에 코드를 올리거나 AI 모델을 직접 돌리려면, 결국 그 서버에 접속해야 합니다. 그 첫 관문이 바로 SSH 예요. (네트워크 강의글의 SSH 개념 부분과 함께 보면 좋습니다.)

12. 🎁 왕초보를 위한 터미널 꿀팁 4가지#

명령어를 일일이 치다 보면 오타도 나고 지치죠? 이 4가지만 손에 익히면 훨씬 편해집니다.

① Tab 키 — 자동 완성 마법 🪄

파일·폴더 이름의 앞 1~2글자만 치고 Tab 을 누르면 리눅스가 나머지를 자동으로 완성해 줍니다.
이름이 길어서 오타 걱정이 될 때 최고의 친구입니다.

$ cd 05[Tab] → cd 0528  # 자동 완성!

② ↑ ↓ 방향키 — 이전 명령어 불러오기 ⏪

이전에 입력했던 명령어를 다시 쓰고 싶을 때, ↑ 화살표를 누르면 하나씩 불러옵니다.
오타가 났을 때 처음부터 다시 타이핑하지 말고, ↑ 로 불러와서 틀린 부분만 수정하세요.

③ history — 내가 입력한 명령어 전체 목록 📜

“아까 내가 뭐라고 쳤더라?” 싶을 때 입력하면 번호와 함께 전체 이력이 나옵니다.

$ history

④ Ctrl + L — 화면 청소 🧹

연습하다 보면 화면이 꽉 차서 어지러울 때가 있습니다.
Ctrl + L 을 누르면 0.1초 만에 화면이 깨끗해집니다. (clear 명령어와 동일)

💡 터미널 입력 함정: 예시의 $ 는 “여기부터 명령어"라는 표시(프롬프트)일 뿐, 직접 타이핑하는 글자가 아닙니다. $ 뒤의 명령어만 입력하세요. 또 명령어는 문서(편집기)가 아니라 터미널 창에 쳐야 실행됩니다.

🗂️ 실습 정리 꿀팁 — 마크다운으로 적고 Notion에 모으기#

오늘 친 명령어와 그 결과를 마크다운 파일(linux_tutorial_01.md) 하나에 명령어 + 결과를 함께 적어두세요. 그러면 그대로 나만의 복습 자료가 됩니다.

  1. VS Code에서 linux_tutorial_01.md 에 명령어와 결과를 정리한다. (코드는 ```bash 블록으로 감싸면 깔끔)
  2. Notion에서 가져오기(Import) 기능으로 이 .md 파일을 불러오면, 제목·코드블록이 자동으로 구조화됩니다.
  3. 날짜별로 계속 쌓으면 → 나만의 학습 아카이브 완성.

💡 마크다운은 LLM 시대의 사실상 문서 표준입니다. 프로젝트를 끝낼 때 README.md 형태로 정리해 GitHub에 올리면 온라인에서 깔끔하게 렌더링되니, 지금부터 마크다운으로 기록하는 습관을 들여두면 좋습니다.
