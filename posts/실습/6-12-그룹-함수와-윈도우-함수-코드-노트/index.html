01 · 이탈고객 분석 (워밍업) — classicmodels#

① 한 줄 설명 — 어제 배운 서브쿼리·JOIN의 실전 응용. 고객별 마지막 주문일과 기준일의 날짜 차이로 “떠난 고객"을 골라낸다.

② 코드 (출처: 노션 Day04-answers [답5] — ✅ 실제 답지)

SELECT
    c.customerName,
    c.country,
    MAX(o.orderDate) AS LastOrderDate,
    CAST(
        julianday('2005-05-31') - julianday(MAX(o.orderDate))
    AS INTEGER) AS DaysSinceLastOrder
FROM customers c
INNER JOIN orders o ON c.customerNumber = o.customerNumber
GROUP BY c.customerNumber, c.customerName, c.country
HAVING MAX(o.orderDate) < '2005-01-01'
ORDER BY DaysSinceLastOrder DESC
LIMIT 15;

③ 출력 결과 — 2005년 들어 한 번도 주문하지 않은(이탈 후보) 고객의 이름·국가·마지막 주문일·경과 일수가 오래된 순으로 최대 15건.

④ 한 줄씩 뜯어보기

  • MAX(o.orderDate) : 고객별 가장 최근 주문일.
  • julianday('2005-05-31') - julianday(MAX(...)) : 기준일(주문 데이터의 마지막 날)과의 일수 차이. julianday가 날짜를 숫자로 바꿔 빼기를 가능하게 한다.
  • HAVING MAX(o.orderDate) < '2005-01-01' : 그룹 집계 결과에 거는 조건 → 2005년 이후 주문이 없는 고객만 남긴다(WHERE가 아니라 HAVING).

⑤ 💡 팁 — 강사님은 이어서 약 60줄짜리 종합 쿼리(셀프조인+EXISTS+인라인뷰로 같은 국가 안에서 상대 비교해 “진짜 이탈자"를 거르는 버전, Day04-answers [답6])도 보여줬다. “풀라는 문제가 아니라 현업 쿼리의 복잡도를 체감하라"는 취지. 전체 코드는 원본 답지 참조.

02 · 순위 함수 RANK / DENSE_RANK / ROW_NUMBER — chinook#

① 한 줄 설명 — 고객별 총구매액을 집계한 뒤, 그 위에 세 가지 순위 컬럼을 얹어 동률 처리 차이를 본다.

② 코드 (출처: Day05_lecture_chinook.sql [문제1] — ✅ 실제 답지)

SELECT
    c.CustomerId,
    c.FirstName || ' ' || c.LastName  AS CustomerName,
    c.Country,
    ROUND(SUM(i.Total), 2)            AS TotalPurchase,
    RANK()       OVER (ORDER BY SUM(i.Total) DESC) AS Rank,
    DENSE_RANK() OVER (ORDER BY SUM(i.Total) DESC) AS DenseRank,
    ROW_NUMBER() OVER (ORDER BY SUM(i.Total) DESC) AS RowNumber
FROM   customers c
JOIN   invoices  i ON c.CustomerId = i.CustomerId
GROUP BY c.CustomerId, c.FirstName, c.LastName, c.Country
ORDER BY TotalPurchase DESC
LIMIT 10;

③ 출력 결과 — 구매액 상위 10고객. 동률이 있으면 Rank는 다음 순위를 건너뛰고(…3,3,5), DenseRank는 건너뛰지 않으며(…3,3,4), RowNumber는 동률이어도 고유 번호(…3,4,5).

④ 한 줄씩 뜯어보기

  • GROUP BY c.CustomerId, ... : 먼저 고객별 구매액을 집계.
  • RANK() OVER (ORDER BY SUM(i.Total) DESC) : 그 집계 결과를 구매액 내림차순으로 줄 세워 순위 부여. SUM()을 OVER 안에서도 그대로 쓸 수 있다.
  • 세 함수의 차이는 동률 처리뿐 — ORDER BY 기준은 셋 다 동일.

⑤ 💡 팁 — 강사님 핵심 패턴 — “GROUP BY로 집계 결과를 만든 뒤, 그 위에 순위 컬럼만 얹는다.” 외우는 법: RANK=건너뜀, DENSE_RANK=촘촘, ROW_NUMBER=무조건 줄번호.

03 · PARTITION BY — 국가별 순위 — chinook#

① 한 줄 설명 — 전체가 아니라 국가별로 순위를 다시 매긴다(칸막이 치기).

② 코드 (출처: Day05_lecture_chinook.sql [문제2] — ✅ 실제 답지)

SELECT
    c.Country,
    c.FirstName || ' ' || c.LastName  AS CustomerName,
    ROUND(SUM(i.Total), 2)            AS TotalPurchase,
    RANK() OVER (
        PARTITION BY c.Country
        ORDER BY SUM(i.Total) DESC
    ) AS CountryRank
FROM   customers c
JOIN   invoices  i ON c.CustomerId = i.CustomerId
GROUP BY c.Country, c.CustomerId, c.FirstName, c.LastName
ORDER BY c.Country, CountryRank;

③ 출력 결과 — 국가별로 구매액 1위부터 다시 매겨진 순위. 각 국가마다 CountryRank = 1이 하나씩 등장한다.

④ 한 줄씩 뜯어보기

  • PARTITION BY c.Country : 국가별로 칸막이를 친다.
  • ORDER BY SUM(i.Total) DESC : 그 칸막이 안에서 구매액 내림차순.
  • OVER (ORDER BY ...)만 쓴 02번은 전체 기준, 여기 PARTITION BY를 더하면 국가별 기준.

⑤ 💡 팁 — PARTITION BY vs GROUP BY: GROUP BY는 국가당 한 줄로 압축, PARTITION BY는 모든 고객을 그대로 두고 “네 국가 안 순위"만 옆에 붙인다(행 수 보존).

04 · 서브쿼리 vs 윈도우 함수 — 국가 평균 — chinook#

① 한 줄 설명 — “각 청구서 옆에 그 나라 평균 청구금액"을 서브쿼리와 윈도우 함수 두 방법으로 비교(같은 결과).

② 코드 (출처: Day05_lecture_chinook.sql [문제3] — ✅ 실제 답지)

-- (A) 서브쿼리 방식 (연관 서브쿼리, 행마다 재실행)
SELECT
    i.InvoiceId,
    i.BillingCountry,
    i.Total,
    (SELECT ROUND(AVG(Total), 2)
     FROM   invoices i2
     WHERE  i2.BillingCountry = i.BillingCountry) AS CountryAvgTotal
FROM   invoices i
ORDER BY i.BillingCountry, i.Total DESC;

-- (B) 윈도우 함수 방식 (한 줄로 끝)
SELECT
    InvoiceId,
    BillingCountry,
    Total,
    ROUND(AVG(Total) OVER (PARTITION BY BillingCountry), 2) AS CountryAvgTotal
FROM   invoices
ORDER BY BillingCountry, Total DESC;

③ 출력 결과 — 두 쿼리 모두 동일: 각 청구서 옆에 그 나라의 평균 청구금액이 붙는다.

④ 한 줄씩 뜯어보기

  • (A) 서브쿼리 안 WHERE i2.BillingCountry = i.BillingCountry → 메인쿼리 참조(연관) → 행마다 다시 실행.
  • (B) AVG(Total) OVER (PARTITION BY BillingCountry) → 일반 집계함수에 OVER만 붙여 윈도우 함수로. 한 줄.

⑤ 💡 팁 — 집계함수(SUM/AVG/MAX/MIN/COUNT)도 OVER만 붙이면 윈도우 함수가 된다. “각 행 옆에 그룹 통계를 붙이고 싶다"면 서브쿼리보다 집계() OVER (PARTITION BY ...)가 짧고 빠르다.

05 · 누적합 Running Total — ROWS BETWEEN — chinook#

① 한 줄 설명 — 청구서를 날짜순으로 누적 합산. 프레임(창의 범위)에 따라 결과가 달라진다.

② 코드 (출처: Day05_lecture_chinook.sql [문제4] — ✅ 실제 답지)

SELECT
    InvoiceId,
    InvoiceDate,
    Total,
    ROUND(SUM(Total) OVER (), 2)               AS GrandTotal,
    ROUND(SUM(Total) OVER (
        ORDER BY InvoiceDate
        ROWS BETWEEN UNBOUNDED PRECEDING
             AND CURRENT ROW
    ), 2)                                      AS RunningTotal
FROM   invoices
ORDER BY InvoiceDate
LIMIT 20;

③ 출력 결과 — 날짜순으로 RunningTotal이 점점 커지는 누적합. GrandTotal은 전체합(단, ⚠ 09번 정정 참고).

④ 한 줄씩 뜯어보기

  • ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW : “맨 첫 행부터 현재 행까지” → 누적합.
  • SUM(Total) OVER () : OVER 안이 비면 전체를 하나의 창으로 본다(전체합).

⑤ 💡 팁 — 프레임을 CURRENT ROW AND UNBOUNDED FOLLOWING(현재 행~끝)으로 바꾸면 잔여합으로 값이 완전히 달라진다. 강사님이 직접 실험하며 “창의 범위 개념"을 강조한 부분. 누적합 정석 프레임은 UNBOUNDED PRECEDING AND CURRENT ROW.

06 · FIRST_VALUE / LAST_VALUE — chinook#

① 한 줄 설명 — 국가별 정렬 후 첫 값(최소)·마지막 값(최대)을 각 행 옆에 붙인다. LAST_VALUE는 프레임 명시가 필수.

② 코드 (출처: Day05_lecture_chinook.sql [문제5] — ✅ 실제 답지)

SELECT
    InvoiceId,
    BillingCountry,
    Total,
    FIRST_VALUE(Total) OVER (
        PARTITION BY BillingCountry
        ORDER BY Total ASC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS CountryMinTotal,
    LAST_VALUE(Total) OVER (
        PARTITION BY BillingCountry
        ORDER BY Total ASC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS CountryMaxTotal
FROM   invoices
ORDER BY BillingCountry, Total;

③ 출력 결과 — 각 청구서 옆에 그 나라의 최소 청구금액(CountryMinTotal)과 최대 청구금액(CountryMaxTotal)이 붙는다.

④ 한 줄씩 뜯어보기

  • ORDER BY Total ASC : 오름차순 정렬 → FIRST_VALUE=최소, LAST_VALUE=최대.
  • ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING : 창 전체를 명시. 이게 핵심.

⑤ 💡 팁 (🚨 함정) — LAST_VALUE는 프레임을 명시 안 하면 기본 프레임이 “첫 행~현재 행"이라 최대값이 아니라 현재 행 값이 나온다. 그래서 UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING으로 창 전체를 반드시 명시해야 한다. (FIRST_VALUE는 비교적 덜 민감하지만 통일성 위해 함께 명시.)

07 · LAG / LEAD — 이전·다음 행 참조 — chinook#

① 한 줄 설명 — 날짜순으로 직전·직후 청구금액을 옆 컬럼으로 가져온다. 시계열 분석의 기본기.

② 코드 (출처: Day05_lecture_chinook.sql [문제6] — ✅ 실제 답지)

SELECT
    InvoiceId,
    InvoiceDate,
    Total,
    LAG(Total,  1) OVER (ORDER BY InvoiceDate) AS PrevInvoiceTotal,
    LEAD(Total, 1) OVER (ORDER BY InvoiceDate) AS NextInvoiceTotal
FROM   invoices
ORDER BY InvoiceDate
LIMIT 20;

③ 출력 결과 — 각 청구서 옆에 직전(PrevInvoiceTotal)·직후(NextInvoiceTotal) 청구금액. 맨 첫 행은 Prev가 NULL, 맨 마지막 행은 Next가 NULL.

④ 한 줄씩 뜯어보기

  • LAG(Total, 1) : 한 행 앞의 Total. 앞이 없는 첫 행은 NULL.
  • LEAD(Total, 1) : 한 행 뒤의 Total. 뒤가 없는 마지막 행은 NULL.
  • 숫자 1은 “몇 칸 떨어진 행"인지 — LAG(Total, 2)면 두 칸 앞.

⑤ 💡 팁 — “누적/전월 대비” 키워드가 나오면 윈도우 함수(특히 LAG)를 떠올리자. 다음(자율실습 [문제7])이 바로 이 LAG로 **전월 대비 매출 증감(MoM)**을 구하는 문제다 → 08번 아래 참고 코드.

🧩 자율 실습 [문제7] MoM (출처: chinook.sql [문제7] — ✅ 실제 답지, 직접 풀이 권장)

SELECT
    strftime('%Y-%m', InvoiceDate)              AS YearMonth,
    ROUND(SUM(Total), 2)                        AS MonthlyTotal,
    LAG(ROUND(SUM(Total), 2), 1) OVER (
        ORDER BY strftime('%Y-%m', InvoiceDate)
    )                                           AS PrevMonthTotal,
    ROUND(
        SUM(Total) -
        LAG(SUM(Total), 1) OVER (ORDER BY strftime('%Y-%m', InvoiceDate))
    , 2)                                        AS MoM_Diff
FROM   invoices
GROUP BY strftime('%Y-%m', InvoiceDate)
ORDER BY YearMonth;

strftime('%Y-%m', ...)로 연-월을 뽑아 월별 집계 → LAG로 전월값을 끌어와 증감 계산. 증감액 = 이번 달 − 전월.

08 · 비율·분위 — PERCENT_RANK / CUME_DIST / NTILE — chinook#

① 한 줄 설명 — 순위 백분율(PERCENT_RANK)·누적 백분율(CUME_DIST), 그리고 N등분 그룹(NTILE)으로 데이터를 비율·등급으로 본다.

② 코드 (출처: Day05_lecture_chinook.sql [문제9]·[문제10] — ✅ 실제 답지)

-- (a) 상위 10고객 PERCENT_RANK / CUME_DIST
SELECT
    c.CustomerId,
    c.FirstName || ' ' || c.LastName  AS CustomerName,
    ROUND(SUM(i.Total), 2)            AS TotalPurchase,
    ROUND(PERCENT_RANK() OVER (ORDER BY SUM(i.Total) DESC), 4) AS PctRank,
    ROUND(CUME_DIST()    OVER (ORDER BY SUM(i.Total) DESC), 4) AS CumeDist
FROM   customers c
JOIN   invoices  i ON c.CustomerId = i.CustomerId
GROUP BY c.CustomerId, c.FirstName, c.LastName
ORDER BY TotalPurchase DESC
LIMIT 10;

-- (b) 직원 고용일 3그룹 분류 NTILE(3)
SELECT
    EmployeeId,
    FirstName || ' ' || LastName AS EmployeeName,
    Title,
    HireDate,
    NTILE(3) OVER (ORDER BY HireDate) AS HireGroup
FROM   employees
ORDER BY HireDate;

③ 출력 결과 — (a) 상위 고객의 순위 백분율(PctRank, 최고=0)과 누적 백분율(CumeDist, 0~1). (b) 직원을 고용일순으로 3등분한 그룹 번호(1·2·3).

④ 한 줄씩 뜯어보기

  • PERCENT_RANK() : 순위 백분율 [0,1], 1등이 0.
  • CUME_DIST() : 나보다 작거나 같은 행의 누적 비율 (0,1].
  • NTILE(3) OVER (ORDER BY HireDate) : 고용일순으로 줄 세운 뒤 3등분해 그룹 번호 부여.

⑤ 💡 팁 — 강사님 학습법 — 모르는 함수(NTILE 등)는 공식 문서 먼저, 안 되면 LLM. 코드 암기보다 “이 함수가 무슨 문제를 푸는지"를 이해하는 게 핵심. NTILE은 신용등급·구간 분할에 자주 쓴다.

📎 참고 — RATIO_TO_REPORT는 SQLite에 없다. 슬라이드의 RATIO_TO_REPORT(SALARY) OVER()(Oracle)는 SQLite/MariaDB에서 안 되므로 (SALARY / SUM(SALARY) OVER())로 직접 나눠 구현한다.

09 · ⚠ GrandTotal 정정 — 국가별 매출비율 — chinook#

① 한 줄 설명 — 국가별 매출과 전체 매출 대비 비율. 이 문제에서 강사님이 출제 오류를 인정하고 정정한 부분이다.

② 코드 (원본 답지) (출처: Day05_lecture_chinook.sql [문제8] — ✅ 실제 답지, 단 GrandTotal 정정 대상)

SELECT
    BillingCountry,
    ROUND(SUM(Total), 2)                           AS CountryTotal,
    ROUND(SUM(Total) OVER (), 2)                   AS GrandTotal,      -- ⚠ 문제 부분
    ROUND(SUM(Total) / SUM(Total) OVER (), 4)      AS RevenueRatio
FROM   invoices
GROUP BY BillingCountry
ORDER BY CountryTotal DESC;

⚠ 강사 정정 (라이브 4-6교시 §4.3): GROUP BY BillingCountry로 이미 국가별로 묶인 결과 위에 SUM(Total) OVER ()를 쓰면 전체 원본 합이 아니라 의도와 다른 값이 나올 수 있다. 강사님은 이를 출제 오류로 인정하고, 전체합은 스칼라 서브쿼리 (SELECT SUM(...) FROM ...)로 따로 구해 분모로 쓰는 방법을 권장했다.

② 코드 (정정 권장형)

SELECT
    BillingCountry,
    ROUND(SUM(Total), 2)                                     AS CountryTotal,
    (SELECT ROUND(SUM(Total), 2) FROM invoices)              AS GrandTotal,
    ROUND(SUM(Total) / (SELECT SUM(Total) FROM invoices), 4) AS RevenueRatio
FROM   invoices
GROUP BY BillingCountry
ORDER BY CountryTotal DESC;

③ 출력 결과 — 국가별 매출(CountryTotal)과 전체 대비 비율(RevenueRatio). 정정형은 GrandTotal이 모든 행에서 동일한 “전체 매출 합"으로 안정적으로 나온다.

④ 한 줄씩 뜯어보기

  • 원본: SUM(Total) OVER () — GROUP BY 이후 단계에서 동작해 “국가별 합들의 집계"처럼 의도와 어긋날 수 있음.
  • 정정: (SELECT SUM(Total) FROM invoices) — 원본 테이블 전체합을 독립적으로 한 번 계산해 분모로 사용 → 명확.

⑤ 💡 팁 — 윈도우 함수로 꼭 처리하려면 인라인뷰로 감싸야 해서 복잡해진다. 비율의 분모처럼 “전체에 대한 단일 값"은 스칼라 서브쿼리가 단순하고 안전하다. “윈도우 함수가 만능은 아니다"라는 교훈. (정직 표기: 원본 답지 SQL과 강사 정정안을 모두 남겼다.)

10 · 그룹 함수 UNION 대체 — ROLLUP / CUBE / GROUPING SETS — chinook#

① 한 줄 설명 — SQLite는 ROLLUP/CUBE/GROUPING SETS를 지원하지 않으므로, 각 집계 레벨을 따로 구해 UNION/UNION ALL로 쌓아 같은 결과를 만든다.

② 코드 (출처: Day05_lecture_chinook.sql [문제12]·[문제13]·[문제14] — ✅ 실제 답지, SQLite UNION 대체)

-- [ROLLUP 대체] (장르,미디어타입) + 장르소계 + 전체  → UNION ALL
SELECT g.Name AS Genre, mt.Name AS MediaType,
       COUNT(t.TrackId) AS TrackCount, ROUND(AVG(t.UnitPrice), 2) AS AvgPrice
FROM   tracks t
JOIN   genres g ON t.GenreId = g.GenreId
JOIN   media_types mt ON t.MediaTypeId = mt.MediaTypeId
GROUP BY g.Name, mt.Name
UNION ALL
SELECT g.Name, NULL, COUNT(t.TrackId), ROUND(AVG(t.UnitPrice), 2)   -- 장르별 소계
FROM   tracks t JOIN genres g ON t.GenreId = g.GenreId
GROUP BY g.Name
UNION ALL
SELECT NULL, NULL, COUNT(TrackId), ROUND(AVG(UnitPrice), 2)         -- 전체 합계
FROM   tracks
ORDER BY Genre, MediaType;

-- [CUBE 대체] 위 ROLLUP에 '미디어타입별 소계'를 더함 → UNION
-- (조합) UNION (장르소계) UNION (미디어타입소계) UNION (전체)
SELECT NULL AS Genre, mt.Name AS MediaType,
       COUNT(t.TrackId) AS TrackCount, ROUND(AVG(t.UnitPrice), 2) AS AvgPrice
FROM   tracks t JOIN media_types mt ON t.MediaTypeId = mt.MediaTypeId
GROUP BY mt.Name;   -- ← CUBE에만 있는 '미디어타입별 소계' (ROLLUP엔 없음)

-- [GROUPING SETS 대체] 장르별 + 미디어타입별 (각각 개별) → UNION ALL
SELECT g.Name AS Genre, NULL AS MediaType,
       COUNT(t.TrackId) AS TrackCount, ROUND(AVG(t.UnitPrice), 2) AS AvgPrice
FROM   tracks t JOIN genres g ON t.GenreId = g.GenreId
GROUP BY g.Name
UNION ALL
SELECT NULL, mt.Name, COUNT(t.TrackId), ROUND(AVG(t.UnitPrice), 2)
FROM   tracks t JOIN media_types mt ON t.MediaTypeId = mt.MediaTypeId
GROUP BY mt.Name
ORDER BY Genre, MediaType;

③ 출력 결과 — ROLLUP 대체: 조합 행 + 장르별 소계(MediaType=NULL) + 전체 행(둘 다 NULL). CUBE 대체: 거기에 미디어타입별 소계까지. GROUPING SETS 대체: 장르별·미디어타입별 두 묶음.

④ 한 줄씩 뜯어보기

  • 각 집계 레벨을 별도 SELECT로 만들고, 빠진 컬럼은 NULL로 채워 컬럼 수·순서를 맞춘다(UNION 규칙).
  • UNION ALL(중복 허용, ROLLUP/GROUPING SETS) vs UNION(중복 제거, CUBE) — 레벨 간 중복 가능성에 따라 선택.
  • CUBE는 ROLLUP에 없는 **“두 번째 컬럼(미디어타입) 단독 소계”**가 핵심 차이.

⑤ 💡 팁 — 어제 배운 UNION의 실전 활용이다. “ROLLUP=소계+총계(3레벨)”, “CUBE=모든 조합(4레벨)”, “GROUPING SETS=각각 따로(2레벨)” — 의미만 잡으면 SQLite에서 그 의미대로 UNION을 쌓으면 된다. Oracle은 함수 한 줄, SQLite는 우회.

11 · 실전: 지역별 순위 + 1등 추출 — classicmodels#

① 한 줄 설명 — 5테이블 JOIN으로 영업사원 매출을 구해 지역(territory)별 순위를 매기고, 인라인뷰로 감싸 각 지역 1등만 뽑는다.

② 코드 (출처: Day05_lecture_classicmodels_lecture.sql [실전1] + 노션 Day05 변형 — ✅ 실제 답지)

-- (a) 지역별 영업사원 매출 순위
SELECT e.firstName || ' ' || e.lastName          AS SalesRep,
       off.territory,
       COUNT(DISTINCT c.customerNumber)          AS CustomerCount,
       ROUND(SUM(od.quantityOrdered * od.priceEach), 2) AS TotalSales,
       RANK() OVER (
           PARTITION BY off.territory
           ORDER BY SUM(od.quantityOrdered * od.priceEach) DESC
       )                                         AS TerritoryRank
FROM   employees   e
JOIN   offices     off ON e.officeCode = off.officeCode
JOIN   customers   c   ON e.employeeNumber = c.salesRepEmployeeNumber
JOIN   orders      o   ON c.customerNumber = o.customerNumber
JOIN   orderdetails od ON o.orderNumber = od.orderNumber
WHERE  e.jobTitle LIKE '%Sales Rep%'
  AND  o.status = 'Shipped'
GROUP BY e.employeeNumber, e.firstName, e.lastName, off.territory
ORDER BY off.territory, TerritoryRank;

-- (b) 각 지역 1등만: 인라인뷰로 감싼 뒤 WHERE rank = 1
SELECT *
FROM (
    SELECT e.firstName || ' ' || e.lastName AS SalesRep,
           off.territory,
           COUNT(DISTINCT c.customerNumber) AS CustomerCount,
           ROUND(SUM(od.quantityOrdered * od.priceEach), 2) AS TotalSales,
           RANK() OVER (
               PARTITION BY off.territory
               ORDER BY SUM(od.quantityOrdered * od.priceEach) DESC
           ) AS TerritoryRank
    FROM employees e
    JOIN offices off ON e.officeCode = off.officeCode
    JOIN customers c ON e.employeeNumber = c.salesRepEmployeeNumber
    JOIN orders o ON c.customerNumber = o.customerNumber
    JOIN orderdetails od ON o.orderNumber = od.orderNumber
    WHERE e.jobTitle LIKE '%Sales Rep%'
      AND o.status = 'Shipped'
    GROUP BY e.employeeNumber, e.firstName, e.lastName, off.territory
    ORDER BY off.territory, TerritoryRank
) a
WHERE a.TerritoryRank = 1;

③ 출력 결과 — (a) 지역(NA/EMEA/APAC)별 영업사원 매출 순위. (b) 각 지역의 1위 영업사원만 한 명씩.

④ 한 줄씩 뜯어보기

  • 5테이블 JOIN: employees→offices(지역)·customers(담당고객)→orders→orderdetails(매출).
  • WHERE e.jobTitle LIKE '%Sales Rep%' AND o.status = 'Shipped' : 영업사원 + 출하완료 주문만.
  • RANK() OVER (PARTITION BY off.territory ORDER BY 매출 DESC) : 지역별 칸막이 안 순위.
  • (b) 인라인뷰로 감싼 뒤 WHERE a.TerritoryRank = 1 : 윈도우 결과를 바깥에서 필터.

⑤ 💡 팁 (핵심 패턴) — 윈도우 함수 결과(TerritoryRank)는 SELECT와 같은 단계라 같은 레벨의 WHERE로는 못 거른다. 그래서 “각 그룹 1등"을 뽑으려면 **인라인뷰/서브쿼리로 한 겹 감싼 뒤 바깥에서 WHERE rank=1**을 거는 게 정석이다.

12 · 실전: 재주문 간격으로 이탈 탐지 — classicmodels#

① 한 줄 설명 — LAG로 고객별 직전 주문일을 끌어와 주문 간격(일수)을 구하고, 간격이 큰 고객을 이탈 위험군으로 본다. 1교시 이탈 분석과 수미상관.

② 코드 (출처: Day05_lecture_classicmodels_lecture.sql [시계열2] — ✅ 실제 답지)

SELECT customerName, country, orderDate, orderRevenue, prevOrderDate,
       CAST(
           julianday(orderDate) - julianday(prevOrderDate)
       AS INTEGER) AS DaysSincePrevOrder
FROM (
    SELECT c.customerName, c.country, o.orderDate,
           ROUND(SUM(od.quantityOrdered * od.priceEach), 2) AS orderRevenue,
           LAG(o.orderDate, 1) OVER (
               PARTITION BY c.customerNumber
               ORDER BY o.orderDate
           ) AS prevOrderDate
    FROM   customers c
    JOIN   orders o       ON c.customerNumber = o.customerNumber
    JOIN   orderdetails od ON o.orderNumber = od.orderNumber
    WHERE  o.status = 'Shipped'
    GROUP BY c.customerNumber, c.customerName, c.country, o.orderNumber, o.orderDate
) order_gap
WHERE  prevOrderDate IS NOT NULL          /* 첫 주문은 비교 대상 제외 */
ORDER BY DaysSincePrevOrder DESC
LIMIT 20;

③ 출력 결과 — 고객별 각 주문과 직전 주문 사이의 간격(일)이 큰 순으로 최대 20건. 주문 간격이 길수록 이탈 위험이 높다.

④ 한 줄씩 뜯어보기

  • LAG(o.orderDate, 1) OVER (PARTITION BY c.customerNumber ORDER BY o.orderDate) : 고객별·주문일순으로 직전 주문일.
  • julianday(orderDate) - julianday(prevOrderDate) : 두 주문 사이 간격(일). CAST(... AS INTEGER)로 정수화.
  • WHERE prevOrderDate IS NOT NULL : 첫 주문은 LAG 결과가 NULL이라 제외(인라인뷰 바깥에서 필터 — 11번 패턴과 동일 이유).

⑤ 💡 팁 — 1교시 이탈 분석이 “마지막 주문일 기준"이라면, 이건 LAG로 주문 사이 간격을 보는 또 다른 각도. 둘 다 같은 비즈니스 문제(Churn)를 다른 함수로 푸는 셈이다. LAG의 NULL(첫 주문) 처리가 실무 포인트.

마무리#

오늘 실습은 윈도우 함수의 전 계열(순위 RANK/DENSE_RANK/ROW_NUMBER, PARTITION BY, 누적합 ROWS BETWEEN, FIRST/LAST_VALUE, LAG/LEAD, PERCENT_RANK/NTILE)을 chinook으로 훑고, 그룹 함수(ROLLUP/CUBE/GROUPING SETS)는 SQLite 한계 때문에 UNION으로 우회하는 법을 익힌 뒤, classicmodels 실전(지역 순위·1등 추출·재주문 간격 이탈탐지)으로 마무리했다. 관통하는 두 메시지 — (1) 윈도우 함수는 행을 줄이지 않고 통계를 옆에 붙인다, (2) 윈도우 결과로 필터링하려면 인라인뷰로 감싼다. 그리고 전체합은 SUM() OVER()가 아니라 스칼라 서브쿼리(강사 정정), SQLite 차원집계는 UNION. 다음 주 시험은 오늘 범위(윈도우 함수) 중심이다.
