01 · ★ 심볼릭 AI 워크플로 — “모델 + 지식"을 손으로 따라 하기#

① 한 줄 설명 — 강의 핵심인 “모든 생성형 AI = 모델 + 지식” 구조를, 실제 AI 도구에서 어떻게 구현하는지 단계로 따라 한다. (코드 아님 — 도구 사용 절차)

② 워크플로

[심볼릭 AI 구조]  사용자 → 질문 → AI시스템(모델 + 지식) → 답변

내가 바꿀 수 있는 건 딱 둘:
  1) 모델   = 빅테크가 만든 것 중 "선택"   (GPT / Claude / Gemini …)
  2) 지식   = 내가 "업로드"하는 자료        (답변 품질을 결정)

[따라 하기]
  STEP 1. 도구에서 '프로젝트/Gem/프로젝트' 같은 공간을 새로 만든다.
  STEP 2. 모델을 고른다.            ← "모델"
  STEP 3. 관련 자료(PDF/문서)를 업로드한다.  ← "지식"
  STEP 4. 지침(역할·형식·톤)을 적고 저장한다.
  STEP 5. 이제 그 안에서 질문하면, 업로드한 지식을 근거로 답한다.

③ 결과(무엇이 달라지나)

일반 채팅:       두루뭉술 / 짧음 / 출처 없음
지식 업로드 후:  구체적 / 길고 전문적 / 페이지·문헌 출처 제시

④ 한 줄씩 뜯어보기

  • STEP 2(모델): 우리가 모델 자체를 만들 순 없다. 빅테크가 만든 선택지에서 고를 뿐이다.
  • STEP 3(지식): 강사님 핵심 메시지 — 무엇을 올리느냐가 답변 품질을 결정한다. 여기가 우리가 가진 가장 큰 레버다.
  • STEP 4(지침): “너는 통계 강사야, 초심자에게 설명하듯 답해” 같은 역할·형식을 미리 박아두면 매번 다시 안 써도 된다.

⑤ 💡 팁 — ChatGPT의 “프로젝트”, Claude의 “프로젝트”, Gemini의 “Gem(잼)”, Genspark의 “드라이브"가 전부 이 지식 업로드 공간이다. 도구 이름만 다를 뿐 구조는 똑같이 “모델 + 지식"이다. “AI가 답을 못 한다"의 절반은 좋은 지식을 안 줘서다.

02 · ★ 지식 업로드 비교 실습 — 일반 채팅 vs 프로젝트#

① 한 줄 설명 — 강의 D2 실습. 같은 질문을 (A) 그냥 채팅과 (B) 자료 업로드한 프로젝트에 던져 답 차이를 직접 확인한다. (도구 사용 절차)

② 절차

1) 참고자료 메뉴 → 오늘 날짜 → "생성형 예제 기초 자료" → 드라이브에서 파일 다운로드
2) 프로젝트에 파일 4개 업로드
3) 지침 입력 → 실행 → 저장 → 채팅 시작
4) 같은 질문을 '일반 채팅'에도 던져 비교

[실습 질문 예시]
  "나는 초심자야. Robust Regression(로버스트 회귀)이 뭔지 자세히 알려줘."
  (예제 데이터로는 tips 데이터 사용)

③ 관찰 결과(강의 시연)

일반 채팅        → 짧고 일반적인 설명
지식 업로드 후   → 훨씬 상세, 통계 교재의 "298페이지" 근거까지 제시
                   (단, 영어로 검색해야 매칭이 잘 됨)

④ 한 줄씩 뜯어보기

  • 비교 기준 3가지: 답변 양(길이) / 완성도·구체성 / 출처 표기 여부. 지식 업로드 쪽이 세 가지 모두에서 앞섰다.
  • 도구별 차이: 같은 지침을 Claude·ChatGPT에도 적용할 수 있지만 출력 스타일·컨텍스트 한계가 다르다. ChatGPT는 지침이 길면 일부가 잘리기도 했다.
  • 팀 협업: 한 명만 프로젝트(지식+지침)를 세팅해 공유 링크를 돌리면, 팀 전체가 같은 품질의 답을 쓸 수 있다.

⑤ 💡 팁 — 1번의 “심볼릭 AI” 개념이 여기서 눈으로 증명된다. 모델을 안 바꿔도, 지식을 바꾸면 답이 바뀐다. 질문을 다듬기 전에 “관련 자료부터 올렸나?“를 먼저 확인하자.

03 · ★ SCQA 컨설팅 리포트 작성 워크플로#

① 한 줄 설명 — 강의 E의 핵심. 바바라 민토의 SCQA로 보고서/리포트 뼈대를 잡는 작성 연습이다. 강의 실습 시나리오(로테이션 소개팅)를 그대로 따라 한다. (코드 아님 — 문서 논리 작성)

② SCQA 골격(빈칸 채우기)

[S — Situation] 모두가 동의하는, 논쟁 없는 배경 사실만.
   예) "내담자는 로테이션 소개팅에 100회 참여했고, 외모·경제력은 준수하다."

[C — Complication] S와 모순·충돌되는 문제 + "이대로면 벌어질 위기".  ← 가장 어려움
   예) "그런데 애프터 성공은 0회다. 이 패턴이 지속되면 비용·시간만 소모되고
        자신감까지 무너진다." (단순 현황 나열 ❌ / 위기까지 ⭕)

[Q — Question] C에서 자연스럽게 떠오르는 핵심 질문.
   예) "조건은 준수한데 왜 애프터로 한 번도 못 이어지나?"

[A — Answer] Q에 대한 결론(핵심 메시지). 결론부터 맨 위에.
   예) "만남을 '평가'가 아닌 '소통'으로 재설계하면 애프터 전환율이 오른다."

③ 피라미드 + MECE로 A 받치기

            [A: 만남을 '소통'으로 재설계하라]      ← 결론(피라미드 꼭대기)
           /              |              \
   [근거1] 대화 지분    [근거2] '해결사'   [근거3] 소개팅을
   7:3로 조정(경청)     태도 버리기        부정 프레임에서 전환
   └─ 서로 중복 ❌, 빠짐 없이 ⭕, 모두 결론을 향함 = MECE

④ 한 줄씩 뜯어보기

  • C가 핵심: 강사님 강조 — C를 잘 만들면 Q·A는 거의 자동으로 따라온다. C는 “문제+위기"여야 하고, 단순 현황 설명이면 실패다.
  • 구체적 맥락이 품질을 결정: 시나리오에 상담자 관점의 관찰 가설(말이 빠름, 다 해결하려는 태도 등)을 추가하면 답이 확 구체화된다. (1~2번의 “지식이 답을 결정한다"와 같은 원리.)
  • MECE 점검: 근거 3개가 서로 겹치지 않는가? 빠진 축은 없는가? 전부 결론을 향하는가?

⑤ 💡 팁 — AI에게 SCQA 리포트를 시킬 때도 출력을 그대로 쓰지 말 것. 강사님이 반복 강조한 대로, AI가 준 SCQA를 보고 S/C가 섞이지 않았는지·C에 위기가 들어갔는지 사람이 직접 수정·보완해야 한다.

04 · 자기회귀(Auto Regression) 시뮬레이션#

① 한 줄 설명 — LLM이 “다음 단어 확률 중 높은 걸 골라 이어붙이는” 자기회귀를, 강의 슬라이드 예시 확률로 흉내 낸다. (보완 예제, 순수 파이썬 — 패키지·API 불필요)

② 코드

# 보완: 강의에 코드는 없었음. A8 슬라이드 예시를 코드로 옮긴 자기회귀 시뮬레이션
# "현재 문장" → "다음 단어 후보 확률"을 표로 정의해 반복한다

step_table = {
    "Second law of robotics : a": {"Robot": 0.8, "Person": 0.16},
    "Second law of robotics : a Robot": {"must": 0.7, "can": 0.3},
    "Second law of robotics : a Robot must": {"obey": 0.9, "ignore": 0.1},
}

sentence = "Second law of robotics : a"

while sentence in step_table:                 # 표에 정의된 단계가 남아 있는 동안 반복
    probs = step_table[sentence]
    next_word = max(probs, key=probs.get)     # 확률이 가장 높은 단어 선택 (greedy)
    print(f"[현재] {sentence}  →  [선택] {next_word} ({probs[next_word]})")
    sentence = sentence + " " + next_word      # 고른 단어를 이어붙여 다음 입력으로

print(f"\n최종 생성 문장: {sentence}")

③ 출력 결과

[현재] Second law of robotics : a  →  [선택] Robot (0.8)
[현재] Second law of robotics : a Robot  →  [선택] must (0.7)
[현재] Second law of robotics : a Robot must  →  [선택] obey (0.9)

최종 생성 문장: Second law of robotics : a Robot must obey

④ 한 줄씩 뜯어보기

  • step_table : “현재 문장 → 다음 단어 확률"을 단계별로 정의. 실제로는 모델이 매 단계 실시간 계산하는 부분을 표로 대신했다.
  • max(probs, key=probs.get) : 확률값이 가장 큰 단어를 고른다. 가장 단순한 greedy(탐욕적) 디코딩.
  • sentence = sentence + " " + next_word : 고른 단어를 끝에 붙여 다음 단계의 입력으로 만든다. 이 “출력이 다시 입력이 되는” 구조가 자기회귀의 핵심.

⑤ 💡 팁 — ChatGPT가 글자를 주르륵 타이핑하듯 출력하는 게 이 반복이 실시간으로 보이는 것이다. 실제 LLM은 항상 1등만 고르지 않고 temperature 값으로 가끔 2~3등도 뽑아 다양성을 준다.

05 · 개인정보 비식별화(마스킹) — 윤리 가이드 실습#

① 한 줄 설명 — 강의 C3의 “민감정보를 AI에 넣기 전 가짜 값으로 치환"을 코드로. 정규표현식으로 전화·이메일·날짜를 마스킹한다. (보완 예제, 표준 라이브러리)

② 코드

import re

text = "연락처는 123-4567-890 이고 이메일은 asdfgh@gmail.com 입니다. 12월 15일에 만나요."

# 방법1: 플레이스홀더 치환 (강의 C3 예시 형식)
masked = text
masked = re.sub(r"\d{3}-\d{4}-\d{3}", "XXX-YYYY-ZZZZ", masked)   # 전화번호
masked = re.sub(r"[\w.]+@[\w.]+", "sample@email", masked)         # 이메일
masked = re.sub(r"\d+월 \d+일", "XX월 YY일", masked)               # 날짜

print("원본 :", text)
print("마스킹:", masked)

③ 출력 결과

원본 : 연락처는 123-4567-890 이고 이메일은 asdfgh@gmail.com 입니다. 12월 15일에 만나요.
마스킹: 연락처는 XXX-YYYY-ZZZZ 이고 이메일은 sample@email 입니다. XX월 YY일에 만나요.

④ 한 줄씩 뜯어보기

  • import re : 정규표현식(패턴 매칭) 라이브러리. 파이썬 기본 내장이라 설치 불필요.
  • re.sub(패턴, 바꿀값, 문자열) : 패턴에 맞는 부분을 찾아 바꾼다.
  • \d{3}-\d{4}-\d{3} : 숫자 3개-4개-3개 = 전화번호 패턴. [\w.]+@[\w.]+ : 이메일 패턴.

⑤ 💡 팁 — 강의에선 ② 변수형 치환([전화번호1], [이름1])도 소개됐다. 의미 없는 객체로 바꾸거나 일반화하면 AI는 맥락만 이해하고 실제 민감값은 못 본다. 핵심 원칙: 민감정보는 AI에 넣지 않거나, 넣어야 하면 반드시 가공해서 넣는다. (삼성 ChatGPT 사례가 경고한 바로 그 위험이다.)

06 · API 키 보안 — 환경변수 & .gitignore#

① 한 줄 설명 — 강의 C4의 “키 하드코딩 금지, .gitignore로 제외"를 실제 파일 구성으로. (보완 예제)

② 코드 / 파일 구성

# 나쁜 예 (절대 금지): 키를 코드에 그대로 박음 → GitHub에 올라가면 유출
client = OpenAI(api_key="sk-1234abcd_진짜키_노출됨")   # ❌

# 좋은 예: 환경변수에서 읽기
import os
client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])   # ✅

# .env 파일 (키를 따로 보관) — 이 파일은 절대 커밋하지 않는다
OPENAI_API_KEY=sk-실제키값

# .gitignore — 키 파일이 git에 올라가지 않도록 제외
.env
*.key
secrets/

③ 출력 결과 — (설정 파일이라 실행 출력 없음. git status에서 .env가 안 보이면 성공)

$ git status
On branch main
nothing to commit, working tree clean   # .env가 무시되어 안 잡힘

④ 한 줄씩 뜯어보기

  • .env : 키 같은 비밀값을 코드와 분리해 담는 파일.
  • .gitignore에 .env 추가 : git이 이 파일을 추적하지 않게 한다 → GitHub에 안 올라간다.
  • git add . 대신 git add .gitignore처럼 개별 스테이징하면 비밀 파일이 실수로 딸려 올라가는 걸 막을 수 있다(1-3교시 Git 실습 강조).

⑤ 💡 팁 — 실수로 키를 커밋·push했다면 파일만 지워선 안 된다. 이미 노출된 키는 즉시 폐기(revoke)하고 새로 발급해야 한다. git 히스토리에 영원히 남기 때문이다.

07 · (참고) API로 LLM 호출하는 기본 패턴#

① 한 줄 설명 — 강의 A7의 “API 활용” 방식. 코드로 모델을 불러 응답받는 가장 기본 패턴이다. (보완 예제 — 실행하려면 openai 패키지와 API 키 필요)

② 코드

# 보완: 강의에 코드는 없었음. OpenAI 공식 SDK의 표준 호출 패턴 예시.
# 실행 전: pip install openai  /  환경변수 OPENAI_API_KEY 설정 필요
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])   # 키는 환경변수에서 (C4 준수)

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "너는 친절한 한국어 비서야."},
        {"role": "user", "content": "생성형 AI를 한 문장으로 설명해줘."},
    ],
)

print(response.choices[0].message.content)

③ 출력 결과 (예시 — 모델 응답이라 매번 다름)

생성형 AI는 학습한 데이터의 패턴을 바탕으로 텍스트·이미지·오디오 등 새로운 콘텐츠를 만들어내는 AI입니다.

④ 한 줄씩 뜯어보기

  • os.environ["OPENAI_API_KEY"] : 키를 코드에 박지 않고 환경변수에서 꺼낸다(6번 보안 원칙).
  • messages=[...] : 대화를 역할별로 구성. system은 AI의 성격 설정, user는 사용자 질문.
  • response.choices[0].message.content : 모델이 만든 답변 텍스트가 여기 들어 있다.

⑤ 💡 팁 — Anthropic(Claude)도 패턴은 비슷하다(anthropic 패키지, client.messages.create(...)). API 방식의 장점은 내 프로그램·앱 안에 AI를 끼워 넣을 수 있다는 것 — 웹 인터페이스(방식 ①)로는 못 하는 자동화가 가능하다.

마무리#

오늘은 코드 실습이 없는 대신, “AI를 잘 쓰는 법” 자체가 실습이었다. 핵심은 두 가지로 요약된다. 첫째, 심볼릭 AI(모델+지식) — 모델은 고르고 지식은 올린다, 그리고 지식이 답의 품질을 결정한다. 둘째, SCQA·피라미드·MECE — 결론부터, 중복·누락 없이, “긴장(C)“을 제대로 잡아 논리적으로 쓴다. 마지막으로 비식별화·API 키 보안·Human in the Loop처럼, AI를 안전하게 쓰는 습관까지 손에 익혔다. 이 감각이 앞으로 실제 코드 실습과 프로젝트에서 든든한 토대가 될 것이다.
