01 · 자기회귀(Auto Regression) 시뮬레이션#

① 한 줄 설명 — LLM이 “다음 단어 확률 중 가장 높은 걸 골라 이어붙이는” 자기회귀 과정을, 강의 슬라이드의 예시 확률로 흉내 내본다. (외부 패키지·API 불필요, 순수 파이썬)

② 코드

# 강의 A8 슬라이드 예시를 그대로 코드로 옮긴 자기회귀 시뮬레이션
# 입력: "Second law of robotics : a" → 다음 단어 확률분포

next_token_probs = {
    "Robot": 0.8,
    "Person": 0.16,
    "Bird": 0.02,
    "Lion": 0.01,
}

prompt = "Second law of robotics : a"

# 가장 확률이 높은 단어를 선택 (greedy 방식)
next_token = max(next_token_probs, key=next_token_probs.get)

print(f"입력: {prompt}")
print(f"다음 단어 확률: {next_token_probs}")
print(f"선택된 단어: {next_token} (확률 {next_token_probs[next_token]})")
print(f"이어진 결과: {prompt} {next_token}")

③ 출력 결과

입력: Second law of robotics : a
다음 단어 확률: {'Robot': 0.8, 'Person': 0.16, 'Bird': 0.02, 'Lion': 0.01}
선택된 단어: Robot (확률 0.8)
이어진 결과: Second law of robotics : a Robot

④ 한 줄씩 뜯어보기

  • next_token_probs = {...} : 슬라이드에 나온 다음 단어 후보와 확률을 딕셔너리(사전)로 표현. 실제 LLM은 이 확률을 수만 개 단어에 대해 계산한다.
  • max(..., key=next_token_probs.get) : 확률값이 가장 큰 단어(Robot, 0.8)를 고른다. 이게 가장 단순한 선택 방식인 greedy(탐욕적) 디코딩.
  • 마지막 print : 고른 단어를 문장 뒤에 이어붙인다. 이 과정을 반복하면 문장이 자라난다.

⑤ 💡 팁 — 실제 LLM은 항상 1등만 고르지 않는다. temperature라는 값으로 “가끔 2~3등도 뽑게” 해서 다양성을 준다. 1등만 고르면(greedy) 매번 똑같은 답이 나오고, 무작위성을 높이면 창의적이지만 엉뚱해질 수 있다.

02 · 자기회귀 반복 — 단어가 문장이 되는 과정#

① 한 줄 설명 — 위 “한 단어 선택"을 여러 번 반복하면 문장이 생성된다는 걸, 미리 정해둔 확률표로 보여준다. (순수 파이썬)

② 코드

# 단계마다 "현재까지 문장" → "다음 단어 후보 확률"을 미리 정의한 미니 시뮬레이터
# (실제 모델 대신, 개념 이해용으로 확률표를 손으로 만들어 둠)

step_table = {
    "Second law of robotics : a": {"Robot": 0.8, "Person": 0.16},
    "Second law of robotics : a Robot": {"must": 0.7, "can": 0.3},
    "Second law of robotics : a Robot must": {"obey": 0.9, "ignore": 0.1},
}

sentence = "Second law of robotics : a"

# 표에 정의된 만큼 다음 단어를 이어붙인다
while sentence in step_table:
    probs = step_table[sentence]
    next_word = max(probs, key=probs.get)
    print(f"[현재] {sentence}  →  [선택] {next_word} ({probs[next_word]})")
    sentence = sentence + " " + next_word

print(f"\n최종 생성 문장: {sentence}")

③ 출력 결과

[현재] Second law of robotics : a  →  [선택] Robot (0.8)
[현재] Second law of robotics : a Robot  →  [선택] must (0.7)
[현재] Second law of robotics : a Robot must  →  [선택] obey (0.9)

최종 생성 문장: Second law of robotics : a Robot must obey

④ 한 줄씩 뜯어보기

  • step_table : “현재 문장 → 다음 단어 확률"을 단계별로 정의. 실제로는 모델이 매 단계 실시간 계산하는 부분을 표로 대신했다.
  • while sentence in step_table: : 표에 정의된 단계가 남아 있는 동안 반복.
  • sentence = sentence + " " + next_word : 고른 단어를 문장 끝에 붙여 다음 단계의 입력으로 만든다. 이 “출력이 다시 입력이 되는” 구조가 자기회귀의 핵심이다.

⑤ 💡 팁 — ChatGPT가 글자를 주르륵 타이핑하듯 출력하는 게 바로 이 반복이 실시간으로 보이는 것이다. 한 번에 문장 전체가 나오는 게 아니라 토큰을 하나씩 만들어 이어붙이는 중이다.

03 · API로 LLM 호출하기 (모델 활용 방식 ②)#

① 한 줄 설명 — 강의 A7에서 배운 “API를 통한 활용” 방식. 코드로 모델을 불러 응답을 받는 가장 기본 패턴이다. (실행하려면 openai 패키지와 API 키 필요)

② 코드

# 보완: 강의에 코드는 없었음. OpenAI 공식 SDK의 표준 호출 패턴 예시.
# 실행 전: pip install openai  /  환경변수 OPENAI_API_KEY 설정 필요
import os
from openai import OpenAI

# 보완: 키를 코드에 직접 적지 않고 환경변수에서 읽는다 (윤리 가이드 C4 준수)
client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "너는 친절한 한국어 비서야."},
        {"role": "user", "content": "생성형 AI를 한 문장으로 설명해줘."},
    ],
)

print(response.choices[0].message.content)

③ 출력 결과 (예시 — 모델 응답이라 매번 다름)

생성형 AI는 학습한 데이터의 패턴을 바탕으로 텍스트·이미지·오디오 등 새로운 콘텐츠를 만들어내는 AI입니다.

④ 한 줄씩 뜯어보기

  • import os, from openai import OpenAI : 운영체제 기능(환경변수 읽기)과 OpenAI 라이브러리를 불러온다.
  • os.environ["OPENAI_API_KEY"] : 키를 코드에 박지 않고 환경변수에서 꺼낸다. 보안의 기본.
  • messages=[...] : 대화를 역할별로 구성. system은 AI의 성격 설정, user는 사용자 질문.
  • response.choices[0].message.content : 모델이 만든 답변 텍스트가 여기 들어 있다.

⑤ 💡 팁 — Anthropic(Claude)도 패턴은 비슷하다(anthropic 패키지, client.messages.create(...)). API 방식의 장점은 내 프로그램·앱 안에 AI를 끼워 넣을 수 있다는 것. 웹 인터페이스(방식 ①)로는 못 하는 자동화가 가능해진다.

04 · 멀티모달 입력 맛보기 (이미지 + 텍스트)#

① 한 줄 설명 — 강의 A10의 멀티모달 개념을 코드로. 텍스트뿐 아니라 이미지도 함께 모델에 넣는 패턴이다. (개념 예시)

② 코드

# 보완: 강의에 코드 없음. 멀티모달(이미지+텍스트) 입력의 구조 예시.
# 한 메시지 안에 텍스트와 이미지 URL을 함께 담는다.
messages = [
    {
        "role": "user",
        "content": [
            {"type": "text", "text": "이 사진에 뭐가 있는지 설명해줘."},
            {"type": "image_url",
             "image_url": {"url": "https://example.com/cat.jpg"}},
        ],
    }
]

# (실제 호출은 03번처럼 client.chat.completions.create(model=..., messages=messages))
for part in messages[0]["content"]:
    print(part["type"], "->", part)

③ 출력 결과

text -> {'type': 'text', 'text': '이 사진에 뭐가 있는지 설명해줘.'}
image_url -> {'type': 'image_url', 'image_url': {'url': 'https://example.com/cat.jpg'}}

④ 한 줄씩 뜯어보기

  • content가 문자열이 아니라 리스트라는 점이 핵심. 텍스트 조각과 이미지 조각을 한 번에 담는다.
  • {"type": "text", ...} / {"type": "image_url", ...} : 각 조각의 종류(모달)를 type으로 구분한다. 이게 바로 멀티모달이 코드에서 표현되는 방식.

⑤ 💡 팁 — “사진 찍어서 물어보기"가 코드 레벨에선 이렇게 텍스트+이미지를 한 메시지에 담는 형태다. Text·Image·Audio·Video를 섞을 수 있게 되면서 AI 활용 폭이 크게 넓어졌다.

05 · 개인정보 비식별화 (마스킹) — 윤리 가이드 실습#

① 한 줄 설명 — 강의 C3에서 배운 “민감정보를 AI에 넣기 전 가짜 값으로 치환"을 코드로. 정규표현식으로 전화번호·이메일을 마스킹한다. (순수 파이썬, 표준 라이브러리)

② 코드

import re

text = "연락처는 123-4567-890 이고 이메일은 asdfgh@gmail.com 입니다. 12월 15일에 만나요."

# 방법1: 플레이스홀더 치환 (강의 C3 예시 형식)
masked = text
masked = re.sub(r"\d{3}-\d{4}-\d{3}", "XXX-YYYY-ZZZZ", masked)   # 전화번호
masked = re.sub(r"[\w.]+@[\w.]+", "sample@email", masked)         # 이메일
masked = re.sub(r"\d+월 \d+일", "XX월 YY일", masked)               # 날짜

print("원본 :", text)
print("마스킹:", masked)

③ 출력 결과

원본 : 연락처는 123-4567-890 이고 이메일은 asdfgh@gmail.com 입니다. 12월 15일에 만나요.
마스킹: 연락처는 XXX-YYYY-ZZZZ 이고 이메일은 sample@email 입니다. XX월 YY일에 만나요.

④ 한 줄씩 뜯어보기

  • import re : 정규표현식(패턴 매칭) 라이브러리. 파이썬 기본 내장이라 설치 불필요.
  • re.sub(패턴, 바꿀값, 문자열) : 패턴에 맞는 부분을 찾아 바꾼다.
  • \d{3}-\d{4}-\d{3} : 숫자 3개-4개-3개 = 전화번호 패턴.
  • [\w.]+@[\w.]+ : @ 앞뒤로 글자가 있는 이메일 패턴.

⑤ 💡 팁 — 강의에선 ② 변수형 치환([전화번호1], [이름1])도 소개됐다. AI 답변을 받은 뒤 이 변수를 원래 값으로 되돌리면, 민감정보를 노출하지 않으면서도 결과를 활용할 수 있다. 핵심 원칙: 민감정보는 AI에 넣지 않거나, 넣어야 하면 반드시 가공해서 넣는다.

06 · API 키 보안 — 환경변수 & .gitignore#

① 한 줄 설명 — 강의 C4의 “키 하드코딩 금지, .gitignore로 제외"를 실제 파일 구성으로 보여준다.

② 코드 / 파일 구성

# 나쁜 예 (절대 금지): 키를 코드에 그대로 박음 → GitHub에 올라가면 유출
client = OpenAI(api_key="sk-1234abcd_진짜키_노출됨")   # ❌

# 좋은 예: 환경변수에서 읽기 (03번에서 쓴 방식)
import os
client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])   # ✅

# .env 파일 (키를 따로 보관) — 이 파일은 절대 커밋하지 않는다
OPENAI_API_KEY=sk-실제키값

# .gitignore — 키 파일이 git에 올라가지 않도록 제외
.env
*.key
secrets/

③ 출력 결과 — (설정 파일이라 실행 출력은 없음. git status 시 .env가 추적 목록에 안 보이면 성공)

$ git status
On branch main
nothing to commit, working tree clean   # .env가 무시되어 안 잡힘

④ 한 줄씩 뜯어보기

  • .env : 키 같은 비밀값을 코드와 분리해 담는 파일.
  • .gitignore에 .env 추가 : git이 이 파일을 추적하지 않게 한다 → GitHub에 안 올라간다.
  • os.environ[...] : 실행 시점에 환경변수로 키를 주입받는다.

⑤ 💡 팁 — 실수로 키를 커밋해 push했다면, 파일만 지워선 안 된다. 이미 노출된 키는 즉시 폐기(revoke)하고 새로 발급해야 한다. git 히스토리에 영원히 남기 때문이다. 강의에서 키 노출의 위험(IP 등 도용)을 강조한 이유다.

07 · Human in the Loop 패턴#

① 한 줄 설명 — 강의 C10의 “AI는 초안, 최종 검증은 사람” 흐름을 코드 구조로 표현. (개념 예시)

② 코드

def ai_generate_draft(context: str) -> str:
    # 보완: 실제로는 03번처럼 API를 호출해 초안을 받는다. 여기선 흐름만.
    return f"[AI 초안] {context} 에 대한 답변 초안입니다."

def human_review(draft: str) -> str:
    print("AI가 만든 초안:")
    print(" ", draft)
    # 보완: 실제 운영에선 여기서 사람이 검토·수정한다 (input() 대신 자동 승인 처리)
    approved = draft + "  → [사람이 검토·수정 완료]"
    return approved

# Human in the Loop 흐름: Human(맥락) → AI(초안) → Human(검토)
context = "생성형 AI 윤리 가이드 요약"
draft = ai_generate_draft(context)      # AI가 초안 생성
final = human_review(draft)             # 사람이 검토·확정

print("\n최종 결과:", final)

③ 출력 결과

AI가 만든 초안:
  [AI 초안] 생성형 AI 윤리 가이드 요약 에 대한 답변 초안입니다.

최종 결과: [AI 초안] 생성형 AI 윤리 가이드 요약 에 대한 답변 초안입니다.  → [사람이 검토·수정 완료]

④ 한 줄씩 뜯어보기

  • ai_generate_draft(...) : AI가 **초안(Draft)**을 만드는 단계.
  • human_review(...) : 사람이 그 초안을 검토·수정하는 단계. AI 출력을 그대로 쓰지 않는다.
  • 마지막 흐름 3줄 : Human(맥락 제공) → AI(초안) → Human(검토) 순서가 코드 호출 순서로 그대로 드러난다.

⑤ 💡 팁 — 환각(Hallucination)과 아첨(Sycophancy) 같은 위험은 결국 이 “사람이 끝에서 확인"하는 단계로 막는다. AI에게 운전대를 통째로 넘기지 말고, 중요한 결정엔 항상 사람이 마지막에 개입하는 구조를 만들자.

📚 보충 자료#

  • OpenAI Python SDK 문서 (API 호출 패턴 참고)
  • Anthropic(Claude) SDK 문서 (API 방식 비교 참고)
  • 파이썬 re (정규표현식) 표준 라이브러리 문서 (비식별화 실습 참고)

다시 강조: 이 노트의 코드는 강의 원본이 아니라, 오늘 배운 개념을 체험하기 위한 보충 예제다 [코드 없음]. 03·04번 API 예제는 패키지 설치와 API 키가 있어야 실제로 동작한다. 01·02·05·06·07번은 추가 설치 없이(또는 파일 설정만으로) 돌려볼 수 있다.

마무리#

오늘은 코드 실습이 없는 이론 수업이었지만, 핵심 개념을 코드로 한 번 만져보면 머릿속에 훨씬 또렷하게 남는다. 자기회귀가 “단어를 하나씩 이어붙이는 반복"이라는 것, API 방식이 “코드로 모델을 부르는 것"이라는 것, 비식별화·키 보안·Human in the Loop가 추상적 구호가 아니라 실제 코드로 구현되는 안전장치라는 것 — 이 감각이 앞으로 실제 실습을 할 때 든든한 토대가 될 것이다.
