Part 0. 지역 변수 / 전역 변수 (클래스 전에 먼저)#

클래스로 들어가기 전, 변수가 “어디까지 살아 있는가”(스코프)를 정리합니다. 클래스의 self.속성(객체에 속함)과 클래스 변수(모두 공유)를 이해하는 밑바탕이 돼요.

0-1. 지역 변수는 함수 밖에서 못 본다 (NameError)#

def greet():
    msg = "함수 안에서 안녕!"   # 지역 변수 — greet() 안에서만 존재
    print(msg)

greet()
print(msg)   # 함수 밖에서 지역 변수 접근 시도

출력:

함수 안에서 안녕!
NameError: name 'msg' is not defined

🔍 msg는 greet() 안에서 만든 지역 변수라 함수가 끝나면 사라집니다. 함수 밖 print(msg)는 “그런 이름 없다"며 NameError를 냅니다.

0-2. 전역 변수는 함수 안에서도 보인다#

msg = "Python is awesome!"   # 전역 변수

def display():
    print("함수 안:", msg)    # 함수 안에서 전역 변수 읽기

display()
print("함수 밖:", msg)

출력:

함수 안: Python is awesome!
함수 밖: Python is awesome!

🔍 함수 밖에서 만든 전역 변수는 함수 안에서도 읽을 수 있습니다.

0-3. Shadowing — 같은 이름의 지역 변수가 전역을 가린다#

s = "I love yeardreamschool"   # 전역

def fun():
    s = "Me too."    # 전역 s가 아니라 새 지역 s를 만든 것
    print(s)

fun()
print(s)   # 함수 밖 — 전역은 그대로

출력:

Me too.
I love yeardreamschool

💡 함수 안에서 s = ... 하면 전역을 바꾼 게 아니라 새 지역 변수를 만든 것이라, 밖의 전역 s는 멀쩡합니다. 이걸 Shadowing(가리기) 이라고 해요.

0-4. 전역 변수를 함수 안에서 “수정"하려면 global#

count = 0

def increase():
    global count       # "여기서 쓰는 count는 전역 count다" 선언
    count = count + 1

increase()
print(count)   # 1
increase()
print(count)   # 2   ← 전역 count가 계속 누적됨

출력:

1
2

🔍 global count를 선언했기 때문에 함수 안에서 전역 count를 직접 수정합니다. 호출할 때마다 0 → 1 → 2로 누적돼요.

대조 — global 없이 매개변수로 받으면 전역은 안 바뀐다#

count = 0

def increase(count=0):   # 여기 count는 매개변수(= 지역 변수)
    count = count + 1
    return count

print(increase())   # 1
print(increase())   # 1  (매번 0에서 시작 — 전역과 무관)
print(count)        # 0  (전역 count는 그대로)

출력:

1
1
0

💡 같은 count라도 매개변수로 받은 count는 지역 변수라 전역과 별개입니다. 전역을 누적해 바꾸고 싶을 때만 global을 쓰고, 그게 아니면 위처럼 인자로 받아 return 하는 쪽이 추적하기 쉬워요.

⚠️ 처음엔 “함수 안에서 같은 이름 쓰면 전역이 바뀌나?” 가 제일 헷갈립니다. 읽기만 하면 전역이 보이고, 새로 대입하면 지역이 생긴다(수정하려면 global) — 이 한 줄만 기억하세요.

Part 1. 클래스 기초#

1. 빈 클래스와 인스턴스#

class TeamMember:      # 설계도 (클래스명 첫 글자 대문자)
    pass               # 아직 내용 없음

member1 = TeamMember()   # 설계도로 실제 객체 생성
member2 = TeamMember()

print(type(member1))       # <class '__main__.TeamMember'>
print(member1 is member2)  # False — 서로 다른 객체

🔍 TeamMember() 처럼 괄호를 붙이면 인스턴스(객체)가 만들어집니다. member1과 member2는 같은 설계도지만 다른 물건이에요.

2. __init__ 와 속성#

class TeamMember:
    def __init__(self, name, role, salary):
        self.name = name        # 인스턴스 속성 저장
        self.role = role
        self.salary = salary

alice = TeamMember(name="Alice", role="시니어 개발자", salary=60000)
bob   = TeamMember(name="Bob",   role="주니어 기획자", salary=3000)

print(f"{alice.name}의 직책: {alice.role}, 연봉: {alice.salary}만원")
print(f"{bob.name}의 직책: {bob.role}, 연봉: {bob.salary}만원")

출력:

Alice의 직책: 시니어 개발자, 연봉: 60000만원
Bob의 직책: 주니어 기획자, 연봉: 3000만원

🔍 __init__은 TeamMember(...)를 호출하는 순간 자동 실행돼 속성을 채웁니다. self는 만들어지는 그 객체(alice, bob)예요.

3. 메서드 — 객체의 행동#

class TeamMember:
    def __init__(self, name, role, salary):
        self.name, self.role, self.salary = name, role, salary
        self.projects = []      # 참여 중인 프로젝트 목록

    def introduce(self):
        print(f"안녕하세요! 저는 {self.role} {self.name}입니다.")

    def negotiate_salary(self, amount):     # 연봉 인상
        self.salary += amount
        print(f"축하합니다! {self.name}님 연봉이 {amount}만원 올라 총 {self.salary}만원입니다.")

    def develop_skill(self, new_role):      # 승진(직책 변경)
        self.role = new_role
        print(f"멋집니다! {self.name}님이 '{self.role}'(으)로 승진했습니다.")

alice = TeamMember("Alice", "주니어 기획자", 3000)
alice.introduce()
alice.develop_skill("시니어 기획자")
alice.negotiate_salary(2000)

출력:

안녕하세요! 저는 주니어 기획자 Alice입니다.
멋집니다! Alice님이 '시니어 기획자'(으)로 승진했습니다.
축하합니다! Alice님 연봉이 2000만원 올라 총 5000만원입니다.

💡 alice.develop_skill("시니어 기획자") — self는 자동으로 alice, new_role에 “시니어 기획자"가 들어갑니다.

4. 클래스 변수 vs 인스턴스 변수#

class TeamMember:
    company_name = "앨리스"      # 클래스 변수 (모두 공유)
    total_member = 0            # 전체 인원 카운터

    def __init__(self, name, role, salary):
        self.name = name        # 인스턴스 변수 (각자 다름)
        self.role = role
        self.salary = salary
        TeamMember.total_member += 1     # 객체 생길 때마다 +1

    def introduce(self):
        print(f"[{self.company_name}] {self.role} {self.name} (연봉: {self.salary}만원)")

alice = TeamMember("Alice", "시니어 개발자", 60000)
bob   = TeamMember("Bob", "주니어 기획자", 3000)
alice.introduce()
bob.introduce()
print(f"현재 총 팀원 수: {TeamMember.total_member}명")

# 클래스 변수를 바꾸면 → 모든 객체에 반영
TeamMember.company_name = "이어드림스쿨"
alice.introduce()

출력:

[앨리스] 시니어 개발자 Alice (연봉: 60000만원)
[앨리스] 주니어 기획자 Bob (연봉: 3000만원)
현재 총 팀원 수: 2명
[이어드림스쿨] 시니어 개발자 Alice (연봉: 60000만원)

💡 company_name을 한 번 바꾸니 alice·bob 모두 바뀝니다 → 공유되는 클래스 변수의 특징.

⚠️ 카운터 변수 이름을 total_member로 선언했으면 올릴 때도 정확히 TeamMember.total_member += 1 이어야 합니다. total_members(s 붙음)처럼 한 글자만 달라도 “그런 변수 없다"며 에러가 나니 주의하세요. (수업 중에도 이 오타로 한 번 막혔어요.)

5. __str__ / __repr__#

class TeamMember:
    def __init__(self, name, role, salary):
        self.name, self.role, self.salary = name, role, salary
    def __str__(self):      # print() 할 때 — 사람이 읽기 좋게
        return f"{self.role} {self.name}"
    def __repr__(self):     # 디버깅용 — 정확한 표현
        return f"TeamMember(name='{self.name}', role='{self.role}', salary={self.salary})"

alice = TeamMember("Alice", "시니어 개발자", 60000)
print(str(alice))    # 시니어 개발자 Alice
print(repr(alice))   # TeamMember(name='Alice', role='시니어 개발자', salary=60000)
print(alice)         # 시니어 개발자 Alice  (print는 __str__ 사용)

6. 클래스 메서드 · 정적 메서드#

class TeamMember:
    total_members = 0
    def __init__(self, name, role, salary):
        self.name, self.role, self.salary = name, role, salary
        TeamMember.total_members += 1

    @classmethod
    def get_total_members(cls):           # cls = 클래스 자신
        return cls.total_members

    @classmethod
    def from_string(cls, member_string):  # 대체 생성자
        """'이름-직책-연봉' 문자열로 객체 생성"""
        name, role, salary = member_string.split("-")
        return cls(name, role, int(salary))

    @staticmethod
    def is_valid_salary(salary):          # self·cls 없는 유틸 함수
        return 1000 <= salary <= 10000

alice = TeamMember("Alice", "시니어 개발자", 60000)
bob   = TeamMember("Bob", "주니어 기획자", 3000)
print(TeamMember.get_total_members())          # 2

carol = TeamMember.from_string("Carol-데이터 분석가-4500")   # 문자열로 생성!
print(TeamMember.get_total_members())          # 3
print(TeamMember.is_valid_salary(6000))        # True
print(TeamMember.is_valid_salary(500))         # False

💡 from_string은 대체 생성자 — "Carol-데이터 분석가-4500" 한 줄로 객체를 만듭니다. cls(...)가 곧 TeamMember(...). 여기서는 구분자로 하이픈(-)을 썼어요. (Part 3 미니프로젝트에서는 콜론 : 버전도 나옵니다 — 구분자는 만드는 사람이 정합니다.)

Part 2. 상속과 다형성#

7. 부모 클래스 + 자식 클래스 (상속)#

class Department:                  # 부모: 모든 팀의 공통 기능
    def __init__(self, team_name, budget):
        self.team_name = team_name
        self.budget = budget
        self.members = []

    def add_member(self, member):
        self.members.append(member)
        print(f"[{self.team_name}] {member.name}님이 합류했습니다.")

    def show_members(self):
        print(f"=== {self.team_name} 구성원 ({len(self.members)}명) ===")
        for i, m in enumerate(self.members, 1):
            print(f"  {i}. {m.role}: {m.name} (연봉 {m.salary}만원)")

    def get_total_salary(self):
        return sum(m.salary for m in self.members)

    def team_meeting(self):                  # 자식이 재정의할 수 있음
        print(f"[{self.team_name}] 정기 회의를 시작합니다.")


class DevTeam(Department):          # 자식: Department 상속
    def __init__(self, budget, tech_stack):
        super().__init__("개발팀", budget)   # 부모 __init__ 호출
        self.tech_stack = tech_stack          # 개발팀만의 추가 속성

    def team_meeting(self):                   # 오버라이딩
        print(f"[{self.team_name}] 스프린트 계획 회의 (기술: {', '.join(self.tech_stack)})")

🔍 DevTeam은 add_member·show_members를 물려받아 그대로 쓰고, team_meeting만 자기 방식으로 재정의했습니다. (영업팀·기획팀·분석팀도 같은 패턴)

8. 팀 구성 시뮬레이션#

# ① 팀원 생성
alice = TeamMember("Alice", "시니어 백엔드 개발자", 6500)
derek = TeamMember("Derek", "프론트엔드 개발자", 4800)
eve   = TeamMember("Eve",   "주니어 백엔드 개발자", 3600)

# ② 팀 생성
dev_team = DevTeam(budget=50000, tech_stack=["Python", "React", "PostgreSQL", "Docker"])

# ③ 팀에 배정
dev_team.add_member(alice)
dev_team.add_member(derek)
dev_team.add_member(eve)

# ④ 현황
dev_team.show_members()
print(f"   => 팀 연봉 합계: {dev_team.get_total_salary():,}만원")

출력:

[개발팀] Alice님이 합류했습니다.
[개발팀] Derek님이 합류했습니다.
[개발팀] Eve님이 합류했습니다.
=== 개발팀 구성원 (3명) ===
  1. 시니어 백엔드 개발자: Alice (연봉 6500만원)
  2. 프론트엔드 개발자: Derek (연봉 4800만원)
  3. 주니어 백엔드 개발자: Eve (연봉 3600만원)
   => 팀 연봉 합계: 14,900만원

💡 enumerate(self.members, 1) → 1번부터 번호 매기기, sum(m.salary for m in ...) → 연봉 합계.

9. 다형성 (Polymorphism)#

class PlanningTeam(Department):
    def __init__(self, budget):
        super().__init__("기획팀", budget)
    def team_meeting(self):
        print(f"[{self.team_name}] 기획 검토 회의를 시작합니다.")

class SalesTeam(Department):
    def __init__(self, budget):
        super().__init__("영업팀", budget)
    def team_meeting(self):
        print(f"[{self.team_name}] 영업 현황 회의를 시작합니다.")

# 같은 team_meeting() 호출 → 팀마다 다르게 동작
teams = [DevTeam(50000, ["Python"]), PlanningTeam(20000), SalesTeam(30000)]
for team in teams:
    team.team_meeting()

출력:

[개발팀] 스프린트 계획 회의 (기술: Python)
[기획팀] 기획 검토 회의를 시작합니다.
[영업팀] 영업 현황 회의를 시작합니다.

🔍 리스트에 담아 똑같이 team.team_meeting() 을 불렀는데 팀마다 결과가 달라요 — 이게 다형성입니다.

10. isinstance() · issubclass() 🔜 예습 (아직 안 배움 · 배운 뒤 보강)#

⏳ 수업에서 아직 안 다룬 부분이에요. 흐름상 짧게만 적어둡니다.

print(isinstance(dev_team, DevTeam))       # True
print(isinstance(dev_team, Department))    # True — 부모 타입으로도 True
print(issubclass(DevTeam, Department))     # True — DevTeam은 Department의 자식

Part 3. 미니프로젝트 — 파일 3개로 나눈 “IT 회사” (모듈 + 클래스 종합)#

지금까지는 한 파일(노트북 셀) 안에서 다뤘지만, 실제 프로젝트는 코드가 길어지면 기능별로 파일을 나눕니다. 이 미니프로젝트는 클래스(상속·다형성)와 모듈(파일 분리·import)을 한꺼번에 쓰는 완성형 예제예요.

3-1. 폴더 구조 — 역할별 파일 3개#

03_mini_project_class/
├── department.py   # 팀원·부서 클래스 정의 (TeamMember, Department, 4개 자식팀)
├── company.py      # 회사 전체를 관리하는 Company 클래스 (department.py를 import)
└── main.py         # 실행 시나리오 (company.py·department.py를 import)

🔍 누가 누구를 가져다 쓰는가가 핵심이에요.

  • department.py : 가장 아래 — 클래스들의 기반(아무것도 import 안 함, time·math만)
  • company.py : from department import ... 로 팀 클래스들을 가져와 회사로 묶음
  • main.py : company·department를 모두 가져와 실제 시나리오를 실행

💡 모듈 = 코드가 든 .py 파일 하나. 같은 폴더에 있으면 from 파일이름 import 클래스이름 으로 가져옵니다(.py는 빼고).

3-2. department.py — 팀원·부서 클래스 (기반 모듈)#

앞서 Part 1~2에서 만든 클래스들을 한 파일에 모으고, time·math 표준 라이브러리로 기능을 더했습니다. 핵심 부분만 봅니다.

# department.py
import time   # 입사 시각 기록, 재직 기간 계산
import math   # 평균 연봉 등 통계 계산

class TeamMember:
    company_name  = "TechCorp"   # 클래스 변수 (모두 공유)
    total_members = 0

    def __init__(self, name, role, salary, skills=None):
        self.name      = name
        self.role      = role
        self.salary    = salary
        self.projects  = []
        self.skills    = skills if skills else []
        self.join_time = time.time()      # 입사 시각(Unix timestamp) 기록
        TeamMember.total_members += 1

    @classmethod
    def from_string(cls, info_string):
        """'이름:직책:연봉:기술1,기술2' 형식 문자열로 팀원 생성"""
        parts  = info_string.split(":")
        name   = parts[0]
        role   = parts[1]
        salary = int(parts[2])
        skills = parts[3].split(",") if len(parts) > 3 else []
        return cls(name, role, salary, skills)

    @staticmethod
    def is_valid_salary(salary):
        """연봉이 합리적인 범위(1000~50000만원)인지 검사"""
        return 1000 <= salary <= 50000

    def get_tenure_days(self):
        """재직 일수 = (지금 - 입사시각) 을 일 단위로 내림"""
        elapsed_seconds = time.time() - self.join_time
        return math.floor(elapsed_seconds / 86400)   # 1일 = 86400초


class Department:                       # 부모: 모든 팀의 공통
    def __init__(self, team_name, budget):
        self.team_name  = team_name
        self.budget     = budget
        self.members    = []
        self.created_at = time.time()

    def add_member(self, member):
        if member not in self.members:
            self.members.append(member)
            print(f"  [{self.team_name}] | {member.name}({member.role}) 합류")

    def get_average_salary(self):
        if not self.members:
            return 0
        avg = self.get_total_salary() / len(self.members)
        return math.floor(avg)          # math.floor: 소수점 버림

    def team_meeting(self):             # 자식이 오버라이딩
        print(f"  [{self.team_name}] | 정기 팀 미팅을 시작합니다.")

    def __len__(self):                  # len(team) → 팀원 수
        return len(self.members)


class DevTeam(Department):              # 자식: 개발팀
    def __init__(self, budget, tech_stack):
        super().__init__("개발팀", budget)
        self.tech_stack   = tech_stack
        self.sprint_count = 0

    def team_meeting(self):             # 오버라이딩
        print(f"  [개발팀] | 스프린트 계획 회의 | 누적 스프린트: {self.sprint_count}회")
        self.show_tech_stack()
# PlanningTeam, SalesTeam, AnalyticsTeam 도 같은 패턴으로 Department를 상속

🔍 3가지가 한 클래스에 다 모였어요.

  • from_string → @classmethod 대체 생성자. 여기선 구분자가 콜론(:)이고 기술 목록까지 받습니다("Bob:시니어 기획자:5200:서비스기획,UX").
  • is_valid_salary → @staticmethod 유틸. 이 프로젝트의 유효 범위는 1000~50000만원.
  • get_tenure_days → time.time()(현재 시각)과 입사 시각의 차이를 math.floor로 일 단위로 내림.

💡 __len__을 정의해 두면 len(dev_team) 으로 팀원 수를 셀 수 있어요. __str__/__repr__/__eq__ 같은 매직 메서드도 이 파일에 함께 들어 있습니다.

3-3. company.py — 회사 전체 관리 (department.py를 import)#

여러 팀(Department 인스턴스)을 묶어 회사로 관리합니다. 맨 위에서 department.py의 클래스들을 가져와요.

# company.py
from department import (        # ← 같은 폴더의 department.py에서 가져오기
    TeamMember, DevTeam, PlanningTeam, SalesTeam, AnalyticsTeam,
)
import time
import math

class Company:
    def __init__(self, name):
        self.name       = name
        self.founded_at = time.time()
        self.teams      = {}        # { "개발팀": DevTeam(...), ... }

    def add_team(self, team):
        self.teams[team.team_name] = team
        print(f"  [{self.name}] '{team.team_name}' 팀이 추가되었습니다.")

    def get_total_headcount(self):
        return sum(len(team) for team in self.teams.values())   # len(team) = __len__

    def get_highest_paid(self):
        all_members = self.get_all_members()
        if not all_members:
            return None
        return max(all_members, key=lambda m: m.salary)         # 연봉 최고 직원

    def all_teams_meeting(self):
        """전사 회의: 모든 팀의 team_meeting()을 순서대로 호출 → 다형성"""
        for team in self.teams.values():
            team.team_meeting()      # 팀마다 다르게 동작

🔍 Company는 팀을 딕셔너리(teams) 로 모아두고, 전사 통계(get_total_headcount, get_highest_paid 등)를 계산합니다.

  • get_total_headcount → 각 팀의 len(team)(= __len__)을 모두 더함.
  • get_highest_paid → max(..., key=lambda m: m.salary) 로 연봉이 가장 높은 직원을 찾음.
  • all_teams_meeting → 같은 team_meeting() 호출이 팀마다 다르게 동작(다형성).

💡 company.py가 department.py를 import하므로, company를 쓰려면 두 파일이 같은 폴더에 있어야 합니다.

3-4. main.py — 실행 진입점 (if __name__ == "__main__")#

실제 시나리오를 실행하는 파일. 위 두 모듈을 모두 가져와 Step 1~11을 진행합니다.

# main.py
from company import Company
from department import (
    TeamMember, DevTeam, PlanningTeam, SalesTeam, AnalyticsTeam,
)
import time

if __name__ == "__main__":          # 이 파일을 직접 실행할 때만 아래 블록 실행
    # Step 1. 팀원 채용
    alice = TeamMember("Alice", "시니어 백엔드 개발자", 6500,
                       skills=["Python", "Django", "PostgreSQL", "Docker"])
    bob   = TeamMember.from_string("Bob:시니어 기획자:5200:서비스기획,UX,데이터분석")
    # ... (나머지 팀원 생성)
    print(f"\n  총 {TeamMember.get_total_members()}명 채용 완료!")

    # Step 2~3. 팀 생성 후 회사에 등록
    dev_team = DevTeam(budget=50000, tech_stack=["Python", "React", "PostgreSQL", "Docker"])
    techcorp = Company("TechCorp Korea")
    techcorp.add_team(dev_team)
    # ... (기획/영업/분석팀도 생성·등록)

    # Step 4. 팀에 팀원 배정
    dev_team.add_member(alice)

    # Step 7. 전사 회의 (다형성)
    techcorp.all_teams_meeting()

    # Step 8. 회사 전체 보고서
    techcorp.company_report()

🔍 if __name__ == "__main__": 이 핵심이에요.

  • python main.py 처럼 직접 실행하면 __name__이 "__main__"이 되어 이 블록이 돌아갑니다.
  • 다른 파일이 import main 하면 __name__은 "main"이라 이 블록은 실행되지 않아요. → “이 파일을 직접 실행할 때만 시나리오를 돌린다"는 안전장치.

3-5. 미니프로젝트가 보여주는 것 (정리)#

배운 것미니프로젝트에서 쓰인 곳
클래스·인스턴스·__init__TeamMember, Department, Company
클래스 변수 / 인스턴스 변수company_name·total_members / name·salary
@classmethod / @staticmethodfrom_string / is_valid_salary
매직 메서드__str__, __repr__, __eq__, __len__
상속 / super()DevTeam·SalesTeam 등이 Department 상속
오버라이딩 / 다형성팀별 team_meeting() 재정의 → all_teams_meeting()
모듈 / importdepartment → company → main 3파일 분리
진입점main.py의 if __name__ == "__main__":
표준 라이브러리time(시각), math(통계)

💡 “한 셀에 다 넣기 vs 파일로 나누기” — 코드가 길어지면 역할별로 파일을 쪼개고 import로 엮는 것이 실무 기본입니다. 이 미니프로젝트가 그 첫 경험이에요.

📚 보충#

실습에서 한 걸 더 깊게 — Python 공식 문서 기반.

self가 헷갈릴 때#

alice.introduce() 는 사실 TeamMember.introduce(alice) 와 같아요. 그래서 메서드 첫 칸 self에 그 객체(alice) 가 자동으로 들어갑니다. “내 정보를 쓰는 메서드라 자기 자신을 받는다"고 기억하세요.

클래스 변수 수정 주의#

self.company_name = "X" 처럼 객체로 바꾸면 그 객체만의 인스턴스 변수가 새로 생깁니다. 모두에게 반영하려면 TeamMember.company_name = "X" 처럼 클래스로 바꿔야 해요.

enumerate · sum(... for ...)#

  • enumerate(목록, 1) : 번호 + 값 동시에 (1부터)
  • sum(m.salary for m in members) : 각 객체의 속성을 꺼내 합산 (제너레이터)

지역/전역 변수 한 번 더#

  • 함수 안에서 전역을 읽기만 하면 그냥 됩니다.
  • 전역을 수정(재대입) 하려면 global이 필요해요.
  • 가급적 전역을 직접 바꾸기보다 인자로 받아 return 하는 방식이 추적하기 쉽습니다.

모듈로 나눌 때#

  • 같은 폴더면 from 파일이름 import 클래스 (.py 빼고).
  • 직접 실행할 때만 돌릴 코드는 if __name__ == "__main__": 안에 둡니다.

핵심 정리#

개념한 줄
지역 / 전역 변수함수 안에서만 / 어디서나 (수정은 global)
클래스 / 인스턴스설계도 / 그걸로 만든 실제 객체
__init__ / self생성 시 자동 실행 / 그 객체 자신
인스턴스 vs 클래스 변수각자 다른 값 / 모두 공유
상속 / super()부모 기능 물려받기 / 부모 호출
오버라이딩 / 다형성부모 메서드 재정의 / 같은 호출 다른 동작
모듈 / import코드를 .py로 나눠 가져다 쓰기
