파이썬 클래스 실습 — “IT 회사의 팀원과 부서"를 코드로 만들며 객체지향을 익혔습니다. 강의 노트북 코드를 그대로 정리하고, 각 단계를 ① 한 줄 설명 → ② 코드 → ③ 출력 → ④ 한 줄씩 뜯어보기 → ⑤ 팁 으로 풀었어요. 직접 쳐보세요! 🏢

Part 1. 클래스 기초#

1. 빈 클래스와 인스턴스#

class TeamMember:      # 설계도 (클래스명 첫 글자 대문자)
    pass               # 아직 내용 없음

member1 = TeamMember()   # 설계도로 실제 객체 생성
member2 = TeamMember()

print(type(member1))       # <class '__main__.TeamMember'>
print(member1 is member2)  # False — 서로 다른 객체

🔍 TeamMember() 처럼 괄호를 붙이면 인스턴스(객체)가 만들어집니다. member1과 member2는 같은 설계도지만 다른 물건이에요.

2. __init__ 와 속성#

class TeamMember:
    def __init__(self, name, role, salary):
        self.name = name        # 인스턴스 속성 저장
        self.role = role
        self.salary = salary

alice = TeamMember(name="Alice", role="시니어 개발자", salary=60000)
bob   = TeamMember(name="Bob",   role="주니어 기획자", salary=3000)

print(f"{alice.name}의 직책: {alice.role}, 연봉: {alice.salary}만원")
print(f"{bob.name}의 직책: {bob.role}, 연봉: {bob.salary}만원")

출력:

Alice의 직책: 시니어 개발자, 연봉: 60000만원
Bob의 직책: 주니어 기획자, 연봉: 3000만원

🔍 __init__은 TeamMember(...)를 호출하는 순간 자동 실행돼 속성을 채웁니다. self는 만들어지는 그 객체(alice, bob)예요.

3. 메서드 — 객체의 행동#

class TeamMember:
    def __init__(self, name, role, salary):
        self.name, self.role, self.salary = name, role, salary
        self.projects = []      # 참여 중인 프로젝트 목록

    def introduce(self):
        print(f"안녕하세요! 저는 {self.role} {self.name}입니다.")

    def negotiate_salary(self, amount):     # 연봉 인상
        self.salary += amount
        print(f"축하합니다! {self.name}님 연봉이 {amount}만원 올라 총 {self.salary}만원입니다.")

    def develop_skill(self, new_role):      # 승진(직책 변경)
        self.role = new_role
        print(f"멋집니다! {self.name}님이 '{self.role}'(으)로 승진했습니다.")

alice = TeamMember("Alice", "주니어 기획자", 3000)
alice.introduce()
alice.develop_skill("시니어 기획자")
alice.negotiate_salary(2000)

출력:

안녕하세요! 저는 주니어 기획자 Alice입니다.
멋집니다! Alice님이 '시니어 기획자'(으)로 승진했습니다.
축하합니다! Alice님 연봉이 2000만원 올라 총 5000만원입니다.

💡 alice.develop_skill("시니어 기획자") — self는 자동으로 alice, new_role에 “시니어 기획자"가 들어갑니다.

4. 클래스 변수 vs 인스턴스 변수#

class TeamMember:
    company_name = "앨리스"      # 클래스 변수 (모두 공유)
    total_member = 0            # 전체 인원 카운터

    def __init__(self, name, role, salary):
        self.name = name        # 인스턴스 변수 (각자 다름)
        self.role = role
        self.salary = salary
        TeamMember.total_member += 1     # 객체 생길 때마다 +1

    def introduce(self):
        print(f"[{self.company_name}] {self.role} {self.name} (연봉: {self.salary}만원)")

alice = TeamMember("Alice", "시니어 개발자", 60000)
bob   = TeamMember("Bob", "주니어 기획자", 3000)
alice.introduce()
bob.introduce()
print(f"현재 총 팀원 수: {TeamMember.total_member}명")

# 클래스 변수를 바꾸면 → 모든 객체에 반영
TeamMember.company_name = "이어드림스쿨"
alice.introduce()

출력:

[앨리스] 시니어 개발자 Alice (연봉: 60000만원)
[앨리스] 주니어 기획자 Bob (연봉: 3000만원)
현재 총 팀원 수: 2명
[이어드림스쿨] 시니어 개발자 Alice (연봉: 60000만원)

💡 company_name을 한 번 바꾸니 alice·bob 모두 바뀝니다 → 공유되는 클래스 변수의 특징.

5. __str__ / __repr__#

class TeamMember:
    def __init__(self, name, role, salary):
        self.name, self.role, self.salary = name, role, salary
    def __str__(self):      # print() 할 때 — 사람이 읽기 좋게
        return f"{self.role} {self.name}"
    def __repr__(self):     # 디버깅용 — 정확한 표현
        return f"TeamMember(name='{self.name}', role='{self.role}', salary={self.salary})"

alice = TeamMember("Alice", "시니어 개발자", 60000)
print(str(alice))    # 시니어 개발자 Alice
print(repr(alice))   # TeamMember(name='Alice', role='시니어 개발자', salary=60000)
print(alice)         # 시니어 개발자 Alice  (print는 __str__ 사용)

6. 클래스 메서드 · 정적 메서드#

class TeamMember:
    total_members = 0
    def __init__(self, name, role, salary):
        self.name, self.role, self.salary = name, role, salary
        TeamMember.total_members += 1

    @classmethod
    def get_total_members(cls):           # cls = 클래스 자신
        return cls.total_members

    @classmethod
    def from_string(cls, member_string):  # 대체 생성자
        """'이름-직책-연봉' 문자열로 객체 생성"""
        name, role, salary = member_string.split("-")
        return cls(name, role, int(salary))

    @staticmethod
    def is_valid_salary(salary):          # self·cls 없는 유틸 함수
        return 1000 <= salary <= 10000

alice = TeamMember("Alice", "시니어 개발자", 60000)
bob   = TeamMember("Bob", "주니어 기획자", 3000)
print(TeamMember.get_total_members())          # 2

carol = TeamMember.from_string("Carol-데이터 분석가-4500")   # 문자열로 생성!
print(TeamMember.get_total_members())          # 3
print(TeamMember.is_valid_salary(6000))        # True
print(TeamMember.is_valid_salary(500))         # False

💡 from_string은 대체 생성자 — "Carol-데이터 분석가-4500" 한 줄로 객체를 만듭니다. cls(...)가 곧 TeamMember(...).

Part 2. 상속과 다형성#

7. 부모 클래스 + 자식 클래스 (상속)#

class Department:                  # 부모: 모든 팀의 공통 기능
    def __init__(self, team_name, budget):
        self.team_name = team_name
        self.budget = budget
        self.members = []

    def add_member(self, member):
        self.members.append(member)
        print(f"[{self.team_name}] {member.name}님이 합류했습니다.")

    def show_members(self):
        print(f"=== {self.team_name} 구성원 ({len(self.members)}명) ===")
        for i, m in enumerate(self.members, 1):
            print(f"  {i}. {m.role}: {m.name} (연봉 {m.salary}만원)")

    def get_total_salary(self):
        return sum(m.salary for m in self.members)

    def team_meeting(self):                  # 자식이 재정의할 수 있음
        print(f"[{self.team_name}] 정기 회의를 시작합니다.")


class DevTeam(Department):          # 자식: Department 상속
    def __init__(self, budget, tech_stack):
        super().__init__("개발팀", budget)   # 부모 __init__ 호출
        self.tech_stack = tech_stack          # 개발팀만의 추가 속성

    def team_meeting(self):                   # 오버라이딩
        print(f"[{self.team_name}] 스프린트 계획 회의 (기술: {', '.join(self.tech_stack)})")

🔍 DevTeam은 add_member·show_members를 물려받아 그대로 쓰고, team_meeting만 자기 방식으로 재정의했습니다. (영업팀·기획팀·분석팀도 같은 패턴)

8. 팀 구성 시뮬레이션#

# ① 팀원 생성
alice = TeamMember("Alice", "시니어 백엔드 개발자", 6500)
derek = TeamMember("Derek", "프론트엔드 개발자", 4800)
eve   = TeamMember("Eve",   "주니어 백엔드 개발자", 3600)

# ② 팀 생성
dev_team = DevTeam(budget=50000, tech_stack=["Python", "React", "PostgreSQL", "Docker"])

# ③ 팀에 배정
dev_team.add_member(alice)
dev_team.add_member(derek)
dev_team.add_member(eve)

# ④ 현황
dev_team.show_members()
print(f"   => 팀 연봉 합계: {dev_team.get_total_salary():,}만원")

출력:

[개발팀] Alice님이 합류했습니다.
[개발팀] Derek님이 합류했습니다.
[개발팀] Eve님이 합류했습니다.
=== 개발팀 구성원 (3명) ===
  1. 시니어 백엔드 개발자: Alice (연봉 6500만원)
  2. 프론트엔드 개발자: Derek (연봉 4800만원)
  3. 주니어 백엔드 개발자: Eve (연봉 3600만원)
   => 팀 연봉 합계: 14,900만원

💡 enumerate(self.members, 1) → 1번부터 번호 매기기, sum(m.salary for m in ...) → 연봉 합계.

9. 다형성 (Polymorphism)#

class PlanningTeam(Department):
    def __init__(self, budget):
        super().__init__("기획팀", budget)
    def team_meeting(self):
        print(f"[{self.team_name}] 기획 검토 회의를 시작합니다.")

class SalesTeam(Department):
    def __init__(self, budget):
        super().__init__("영업팀", budget)
    def team_meeting(self):
        print(f"[{self.team_name}] 영업 현황 회의를 시작합니다.")

# 같은 team_meeting() 호출 → 팀마다 다르게 동작
teams = [DevTeam(50000, ["Python"]), PlanningTeam(20000), SalesTeam(30000)]
for team in teams:
    team.team_meeting()

출력:

[개발팀] 스프린트 계획 회의 (기술: Python)
[기획팀] 기획 검토 회의를 시작합니다.
[영업팀] 영업 현황 회의를 시작합니다.

🔍 리스트에 담아 똑같이 team.team_meeting() 을 불렀는데 팀마다 결과가 달라요 — 이게 다형성입니다.

10. isinstance() · issubclass() 🔜 예습 (아직 안 배움 · 배운 뒤 보강)#

⏳ 수업에서 아직 안 다룬 부분이에요. 흐름상 짧게만 적어둡니다.

print(isinstance(dev_team, DevTeam))       # True
print(isinstance(dev_team, Department))    # True — 부모 타입으로도 True
print(issubclass(DevTeam, Department))     # True — DevTeam은 Department의 자식

📚 보충#

실습에서 한 걸 더 깊게 — Python 공식 문서 기반.

self가 헷갈릴 때#

alice.introduce() 는 사실 TeamMember.introduce(alice) 와 같아요. 그래서 메서드 첫 칸 self에 그 객체(alice) 가 자동으로 들어갑니다. “내 정보를 쓰는 메서드라 자기 자신을 받는다"고 기억하세요.

클래스 변수 수정 주의#

self.company_name = "X" 처럼 객체로 바꾸면 그 객체만의 인스턴스 변수가 새로 생깁니다. 모두에게 반영하려면 TeamMember.company_name = "X" 처럼 클래스로 바꿔야 해요.

enumerate · sum(... for ...)#

  • enumerate(목록, 1) : 번호 + 값 동시에 (1부터)
  • sum(m.salary for m in members) : 각 객체의 속성을 꺼내 합산 (제너레이터)

핵심 정리#

개념 한 줄
클래스 / 인스턴스 설계도 / 그걸로 만든 실제 객체
__init__ / self 생성 시 자동 실행 / 그 객체 자신
인스턴스 vs 클래스 변수 각자 다른 값 / 모두 공유
상속 / super() 부모 기능 물려받기 / 부모 호출
오버라이딩 / 다형성 부모 메서드 재정의 / 같은 호출 다른 동작
