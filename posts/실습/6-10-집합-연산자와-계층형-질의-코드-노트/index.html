📌 정답 출처 안내 — 이번엔 거의 전부 실제 답지다. 오늘 실습 쿼리는 강사님 정답본(Day03_lecture.sql) 과 노션 발표용 답지(0610) 두 곳에 실제 정답이 모두 있다. 그래서 아래 쿼리는 표시 없으면 모두 ✅ 실제 답지 (정답본 + 노션 답지 일치)다. 다만 정답본 자체의 사소한 흠 2건은 정직하게 처리했다.

  • / 10000 단위 오타(05 MAX 절): 정답본 원문이 분 환산이라면서 / 10000으로 적혀 있다(분이면 / 60000이 맞다). 노션엔 해당 쿼리가 없어 대조 불가 → 원문 그대로 싣고 한 줄 주석으로 안내한다.
  • 괄호 누락 버그(07 4-2 확인3): 정답본의 해당 블록은 여는 SELECT ... FROM ( 없이 닫는 ); 만 남은 문법 오류다 → 올바른 서브쿼리 래핑 형태로 보정해 싣고 그 자리에 명시한다.

🧪 실습 노트#

실습 DB는 chinook(SQLite)다. 오늘 쓰는 주요 관계(키)는 다음과 같다.

employees.EmployeeId   ↔ employees.ReportsTo     (자기 참조 = 계층형!)
employees.EmployeeId   ↔ customers.SupportRepId
customers.CustomerId   ↔ invoices.CustomerId
invoices.InvoiceId     ↔ invoice_items.InvoiceId
invoice_items.TrackId  ↔ tracks.TrackId
tracks.GenreId         ↔ genres.GenreId
tracks.AlbumId         ↔ albums.AlbumId
tracks.TrackId         ↔ playlist_track.TrackId

순서:

  1. UNION — 합집합(중복 제거)
  2. UNION ALL — 합집합(중복 포함) + 소계 패턴
  3. INTERSECT — 교집합
  4. INTERSECT 결과를 JOIN으로 확장 (이름까지)
  5. EXCEPT — 차집합(이탈 고객·미포함 트랙)
  6. 집계 + 조인 + UNION ALL — 장르별 매출 리포트(소계 포함)
  7. 서브쿼리 + EXCEPT (괄호 누락 버그 보정)
  8. 계층형 질의 ① 기본 보고 체계 (WITH RECURSIVE)
  9. 계층형 질의 ② 계층 + 집계 (담당 고객수·매출)
  10. 계층형 질의 ③ 경로 추적 + Leaf/Branch 판별
  11. 계층형 질의 ④ 레벨별 인원 + 합계 (계층 + UNION ALL)

01 · UNION — 합집합 (중복 제거)#

① 한 줄 설명 — 두 SELECT 결과를 세로로 합치되 중복 행은 한 번만 남긴다. 상수 컬럼으로 출처를 구분한다.

② 코드 (출처: Day03_lecture.sql 3-1 / 노션 0610 — ✅ 실제 답지)

-- (a) 직원 이름 + 고객 이름 통합 목록
SELECT FirstName, LastName, 'Employee' AS Type
FROM employees

UNION

SELECT FirstName, LastName, 'Customer'
FROM customers

ORDER BY FirstName, LastName;

-- (b) 구매 이력 유무별 고객 분류
SELECT CustomerId,
       FirstName || ' ' || LastName AS 고객명,
       'Has Invoice'                AS 상태
FROM customers
WHERE CustomerId IN (SELECT DISTINCT CustomerId FROM invoices)

UNION

SELECT CustomerId,
       FirstName || ' ' || LastName AS 고객명,
       'No Invoice'                 AS 상태
FROM customers
WHERE CustomerId NOT IN (SELECT DISTINCT CustomerId FROM invoices)

ORDER BY CustomerId;

③ 출력 결과 — (a) 직원+고객 이름이 한 명단으로, 세 번째 컬럼에 Employee/Customer 표시가 붙어 이름순으로 정렬. (b) 모든 고객이 Has Invoice/No Invoice로 분류돼 CustomerId순으로.

④ 한 줄씩 뜯어보기

  • 'Employee' AS Type : 어느 테이블에서 왔는지 표시하는 상수 컬럼. (b)의 두 번째 SELECT는 별칭을 생략했는데, 규칙 ③대로 결과 컬럼명은 첫 SELECT의 Type/상태를 따른다.
  • FirstName || ' ' || LastName : SQLite의 문자열 결합(||)으로 성+이름을 한 컬럼으로.
  • ORDER BY : 두 SELECT를 합친 최종 결과에만 한 번 적용(규칙 ④).
  • (b)의 두 WHERE(IN / NOT IN)가 전체 고객을 “청구서 있음 / 없음"으로 정확히 둘로 가른다.

⑤ 💡 팁 — UNION은 중복 제거를 위해 정렬 비용이 든다. (a)처럼 직원·고객 이름이 겹칠 가능성이 있을 때 중복을 합치고 싶으면 UNION이 맞다. 단순히 다 쌓기만 하면 되면 다음 절의 UNION ALL이 더 빠르다.

02 · UNION ALL — 합집합(중복 포함) + 소계 패턴#

① 한 줄 설명 — 중복 제거·정렬 없이 그냥 이어 붙인다(더 빠름). 그룹 집계 + 전체 합계 행을 합치는 “소계 리포트"에 딱이다.

② 코드 (출처: Day03_lecture.sql 3-2 / 노션 0610 — ✅ 실제 답지)

-- (a) 연도별 매출 + 전체 합계 (소계 패턴)
SELECT strftime('%Y', InvoiceDate) AS 연도,
       ROUND(SUM(Total), 2)        AS 매출합계
FROM invoices
GROUP BY 연도

UNION ALL

SELECT '── 전체합계',
       ROUND(SUM(Total), 2)
FROM invoices

ORDER BY 연도;

-- (b) 장르별 트랙 수 + 전체 합계
SELECT g.Name            AS 장르명,
       COUNT(t.TrackId)  AS 트랙수
FROM genres g
LEFT JOIN tracks t ON g.GenreId = t.GenreId
GROUP BY g.Name

UNION ALL

SELECT '■ 전체합계',
       COUNT(*)
FROM tracks

ORDER BY 장르명;

③ 출력 결과 — (a) 연도별 매출 행들 + ── 전체합계 행 한 줄(전체 매출). (b) 장르별 트랙 수 + ■ 전체합계 행(총 트랙 수). 합계 행이 함께 섞여 정렬돼 나온다.

④ 한 줄씩 뜯어보기

  • 위쪽 SELECT = 그룹별 집계(GROUP BY 연도 / 장르명).
  • 아래쪽 SELECT = 전체 합계(GROUP BY 없이 전체 SUM/COUNT).
  • '── 전체합계' : 그룹 자리에 문자열을 박아 합계 행임을 표시. 두 SELECT의 컬럼 수·타입이 맞아야 한다(규칙 ①②).
  • 여기서 UNION ALL을 쓰는 이유 = 합계 행은 중복될 일이 없으니 굳이 중복 제거 비용을 치를 필요가 없다.

⑤ 💡 팁 — 강사님 진행법: 위 쿼리와 아래 쿼리를 따로 먼저 실행해 값을 확인한 뒤 UNION ALL로 합쳤다. “분할 → 각각 실행 → 합치기"가 소계 패턴에서 특히 유용하다. (노션 답지엔 합계 행 라벨이 ------전체합계, 전체합계 ROUND 자릿수가 1로 적힌 버전도 있는데, 표시·반올림 취향 차이일 뿐 로직은 동일하다.)

03 · INTERSECT — 교집합#

① 한 줄 설명 — 두 결과에 모두 들어 있는 행만 남긴다(중복 제거).

② 코드 (출처: Day03_lecture.sql 3-3 / 노션 0610 — ✅ 실제 답지)

-- (a) 청구서가 있는 고객 (INTERSECT 방식)
SELECT CustomerId, FirstName, LastName
FROM customers

INTERSECT

SELECT CustomerId, FirstName, LastName
FROM invoices
INNER JOIN customers USING (CustomerId)

ORDER BY CustomerId;

-- (b) 2009년·2010년 모두 구매한 고객 ID
SELECT CustomerId
FROM invoices
WHERE strftime('%Y', InvoiceDate) = '2009'

INTERSECT

SELECT CustomerId
FROM invoices
WHERE strftime('%Y', InvoiceDate) = '2010'

ORDER BY CustomerId;

③ 출력 결과 — (a) 전체 고객 ∩ 청구서를 가진 고객 = 실제 구매 고객만. (b) 2009·2010 두 해 모두에 등장하는 고객 ID 목록.

④ 한 줄씩 뜯어보기

  • (a) 위 SELECT = 전체 고객, 아래 SELECT = invoices와 조인된(=청구서가 있는) 고객. 교집합 = 둘 다 충족 = 구매 고객.
  • INNER JOIN customers USING (CustomerId) : 두 테이블에 같은 이름 컬럼이 있을 때 USING(컬럼)으로 간결하게 조인.
  • (b) 같은 invoices 테이블을 연도 조건만 다르게 두 번 조회해 교집합 → “두 해 다 산 사람”.

⑤ 💡 팁 — MySQL은 INTERSECT를 지원하지 않는다. MySQL이라면 (b)는 INNER JOIN이나 IN 서브쿼리로 우회해야 한다. SQLite·Oracle·MariaDB는 그대로 동작.

04 · INTERSECT 결과를 JOIN으로 확장 (이름까지)#

① 한 줄 설명 — 03(b)의 교집합 결과(ID 목록)를 FROM절 서브쿼리(인라인 뷰)로 감싸 customers와 조인하면 이름까지 붙는다.

② 코드 (출처: Day03_lecture.sql 3-3(b) 확장 / 노션 0610 — ✅ 실제 답지)

SELECT c.CustomerId, c.FirstName, c.LastName
FROM customers c
INNER JOIN (

    SELECT CustomerId
    FROM invoices
    WHERE strftime('%Y', InvoiceDate) = '2009'

    INTERSECT

    SELECT CustomerId
    FROM invoices
    WHERE strftime('%Y', InvoiceDate) = '2010'

    ORDER BY CustomerId
) inv ON inv.CustomerId = c.CustomerId;

③ 출력 결과 — 2009·2010 두 해 모두 구매한 고객의 CustomerId + FirstName + LastName. ID만 있던 03(b)에 이름이 붙은 완성형.

④ 한 줄씩 뜯어보기

  • 괄호 안 = 03(b)의 INTERSECT 쿼리 통째로. 이걸 하나의 임시 테이블(inv) 처럼 쓴다.
  • INNER JOIN ( ... ) inv ON inv.CustomerId = c.CustomerId : 교집합 결과(ID들)와 customers를 ID로 연결 → 이름 획득.
  • 어제 배운 인라인 뷰 + 조인이 집합 연산과 결합되는 지점.

⑤ 💡 팁 — 집합 연산 결과는 보통 ID 같은 식별자만 나온다. “사람이 읽을 리포트"로 만들려면 이렇게 서브쿼리로 감싸 원본 테이블과 JOIN하는 게 정석 패턴이다. EXCEPT 결과도 똑같이 확장할 수 있다.

05 · EXCEPT — 차집합 (이탈 고객·미포함 트랙)#

① 한 줄 설명 — 앞 결과에서 뒤 결과에 있는 것을 빼낸다(중복 제거). “있다가 없어진 것” 찾기에 유용.

② 코드 (출처: Day03_lecture.sql 3-4 / 노션 0610 — ✅ 실제 답지)

-- (a) 청구서 없는 고객 (전체 - 청구서 있는 고객)
SELECT CustomerId, FirstName, LastName
FROM customers

EXCEPT

SELECT CustomerId, FirstName, LastName
FROM invoices
INNER JOIN customers USING (CustomerId)

ORDER BY CustomerId;

-- (b) 2009년 구매했지만 2010년엔 안 산 고객 (이탈 고객)
SELECT CustomerId
FROM invoices
WHERE strftime('%Y', InvoiceDate) = '2009'

EXCEPT

SELECT CustomerId
FROM invoices
WHERE strftime('%Y', InvoiceDate) = '2010'

ORDER BY CustomerId;

-- (c) 플레이리스트에 없는 트랙
SELECT TrackId, Name
FROM tracks

EXCEPT

SELECT t.TrackId, t.Name
FROM tracks t
JOIN playlist_track pt ON t.TrackId = pt.TrackId

ORDER BY TrackId;

③ 출력 결과 — (a) 전체 고객 − 청구서 있는 고객 = 청구서 없는 고객(아래 팁 참고). (b) 작년만 사고 올해 안 산 “이탈 고객” ID. (c) 어떤 플레이리스트에도 안 들어간 트랙.

④ 한 줄씩 뜯어보기

  • EXCEPT는 순서가 중요하다. A EXCEPT B = A에는 있고 B엔 없는 것. 뒤집으면 결과가 달라진다.
  • (b)가 마케팅의 “이탈 고객”(작년 구매자 − 올해 구매자) 개념. (c)는 “전체 트랙 − 플리에 든 트랙”.

⑤ 💡 팁 — (a)의 Chinook 데이터는 고객과 청구서가 거의 1:1이라 결과가 비어 보일 수 있다(쿼리가 틀린 게 아니라 데이터 특성). 그리고 EXCEPT는 Oracle에선 MINUS, MySQL은 미지원(JOIN/NOT IN/NOT EXISTS로 우회)이다.

06 · 집계 + 조인 + UNION ALL — 장르별 매출 리포트(소계 포함)#

① 한 줄 설명 — 3개 테이블 조인 → 장르별 집계 → UNION ALL로 전체 합계 행 추가. 오늘 가장 종합적인 쿼리.

② 코드 (출처: Day03_lecture.sql 4-1 / 노션 0610 — ✅ 실제 답지)

SELECT g.Name                          AS 장르,
       COUNT(DISTINCT ii.InvoiceId)    AS 청구서수,
       SUM(ii.Quantity)                AS 판매수량,
       ROUND(SUM(ii.UnitPrice * ii.Quantity), 2) AS 총매출
FROM invoice_items ii
INNER JOIN tracks t ON ii.TrackId = t.TrackId
INNER JOIN genres g ON t.GenreId  = g.GenreId
GROUP BY g.Name

UNION ALL

SELECT '── 전체합계',
       COUNT(DISTINCT InvoiceId),
       SUM(Quantity),
       ROUND(SUM(UnitPrice * Quantity), 2)
FROM invoice_items

ORDER BY 장르;

③ 출력 결과 — 장르별 청구서수·판매수량·총매출 4컬럼 + 맨 끝 ── 전체합계 행.

④ 한 줄씩 뜯어보기

  • invoice_items → tracks → genres 2단 조인으로 “어떤 라인 아이템이 어느 장르인지” 연결.
  • COUNT(DISTINCT ii.InvoiceId) : 한 청구서에 같은 장르 트랙이 여러 개여도 청구서는 1건으로(중복 제거).
  • SUM(ii.UnitPrice * ii.Quantity) : 라인별 (단가×수량)을 합산한 실제 매출.
  • 아래 SELECT는 GROUP BY 없이 invoice_items 전체를 같은 방식으로 집계 → 전체 합계 행.

⑤ 💡 팁 — 강사님이 “혼자 풀면 고난도"라 평한 문제다. 한 번에 쓰려 하지 말고 ① 3개 조인 + 장르 집계, ② 전체 합계, 두 쿼리를 따로 검증한 뒤 UNION ALL로 합치자. 집계·조인·집합 연산이 한 쿼리에 모이는 실무형 리포트.

07 · 서브쿼리 + EXCEPT (괄호 누락 버그 보정)#

① 한 줄 설명 — “판매됐지만 플레이리스트엔 없는 트랙"을 EXCEPT로 구하고, 단계별로 개수를 확인한다.

② 코드 (출처: Day03_lecture.sql 4-2 — ✅ 실제 답지, 단 확인3은 보정)

⚠️ 보정 안내: 강사 원본 SQL의 “확인 3” 블록은 여는 SELECT ... FROM ( 없이 닫는 ); 만 남은 괄호 누락 오타라 그대로 실행하면 문법 오류가 난다. 아래는 의도(판매 트랙 − 플리 트랙)에 맞게 올바른 형태로 보정한 것이다.

-- 확인 1: 판매된 트랙 수
SELECT COUNT(DISTINCT TrackId) AS 판매된트랙수
FROM invoice_items;

-- 확인 2: 플레이리스트에 있는 트랙 수
SELECT COUNT(DISTINCT TrackId) AS 플리트랙수
FROM playlist_track;

-- 확인 3: 판매됐지만 플리에 없는 트랙
--   ※ 강사 원본은 여는 'SELECT ... FROM (' 가 누락된 orphan ");" 버그 → 아래처럼 보정
SELECT COUNT(*) AS 판매O_플리X_트랙수
FROM (
    SELECT DISTINCT TrackId FROM invoice_items
    EXCEPT
    SELECT DISTINCT TrackId FROM playlist_track
);

-- 확인 4: 플리에 있지만 판매 안 된 트랙 (반대 방향)
SELECT DISTINCT t.TrackId AS TrackId, t.Name AS 트랙명
FROM tracks t
JOIN playlist_track pt ON t.TrackId = pt.TrackId

EXCEPT

SELECT DISTINCT t.TrackId, t.Name
FROM invoice_items ii
JOIN tracks t ON ii.TrackId = t.TrackId

ORDER BY TrackId;

③ 출력 결과 — 확인1·2는 각각 개수 한 줄, 확인3은 (판매 트랙 − 플리 트랙) 개수, 확인4는 그 반대 방향(플리엔 있고 판매 안 된) 트랙 목록.

④ 한 줄씩 뜯어보기

  • 확인3 보정: EXCEPT 결과(판매O·플리X 트랙 ID들)를 FROM절 서브쿼리로 감싸 COUNT(*)로 개수를 센다. 04와 같은 “집합 연산을 서브쿼리로 감싸기” 패턴.
  • 확인4 = 방향만 뒤집은 EXCEPT. EXCEPT는 좌우 순서에 따라 결과가 달라진다는 걸 확인1~4로 체감.

⑤ 💡 팁 — 복잡한 EXCEPT는 이렇게 “확인 쿼리"로 양쪽 개수를 먼저 재 보고 본 쿼리를 짜면 검증이 쉽다. 원본 답지에도 오타가 있을 수 있으니, 실행이 안 되면 괄호 짝부터 점검하자(여는 괄호 없는 닫는 괄호는 흔한 실수).

08 · 계층형 질의 ① 기본 보고 체계 (WITH RECURSIVE)#

① 한 줄 설명 — employees의 자기 참조(ReportsTo)를 재귀 CTE로 펼쳐 조직 보고 체계 전체를 레벨과 함께 조회한다.

② 코드 (출처: Day03_lecture.sql 5-1 / 노션 0610 — ✅ 실제 답지)

WITH RECURSIVE emp_hierarchy(
    EmployeeId, FirstName, LastName, Title, ReportsTo, lvl
) AS (
    -- Anchor: 최상위 직원 (Root)
    SELECT EmployeeId, FirstName, LastName, Title, ReportsTo,
           0 AS lvl
    FROM employees
    WHERE ReportsTo IS NULL

    UNION ALL

    -- Recursive: 직속 부하 반복 탐색
    SELECT e.EmployeeId, e.FirstName, e.LastName,
           e.Title, e.ReportsTo, h.lvl + 1
    FROM employees e
    JOIN emp_hierarchy h ON e.ReportsTo = h.EmployeeId
)
SELECT lvl                                                AS 계층레벨,
       EmployeeId                                         AS 직원ID,
       SUBSTR('                ', 1, lvl * 4)
           || FirstName || ' ' || LastName                AS 직원명,
       Title                                              AS 직책,
       ReportsTo                                          AS 관리자ID
FROM emp_hierarchy
ORDER BY lvl, EmployeeId;

③ 출력 결과 — 직원이 계층 레벨(0=사장) 순으로, 직원명이 레벨에 비례해 들여쓰기된 조직도 형태로 출력. 각 행에 직책·관리자ID 포함.

④ 한 줄씩 뜯어보기

  • 앵커: WHERE ReportsTo IS NULL → 관리자가 없는 최상위 1명, lvl=0.
  • UNION ALL : 앵커 결과와 재귀 결과를 계속 합치는 접착제.
  • 재귀: JOIN emp_hierarchy h ON e.ReportsTo = h.EmployeeId → “방금 찾은 사람(h)을 관리자로 둔 부하(e)“를 찾아 lvl+1. 더 찾을 부하가 없으면 종료.
  • SUBSTR(' ', 1, lvl * 4) : 레벨×4칸 공백으로 들여쓰기 흉내(Oracle의 LPAD 대용).

⑤ 💡 팁 — SQLite엔 Oracle의 CONNECT BY가 없어 이 WITH RECURSIVE가 표준 대안이다. 재귀가 헷갈리면 “앵커가 첫 줄을 깔고, 재귀가 그 아래 층을 한 단계씩 쌓는다"로 기억. 들여쓰기는 폰트·뷰어에 따라 의도대로 안 보일 수 있다(강사님 언급).

09 · 계층형 질의 ② 계층 + 집계 (담당 고객수·매출)#

① 한 줄 설명 — 08의 계층 CTE 결과에 customers·invoices를 LEFT JOIN하고 GROUP BY로 직원별 담당 고객수·매출을 붙인다.

② 코드 (출처: Day03_lecture.sql 5-2 / 노션 0610 — ✅ 실제 답지)

WITH RECURSIVE emp_hier(
    EmployeeId, FirstName, LastName, Title, ReportsTo, lvl
) AS (
    SELECT EmployeeId, FirstName, LastName, Title, ReportsTo, 0 AS lvl
    FROM employees
    WHERE ReportsTo IS NULL

    UNION ALL

    SELECT e.EmployeeId, e.FirstName, e.LastName,
           e.Title, e.ReportsTo, h.lvl + 1
    FROM employees e
    JOIN emp_hier h ON e.ReportsTo = h.EmployeeId
)
SELECT h.lvl        AS 계층레벨,
       h.EmployeeId AS 직원ID,
       SUBSTR('                ', 1, h.lvl * 4)
           || h.FirstName || ' ' || h.LastName AS 직원명,
       h.Title      AS 직책,
       COUNT(c.CustomerId)                     AS 담당고객수,
       ROUND(SUM(i.Total), 2)                  AS 담당매출합계
FROM emp_hier h
LEFT JOIN customers c ON h.EmployeeId = c.SupportRepId
LEFT JOIN invoices  i ON c.CustomerId  = i.CustomerId
GROUP BY h.EmployeeId, h.lvl, h.FirstName, h.LastName, h.Title
ORDER BY h.lvl, h.EmployeeId;

③ 출력 결과 — 계층 트리에 직원별 담당고객수·담당매출합계가 더해진 표. 담당 고객이 없는 직원(관리자급)은 0으로.

④ 한 줄씩 뜯어보기

  • CTE 부분은 08과 동일(이름만 emp_hier).
  • LEFT JOIN customers c ON h.EmployeeId = c.SupportRepId : 직원이 담당(SupportRep)하는 고객 연결. LEFT라 담당 고객 없는 직원도 빠지지 않는다.
  • LEFT JOIN invoices i ON c.CustomerId = i.CustomerId : 그 고객들의 청구서 → 매출 집계.
  • GROUP BY에 lvl·이름 등을 함께 넣어 들여쓰기·표시용 컬럼을 유지.

⑤ 💡 팁 — 어제 배운 집계+조인이 계층형 위에 그대로 얹힌다. LEFT JOIN이 핵심 — INNER JOIN이면 담당 고객이 없는 상위 관리자가 결과에서 사라진다. “전부 보존"이 필요하면 LEFT.

10 · 계층형 질의 ③ 경로 추적 + Leaf/Branch 판별#

① 한 줄 설명 — 재귀하면서 “루트 > … > 현재” 경로 문자열을 누적하고, 부하가 없는 직원을 Leaf로 표시한다.

② 코드 (출처: Day03_lecture.sql 5-3 / 노션 0610 — ✅ 실제 답지)

WITH RECURSIVE emp_path(
    EmployeeId, FirstName, LastName, Title, ReportsTo, lvl, path
) AS (
    SELECT EmployeeId, FirstName, LastName, Title, ReportsTo,
           0,
           FirstName || ' ' || LastName AS path
    FROM employees
    WHERE ReportsTo IS NULL

    UNION ALL

    SELECT e.EmployeeId, e.FirstName, e.LastName,
           e.Title, e.ReportsTo, p.lvl + 1,
           p.path || ' > ' || e.FirstName || ' ' || e.LastName
    FROM employees e
    JOIN emp_path p ON e.ReportsTo = p.EmployeeId
)
SELECT lvl        AS 계층레벨,
       EmployeeId AS 직원ID,
       path       AS 조직경로,
       Title      AS 직책,
       CASE
           WHEN EmployeeId NOT IN (
               SELECT ReportsTo
               FROM employees
               WHERE ReportsTo IS NOT NULL
           ) THEN 'Leaf'
           ELSE 'Branch'
       END AS 노드유형
FROM emp_path
ORDER BY path;

③ 출력 결과 — 각 직원의 조직경로(예: Andrew Adams > Nancy Edwards > Jane Peacock)와, 부하 유무에 따른 Leaf/Branch 구분.

④ 한 줄씩 뜯어보기

  • 앵커에서 path를 자기 이름으로 시작.
  • 재귀에서 p.path || ' > ' || ... : 부모 경로 뒤에 자기 이름을 이어 붙여 전체 경로를 누적. (Oracle SYS_CONNECT_BY_PATH에 대응.)
  • CASE WHEN EmployeeId NOT IN (관리자로 등장하는 ID들) : 아무의 관리자도 아니면 = 부하 없음 = Leaf, 아니면 Branch.

⑤ 💡 팁 — 경로 누적은 카테고리 트리(가전 > TV > OLED)나 댓글 스레드에도 똑같이 쓰는 패턴이다. Leaf 판별의 NOT IN은 서브쿼리에서 ReportsTo IS NOT NULL로 NULL을 먼저 걸러야 안전하다(NOT IN + NULL 함정 회피).

11 · 계층형 질의 ④ 레벨별 인원 + 합계 (계층 + UNION ALL)#

① 한 줄 설명 — 계층 CTE를 레벨로 GROUP BY해 레벨별 인원을 세고, UNION ALL로 전체 합계 행을 붙인다(계층 + 소계 패턴 결합).

② 코드 (출처: Day03_lecture.sql 5-4 / 노션 0610 — ✅ 실제 답지)

WITH RECURSIVE emp_cte(
    EmployeeId, FirstName, LastName, Title, ReportsTo, lvl
) AS (
    SELECT EmployeeId, FirstName, LastName, Title, ReportsTo, 0
    FROM employees
    WHERE ReportsTo IS NULL

    UNION ALL

    SELECT e.EmployeeId, e.FirstName, e.LastName,
           e.Title, e.ReportsTo, c.lvl + 1
    FROM employees e
    JOIN emp_cte c ON e.ReportsTo = c.EmployeeId
)
SELECT 'Level ' || CAST(lvl AS TEXT) AS 계층레벨,
       COUNT(*)                      AS 직원수
FROM emp_cte
GROUP BY lvl

UNION ALL

SELECT '── 합계', COUNT(*)
FROM emp_cte

ORDER BY 계층레벨;

③ 출력 결과 — Level 0, Level 1, Level 2 … 각 레벨 인원수 + 맨 끝 ── 합계(전체 직원 수).

④ 한 줄씩 뜯어보기

  • CTE는 08·09와 동일 구조(emp_cte). (노션 답지는 이 CTE 본문을 ( ... )로 생략 표기 — 실제로는 5-1과 같은 정의를 넣어야 실행된다.)
  • 위 SELECT = GROUP BY lvl로 레벨별 인원, 아래 SELECT = 전체 인원 → UNION ALL로 합계 행.
  • 'Level ' || CAST(lvl AS TEXT) : 숫자 lvl을 문자열로 바꿔 Level 0 형태 라벨로.

⑤ 💡 팁 — 오늘 배운 두 주제(계층형 + 집합 연산 소계)가 한 쿼리에서 만난다. 재귀 CTE로 계층을 펼친 결과도 결국 하나의 표일 뿐이라, 02·06에서 한 UNION ALL 소계를 똑같이 얹을 수 있다. “배운 조각들이 서로 끼워 맞춰진다"는 걸 보여주는 마무리 문제.

🔎 단위 오타 메모(집계 함수 MAX): 정답본 1-4(a) “가장 긴 트랙(분)“은 원문이 SELECT MAX(Milliseconds) / 10000 ... 으로 되어 있다. 밀리초 → 분 환산이면 / 60000이 맞다(60,000ms = 1분). 노션엔 이 쿼리가 없어 대조 불가하므로 원문(/10000)을 보존하되, 분 단위가 의도라면 / 60000으로 읽어야 한다. 오늘 코드 노트 본문(01~11)은 집합 연산자·계층형에 집중하므로 이 집계 쿼리는 여기 메모로만 남긴다.

마무리#

오늘 실습은 조인 없이 합치고 빼는 법(UNION·UNION ALL·INTERSECT·EXCEPT)과 같은 테이블의 상하 계층을 펼치는 법(재귀 CTE)을 손으로 익혔다. UNION ALL로 엑셀 같은 소계 리포트를 만들고, 집합 연산 결과를 서브쿼리로 감싸 JOIN해 이름까지 붙이고, WITH RECURSIVE로 조직도를 펼쳐 거기에 다시 집계·경로·소계를 얹었다 — 어제 배운 집계·조인·서브쿼리가 오늘 주제와 그대로 맞물린다. 기억할 두 가지: DB마다 문법 지원이 다르다(MySQL INTERSECT/EXCEPT 미지원, Oracle CONNECT BY vs 표준 WITH RECURSIVE), 그리고 복잡할수록 “분할 → 각각 실행 → 합치기”.
