00 · 실습 환경설정 — 디버깅 포인트 ★먼저 읽기#

라이브에서 가장 많은 시간을 잡아먹은 건 분석 코드가 아니라 환경설정이었다. 코랩(리눅스)은 기본으로 한글 폰트가 없고, 데이터 경로/파일명에서 에러가 잦다. 여기를 먼저 통과해야 나머지가 돌아간다.

한글 폰트 설치 (코랩·리눅스)#

① 코랩에서 한글이 깨지면 나눔폰트를 설치한다. 설치 후 반드시 [런타임 > 세션 다시 시작] 해야 적용된다. (로컬 Windows/Mac은 이미 폰트가 있어 생략 가능 — 그래서 주석 처리되어 있다.)

② matplotlib에 한글 폰트를 적용한다. 플랫폼별로 try-except로 안전하게 잡는다. (원본 출처: pandas_예제.ipynb cell 2)

import platform
import matplotlib.pyplot as plt
from matplotlib import font_manager

def setup_matplotlib_korean_font() -> str | None:
    """Windows / Mac / 기타 순으로 한글 폰트를 try-except로 적용."""
    plt.rcParams["axes.unicode_minus"] = False   # 마이너스 기호 깨짐 방지
    system = platform.system()
    if system == "Windows":
        candidates = ["Malgun Gothic", "맑은 고딕"]
    elif system == "Darwin":
        candidates = ["Apple SD Gothic Neo", "AppleGothic"]
    else:
        candidates = ["NanumGothic", "Noto Sans CJK KR", "Malgun Gothic"]
    for family in candidates:
        try:
            prop = font_manager.FontProperties(family=family)
            path = font_manager.findfont(prop, fallback_to_default=False)
            if path and "dejavu" not in path.lower():
                plt.rcParams["font.family"] = family
                print(f"[한글 폰트] 적용: {family}")
                return family
        except Exception:
            continue
    return None

setup_matplotlib_korean_font()

③ 출력:

[한글 폰트] 적용: Malgun Gothic
'Malgun Gothic'

④ platform.system()으로 OS를 감지해 후보 폰트를 정하고, findfont로 실제 설치 여부를 확인한 뒤 첫 성공 폰트를 적용한다. Windows 환경이라 Malgun Gothic이 잡혔다. ⑤ 💡 axes.unicode_minus = False도 잊지 말 것 — 안 하면 음수 축 라벨의 마이너스 기호가 네모로 깨진다.

데이터 경로·파일명 디버깅#

⑤ 💡 강사가 반복 강조한 실수 4가지 — 코드 노트에 박아둔다.

  1. 경로는 직접 타이핑 금지 → 코랩 파일 메뉴의 “경로 복사” 로 붙여넣기.
  2. 경로 끝 슬래시(/) 누락 이 잦다 — pd.read_csv(data_path + 파일명)처럼 문자열을 연결할 때 data_path 끝에 /가 없으면 경로가 깨진다.
  3. 파일명 대소문자/오타 → FileNotFoundError. 에러 메시지에 찍힌 경로를 실제 파일과 한 글자씩 대조하라.
  4. 압축 해제 시 한글 파일명 깨짐(윈도우) → 파일명을 통일. 공유 폴더는 읽기 전용이라 더블클릭 편집 말고 다운로드 후 사용.

(견고한 버전) 헤더 시그니처로 CSV 자동 구분#

① 라이브에선 파일명을 직접 문자열로 이어 붙였지만, 예제 노트북은 파일명 대신 헤더(컬럼)로 어떤 표인지 판별하는 견고한 로더를 쓴다 — 파일명이 깨지거나 달라도 동작한다. (출처: pandas_예제.ipynb cell 5)

from pathlib import Path
import numpy as np
import pandas as pd

def resolve_jeonghyeong_dir() -> Path:
    cwd = Path.cwd()
    for c in (cwd / "소집교육" / "dataset" / "정형",
              cwd / "dataset" / "정형",
              cwd.parent / "dataset" / "정형"):
        if c.is_dir():
            return c.resolve()
    raise FileNotFoundError("dataset/정형 폴더를 찾을 수 없습니다.")

def load_three_tables(data_dir: Path):
    """헤더로 세 종류 CSV를 구분 (파일명 정규화 차이 무시)."""
    srv = sup = wel = None
    path_srv = path_sup = path_wel = None
    for p in sorted(data_dir.glob("*.csv")):
        cols = pd.read_csv(p, nrows=0, encoding="utf-8").columns.tolist()
        if "log_id" in cols and "server_id" in cols:
            srv, path_srv = pd.read_csv(p, encoding="utf-8"), p
        elif "supply_id" in cols:
            sup, path_sup = pd.read_csv(p, encoding="utf-8"), p
        elif "soldier_id" in cols:
            wel, path_wel = pd.read_csv(p, encoding="utf-8"), p
    return srv, sup, wel, path_srv, path_sup, path_wel

DATA = resolve_jeonghyeong_dir()
df_srv, df_sup, df_wel, path_server, path_supply, path_welfare = load_three_tables(DATA)
print("서버:", df_srv.shape, path_server.name)
print("군수품:", df_sup.shape, path_supply.name)
print("복지:", df_wel.shape, path_welfare.name)

③ 출력:

서버: (11000, 15) 서버유지보수_보정데이터(0512).csv
군수품: (11000, 15) 군수품자동청구_보정데이터(0512).csv
복지: (11000, 19) 장병복지시설이용_보완데이터(0512).csv

④ pd.read_csv(p, nrows=0)로 헤더만 먼저 읽어 컬럼 이름을 보고, log_id/supply_id/soldier_id라는 시그니처 컬럼으로 어떤 표인지 판별해 각각 df_srv·df_sup·df_wel에 담는다. ⑤ 💡 파일명에 의존하지 않는 게 핵심. 한글 파일명이 OS마다 깨질 수 있으니, 내용(헤더)으로 판별하면 환경이 바뀌어도 견고하다. 같은 맥락의 NFC/NFD 대응은 §07 끝에서 다룬다.

① 데이터를 올렸으면 규모·스키마·분포부터 본다. (출처: 문제1~10)

print(df_srv.shape)            # (11000, 15)

④ shape는 (행, 열) 튜플 — 세 표 모두 11,000행이다. info()는 열별 타입·비결측·메모리를, describe()는 수치형 요약을 준다. memory_usage(deep=True).sum()은 문자열까지 포함한 실제 메모리(바이트). ⑤ 💡 sample의 random_state=42 로 매번 같은 5행이 나온다(재현성). 어제 NumPy default_rng(42)와 같은 시드 고정 개념이다. 분석 전에 describe()로 각 열의 분포(min·max·사분위) 를 보는 습관이 뒤에서 문제27 같은 함정을 미리 잡아준다.

02 · 행·열 선택 (loc · [] · iloc)#

① loc(라벨)와 iloc(위치)로 행·열을 고른다. 형태는 df.loc[행, 열]. (출처: 문제11~18)

df_srv.loc[:, ['server_id','location','cpu_usage']].head()   # 모든 행 + 특정 열 (loc)
df_sup[['item_name','category','stock_level']].head()        # [] 로 열 선택
df_srv.iloc[0, :]                  # 첫 행 → Series
df_sup.iloc[:5, :3]                # 앞 5행 · 앞 3열 (끝 미포함)
df_srv.loc[df_srv.index[:10], ['log_id','check_type']]       # 인덱스 일부 + 열
df_sup.iloc[100:105]               # 중간 구간 100~104

④ loc[:, [...]]는 “모든 행 + 지정한 열”. iloc[0, :]는 첫 행을 Series로 꺼낸다(단일 행=1차원=Series). iloc[:5, :3]은 위치 기반 슬라이싱이라 끝 미포함(04행, 02열). ⑤ 💡 단일 컬럼 df['col']은 Series, 컬럼 리스트 df[['col']]은 DataFrame — 대괄호 개수가 결과 타입을 가른다. iloc 슬라이싱의 “끝 미포함"은 어제 NumPy 슬라이싱과 동일 규칙이다.

03 · 조건 필터링 (Boolean · & | · isin · 컬럼 간 비교)#

비교 연산이 만든 True/False Series를 loc에 넣어 행을 필터링한다. 어제 NumPy 불리언 마스킹과 원리가 같다.

단일 조건 · value_counts 기반#

① ② (출처: 문제19~21, 25)

df_srv.loc[df_srv['issue_category'] == '디스크', :].head()    # 이슈='디스크'
df_srv.loc[df_srv['cpu_usage'] > 40, :].head()                # CPU 40 초과
top_r = df_wel['region'].value_counts().index[0]              # 최빈 지역
df_wel.loc[df_wel['region'] == top_r, :].head()

④ df_srv['cpu_usage'] > 40은 11,000개짜리 True/False Series를 만들고, loc이 True인 행만 남긴다. value_counts().index[0]은 가장 빈도 높은 값(최빈값)을 꺼내 그걸로 필터링한 것. ⑤ 💡 “가장 많은 지역만 보기"처럼 데이터에서 동적으로 기준값을 뽑아 필터에 쓰는 패턴이 실무에서 잦다.

복합 조건 · isin#

① (출처: 문제22~24)

# AND — 두 조건 모두 (각 조건 괄호 + & )
df_srv.loc[(df_srv['fix_required']==1) & (df_srv['issue_detected']==1), :].head()
# isin — 여러 값 중 하나
df_srv.loc[df_srv['check_type'].isin(['일간','주간']), :].head()
df_srv.loc[df_srv['issue_category'].isin(['CPU과부하','디스크']), :].head()

④ 복합 조건은 and/or가 아니라 &/|, 그리고 각 조건을 괄호로 감싼다. isin([...])은 긴 (==A)|(==B)를 한 줄로 줄인다. ⑤ 💡 괄호를 빼면 연산자 우선순위 때문에 에러나 오작동한다 — 어제 NumPy (a>2)&(a<11)에서 강조한 것과 동일. 부정(NOT)은 앞에 ~.

★ 컬럼 간 비교#

① 상수가 아니라 다른 열과 비교한다. (출처: 문제26)

# 재고가 재발주 기준보다 낮은 행
df_sup.loc[df_sup['stock_level'] < df_sup['reorder_threshold'], :].head()

④ df_sup['stock_level'] < df_sup['reorder_threshold']는 행마다 두 열 값을 비교해 True/False Series를 만든다. “재고 부족” 같은 실무 조건이 이 형태. ⑤ 💡 강사는 iris로 Sepal.Width > Petal.Length를 시연했다 — 중간 계산 없이 두 열 비교가 한 줄로 축약되는 게 포인트.

⚠ 문제27 정정 — 60~80은 빈 결과#

① 원본 문제27을 그대로 실행한다. (출처: pandas_예제.ipynb cell 68)

df_wel.loc[(df_wel['mental_wellbeing_score'] >= 60) & (df_wel['mental_wellbeing_score'] <= 80), :].head()

④ 결과가 Empty DataFrame — 에러가 아니라 조건에 맞는 행이 0개다. mental_wellbeing_score의 실제 분포가 한 자리 수(1~10 수준) 라 60~80 구간엔 해당 행이 없다. ⑤ 💡 원본 예제의 오류로 보이는 부분이라 정직하게 정정한다. 라이브에서도 강사가 “6080 vs 68을 재확인해야 한다” 고 언급했다 — 의도한 구간은 6~8이었을 가능성이 높다. 데이터에 맞춘 버전:

# 정정 버전 — 데이터 분포(1~10)에 맞는 6~8 구간
df_wel.loc[(df_wel['mental_wellbeing_score'] >= 6) & (df_wel['mental_wellbeing_score'] <= 8), :].head()

⑤ 💡 분포가 한 자리 수라는 증거는 §05 문제39(rank별 median이 1~2)에서 직접 확인된다. 필터가 비면 “내 조건이 데이터 분포 안에 있나"를 describe()·value_counts()로 먼저 확인하라 — 빈 결과는 버그가 아니라 데이터에 대한 오해의 신호다.

① 값 기준으로 정렬한다. 기본 오름차순, ascending=False로 내림차순, 다중 키는 리스트. (출처: 문제29~32)

df_srv.sort_values('cpu_usage', ascending=False).head(8)         # CPU 높은 순 (최대 100.0)

df_srv.sort_values(['location','check_date']).head(8)            # 다중 키 (지역→날짜)

④ sort_values('col', ascending=False)로 내림차순, head(8)로 상위 8개. 다중 키 ['location','check_date']는 지역으로 먼저 묶고 같은 지역 안에서 날짜로 정렬한다. ⑤ 💡 다중 키에 방향을 따로 줄 수도 있다 — ascending=[True, False](지역 오름, 날짜 내림). SQL의 ORDER BY a, b DESC와 같다.

오늘 pandas의 핵심. Split(쪼개기) → Apply(집계) → Combine(합치기). 문법은 df.groupby(그룹컬럼)[수치컬럼].집계().

기본 집계#

① (출처: 문제3334, 3839)

df_srv.groupby('location')['log_id'].count().sort_values(ascending=False).head(10)  # 지역별 건수
df_srv.groupby('issue_category')['cpu_usage'].mean()                  # 이슈별 평균 CPU
df_wel.groupby('rank')['mental_wellbeing_score'].median()             # 계급별 중앙값

④ groupby('rank')로 계급별로 쪼개고, ['mental_wellbeing_score'].median()로 그룹마다 중앙값을 낸다. ⑤ 💡 이 출력이 §03 문제27 정정의 결정적 증거다 — 정신건강 점수의 중앙값이 1~2다. 점수가 한 자리 수이니 60~80 필터가 빈 결과였던 것. 그룹 컬럼은 아무거나가 아니라 범주형(rank·region)이나 값 종류가 제한된 수치가 적합하다.

① 한 번에 여러 통계를 낸다. (출처: 문제35~36)

df_srv.groupby('check_type')['fix_duration_hours'].agg(['mean','max'])
df_sup.groupby('category')['requested_quantity'].agg(['sum','mean'])

④ agg(['mean','max'])로 점검 유형별 평균·최대 수리시간을 동시에 낸다. ⑤ 💡 집계가 하나면 결과는 Series, 여럿이면(['mean','max']) 복수 컬럼 → DataFrame이 된다. 가능한 집계: count, sum, min, max, mean, median, std, var, quantile, first, last.

다중 그룹 + unstack#

① 두 컬럼으로 묶으면 인덱스가 다중(MultiIndex)이 된다. (출처: 문제40~41)

df_wel.groupby(['region','facility_type'])['satisfaction_score'].mean().head(15)   # 다중 그룹
df_wel.groupby(['region','facility_type'])['satisfaction_score'].mean().unstack()  # 표로 펼치기
df_sup.groupby('auto_reorder_flag').size()                                         # 그룹별 행 수

④ 다중 그룹 결과는 세로로 길게 쌓인 MultiIndex Series라 보기 불편하다. unstack()이 둘째 키(facility_type)를 열로 펼쳐 region×facility_type 교차표를 만든다. size()는 그룹별 행 개수. ⑤ 💡 unstack = MultiIndex를 피벗 테이블로. 펼친 뒤 df.loc['A지역', '체육시설']처럼 특정 조합 값을 바로 조회할 수 있다. groupby('x')만 하면 아직 DataFrameGroupBy 객체일 뿐 — 뒤에 집계 함수를 붙여야 결과가 나온다.

📎 여기부터는 라이브 당일이 아닌 자료 제공/후속 진행분(예제 노트북 후반). 같이 정리해 둔다.

결측 · 중복#

① (출처: 문제43~46)

④ isna().sum()은 열별 결측 개수(전체는 .sum().sum()). 수치열 결측은 중앙값(fillna(median())), 범주형은 fillna('Unknown')로 채운다. 중복은 duplicated().sum(), 키 기준 제거는 drop_duplicates(subset=[...]). ⑤ 💡 어제 §05의 “결측치 처리엔 정답이 없다, 비교 실험으로 고른다"가 여기 코드로 이어진다.

⚠ 문제61 정정 — inner merge가 0행#

① 두 테이블을 unit_code로 inner merge한다. (출처: pandas_예제.ipynb cell 149)

m = df_sup.merge(df_wel, on='unit_code', how='inner', suffixes=('_sup', '_wel'))
m.shape

③ 출력 (원본 실행 결과 그대로):

(0, 33)

④ 열은 33개로 합쳐졌는데 행이 0개다 — 또 에러는 아니다. inner는 양쪽 키가 일치하는 행만 남기는데, unit_code 값의 도메인이 서로 다르다: 군수품은 31A·18A 같은 코드형, 복지는 17사단·14사단 같은 명칭형이라 겹치는 값이 하나도 없다. ⑤ 💡 버그가 아니라 “merge 키 정합성"의 산 교훈이다. merge 전에 양쪽 키를 찍어 형식이 같은지 확인하라:

print(df_sup['unit_code'].unique()[:5])   # 예: ['31A' '18A' ...]  코드형
print(df_wel['unit_code'].unique()[:5])   # 예: ['17사단' '14사단' ...]  명칭형

도메인이 다르면 매핑 테이블로 한쪽을 변환하거나 키 자체를 재검토해야 한다. 참고로 정상 merge는 그룹 평균을 원본에 되붙이는 형태다 (문제63):

loc_cpu = df_srv.groupby('location', as_index=False)['cpu_usage'].mean()
df_srv.merge(loc_cpu, on='location', how='left', suffixes=('', '_locmean')).head()  # 정상 동작
merge how의미
inner교집합 (양쪽 키 일치 행만)
outer합집합 (없는 쪽은 NaN)
left/right왼쪽/오른쪽 기준

07 · ★ 벡터화 — 루프 vs 배열 연산#

📎 별도 노트북 vectorization.ipynb. 어제 NumPy “가장 중요"라 한 벡터화를 실측한다.

루프 vs 벡터화 — 속도 측정#

① 같은 계산을 루프와 벡터화로 각각 돌려 시간을 잰다. (출처: vectorization.ipynb cell 12)

rng = np.random.default_rng(0)
n = 50_000
a = rng.random(n).astype(np.float64)
b = rng.random(n).astype(np.float64)

# 루프 — 파이썬이 5만 번 반복
t0 = time.perf_counter()
out_loop = np.empty(n)
for i in range(n):
    out_loop[i] = a[i] * b[i] + np.sqrt(a[i])
t_loop = time.perf_counter() - t0

# 벡터화 — 배열 전체를 한 번에 (내부 C 루프)
t0 = time.perf_counter()
out_vec = a * b + np.sqrt(a)
t_vec = time.perf_counter() - t0

np.testing.assert_allclose(out_loop, out_vec, rtol=1e-12)   # 결과 동일 검증
print(f"loop:   {t_loop*1000:.1f} ms")
print(f"vector: {t_vec*1000:.1f} ms")
print(f"speedup: {t_loop / t_vec:.1f}x")

③ 출력:

loop:    17.3 ms
vector: 0.4 ms
speedup: 39.4x

④ 두 방식의 결과는 assert_allclose로 동일함을 검증했고, 벡터화가 약 39배 빠르다. 루프는 파이썬 인터프리터가 5만 번 도는 반면, a*b + np.sqrt(a)는 내부 C 루프로 한 번에 처리한다. ⑤ 💡 절대 수치는 환경·난수에 따라 달라진다 — 17.3ms나 0.4ms 자체가 아니라 “수십 배 차이"라는 자릿수가 핵심이다. 실데이터 파생변수 생성이 전부 이 패턴이다.

실데이터 파생변수 — 벡터화 패턴#

① 0으로 나누기 방지(clip·eps)와 함께 군수품 파생변수를 만든다. (출처: vectorization.ipynb cell 4, 발췌)

eps = 1e-6
usage = mil["avg_daily_usage"].clip(lower=eps)   # 0 나눗셈 방지
mil["stock_runway_days"] = (mil["stock_level"] / usage).replace([np.inf, -np.inf], np.nan)
mil["expected_demand_in_lead_time"] = mil["avg_daily_usage"] * mil["delivery_lead_time"]
mil["weekend_adjusted_daily"] = mil["avg_daily_usage"] * (1.0 + mil["weekend_usage_ratio"].fillna(0))
mil["reorder_gap"] = mil["reorder_threshold"] - mil["stock_level"]

④ 열 전체에 사칙연산을 한 번에 적용해 파생변수(재고 버티는 일수·예상 수요·재발주 갭 등)를 만든다. 루프 없이 11,000행이 한 줄에 계산된다. ⑤ 💡 0으로 나누기 방지가 실무 단골. 분모가 될 수 있는 값엔 clip(lower=eps)나 np.where(denom<1e-9, 1.0, denom)를 건다. 서버는 mean(axis=1) 자원부하·np.log1p, 복지는 min-max 정규화, 엑셀은 np.nanmean/nanstd z-score로 같은 벡터화 패턴이 반복된다.

NFC/NFD — 한글 파일명 자모분리 대응#

① macOS(NFD)와 Windows/Linux(NFC)는 한글을 다르게 저장해, 파일명 매칭이 깨질 수 있다. (출처: vectorization.ipynb cell 2)

import unicodedata

def pick_csv(keyword: str) -> Path:
    kw = unicodedata.normalize("NFC", keyword)           # 키워드를 NFC로
    for p in sorted(정형_dir.glob("*.csv")):
        name = unicodedata.normalize("NFC", p.name)      # 파일명도 NFC로
        if kw in name:
            return p
    raise FileNotFoundError(f"키워드 {keyword!r}에 해당하는 CSV가 없습니다.")

④ macOS는 ‘가’를 자모(ㄱ+ㅏ)로 분리 저장(NFD), Windows/Linux는 합쳐서(NFC) 저장한다. 그냥 문자열 비교하면 같은 ‘군수품’도 안 맞을 수 있어, 양쪽을 normalize("NFC")로 통일해 비교한다. ⑤ 💡 §00의 “헤더로 CSV 구분"과 함께, OS 차이에 강한 데이터 로딩의 양대 기법이다. 한글 파일명을 코드에서 다룰 때 깨짐이 의심되면 이 정규화를 먼저 의심하라.
