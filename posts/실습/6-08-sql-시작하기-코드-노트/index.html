01 · SELECT / FROM · 컬럼 선택 · LIMIT#

① 한 줄 설명 — 가장 기본. 어떤 컬럼을(SELECT) 어느 테이블에서(FROM) 가져올지 지정한다.

② 코드 (출처: Day01_lecture.sql)

-- 문제 1. albums 테이블에서 앨범 제목(Title)만 모두 보여주세요.
SELECT Title
FROM albums;

-- 문제 2. artists 테이블의 모든 정보를 보여주세요.
SELECT *
FROM artists;

-- 문제 3. tracks 테이블의 모든 컬럼을 앞 10건만 보여주세요.
SELECT *
FROM tracks
LIMIT 10;

-- 문제 4. tracks 테이블에서 곡 이름(Name)과 단가(UnitPrice)만 보여주세요. (앞 10건)
SELECT Name, UnitPrice
FROM tracks
LIMIT 10;

③ 출력 결과 — 문제 1은 앨범 제목 한 컬럼, 문제 2는 artists 전체 컬럼, 문제 3·4는 10행만 출력된다.

④ 한 줄씩 뜯어보기

  • SELECT Title : Title 컬럼만 고른다. 여러 개면 Name, UnitPrice처럼 콤마로.
  • SELECT * : *는 모든 컬럼.
  • FROM albums : 데이터를 가져올 테이블.
  • LIMIT 10 : 앞 10건만. 데이터가 많을 때 미리보기용.

⑤ 💡 팁 — 큰 테이블을 통째로 SELECT *하면 느리다. 처음엔 LIMIT 10으로 구조를 확인하고 시작하자.

02 · DISTINCT (중복 제거)#

① 한 줄 설명 — 뒤에 오는 컬럼의 중복을 제거하고 보여준다.

② 코드 (출처: Day01_lecture.sql)

-- 문제 1. customers 테이블에서 Country를 중복 없이.
SELECT DISTINCT Country
FROM customers;

-- 문제 2. tracks 테이블에서 UnitPrice의 종류를 중복 없이.
SELECT DISTINCT UnitPrice
FROM tracks;

-- 문제 3. City와 Country를 함께 중복 없이.
SELECT DISTINCT City, Country
FROM customers;

③ 출력 결과 — 문제 1은 고객 국가의 “종류"만, 문제 3은 (City, Country) 조합의 종류만 출력된다.

④ 한 줄씩 뜯어보기

  • DISTINCT Country : Country 값에서 중복을 없앤다.
  • DISTINCT City, Country : 두 컬럼 조합 기준으로 중복 제거.

⑤ 💡 팁 — 컬럼이 2개 이상이면 “조합” 기준이라, 같은 도시여도 나라가 다르면 별개로 본다. “나라 종류 수만 알고 싶다"면 컬럼 하나만 DISTINCT 하자.

03 · WHERE + 비교 연산자#

① 한 줄 설명 — 조건에 맞는 행만 걸러낸다.

② 코드 (출처: Day01_lecture.sql)

-- 문제 1. Country가 'USA'인 고객.
SELECT *
FROM customers
WHERE Country = 'USA';

-- 문제 2. UnitPrice가 0.99 초과인 곡. (앞 10건)
SELECT *
FROM tracks
WHERE UnitPrice > 0.99
LIMIT 10;

-- 문제 3. invoices에서 Total이 10 이상인 건.
SELECT *
FROM invoices
WHERE Total >= 10;

③ 출력 결과 — 각 조건을 만족하는 행만 출력된다.

④ 한 줄씩 뜯어보기

  • WHERE Country = 'USA' : 문자열은 작은따옴표로 감싼다.
  • WHERE UnitPrice > 0.99 : 숫자는 따옴표 없이. >는 초과, >=는 이상.

⑤ 💡 팁 — = 하나는 “같다”(비교)다. 헷갈려서 따옴표를 빼면 컬럼/문자열 오류가 난다. 문자열 비교는 항상 따옴표 확인.

04 · 복합 조건 (AND / OR / NOT)#

① 한 줄 설명 — 여러 조건을 AND·OR·NOT으로 묶는다.

② 코드 (출처: Day01_lecture.sql)

-- 문제 1. Country가 'USA' 그리고 State가 'CA'인 고객.
SELECT *
FROM customers
WHERE Country = 'USA' AND State = 'CA';

-- 문제 2. Country가 'USA' 이거나 'Canada'인 고객.
SELECT *
FROM customers
WHERE Country = 'USA' OR Country = 'Canada';

-- 문제 3. Country가 'USA'가 아닌 고객.
SELECT *
FROM customers
WHERE NOT Country = 'USA';
-- (WHERE Country != 'USA' 와 동일)

③ 출력 결과 — 문제 1은 두 조건 모두 만족, 문제 2는 둘 중 하나, 문제 3은 USA가 아닌 고객.

④ 한 줄씩 뜯어보기

  • AND : 둘 다 만족해야 통과.
  • OR : 하나만 만족해도 통과.
  • NOT Country = 'USA' : 조건의 반대. Country != 'USA'와 같다.

⑤ 💡 팁 — 같은 컬럼을 여러 값과 OR로 길게 나열할 거면, 다음 절의 IN(...)이 훨씬 깔끔하다.

05 · 기타 연산자 (BETWEEN / IN / NOT IN)#

① 한 줄 설명 — 범위(BETWEEN)와 목록(IN/NOT IN)으로 조건을 건다.

② 코드 (출처: Day01_lecture.sql)

-- 문제 1. Total이 5~10 사이(포함)인 인보이스.
SELECT *
FROM invoices
WHERE Total BETWEEN 5 AND 10;

-- 문제 2. 미국, 캐나다, 브라질 고객.
SELECT *
FROM customers
WHERE Country IN ('USA', 'Canada', 'Brazil');

-- 문제 3. 위 세 나라를 제외한 나머지.
SELECT *
FROM customers
WHERE Country NOT IN ('USA', 'Canada', 'Brazil');

③ 출력 결과 — 문제 1은 5~10 범위(경계 포함), 문제 2는 세 나라, 문제 3은 그 외 나라.

④ 한 줄씩 뜯어보기

  • BETWEEN 5 AND 10 : 5와 10을 포함하는 범위.
  • IN ('USA', 'Canada', 'Brazil') : 목록 중 하나라도 일치.
  • NOT IN (...) : 목록에 없는 것.

⑤ 💡 팁 — BETWEEN은 경계값을 포함한다. “5 초과 10 미만"이 필요하면 Total > 5 AND Total < 10처럼 직접 써야 한다.

06 · LIKE (패턴 검색)#

① 한 줄 설명 — 특정 문자가 포함된 문자열을 와일드카드 %로 찾는다.

② 코드 (출처: Day01_lecture.sql)

-- 문제 1. 제목이 'Rock'으로 시작하는 앨범.
SELECT *
FROM albums
WHERE Title LIKE 'Rock%';

-- 문제 2. 제목이 'Live'로 끝나는 앨범.
SELECT *
FROM albums
WHERE Title LIKE '%Live';

-- 문제 3. 곡 이름에 'Love'가 들어간 곡. (앞 10건)
SELECT *
FROM tracks
WHERE Name LIKE '%Love%'
LIMIT 10;

③ 출력 결과 — ‘Rock…’ 시작 앨범, ‘…Live’ 끝 앨범, ‘Love’ 포함 곡(10건).

④ 한 줄씩 뜯어보기

  • 'Rock%' : Rock으로 시작(% = 뒤에 아무거나).
  • '%Live' : Live로 끝남(% = 앞에 아무거나).
  • '%Love%' : Love 포함(앞뒤 아무거나).

⑤ 💡 팁 — %는 “임의의 문자열"이다. 한 글자만 매칭하는 _(언더스코어)도 있다. SQLite의 LIKE는 기본적으로 대소문자를 구분하지 않는다.

07 · ORDER BY (정렬)#

① 한 줄 설명 — 결과를 오름차순(ASC)·내림차순(DESC)으로 정렬한다.

② 코드 (출처: Day01_lecture.sql)

-- 문제 1. tracks를 UnitPrice 내림차순으로. (앞 10건)
SELECT Name, UnitPrice
FROM tracks
ORDER BY UnitPrice DESC
LIMIT 10;

-- 문제 2. 결제 금액이 가장 큰 인보이스 5건.
SELECT *
FROM invoices
ORDER BY Total DESC
LIMIT 5;

-- 문제 3. 앨범 제목을 알파벳 오름차순으로. (앞 10건)
SELECT Title
FROM albums
ORDER BY Title ASC
LIMIT 10;

③ 출력 결과 — 단가 높은 순 10곡, 결제액 큰 순 5건, 제목 알파벳 순 10개.

④ 한 줄씩 뜯어보기

  • ORDER BY UnitPrice DESC : UnitPrice 기준 내림차순(큰 값부터).
  • ORDER BY Title ASC : Title 기준 오름차순(작은 값/A부터). ASC는 기본값이라 생략 가능.

⑤ 💡 팁 — ORDER BY ... DESC + LIMIT n 조합이 “상위 n개” 뽑는 단골 패턴이다(예: 매출 TOP 5). 여기 DESC는 정렬용으로, 6/8 강의의 DESC 테이블명(구조 보기)과 다른 기능이다.

08 · DML 준비 — book 테이블 생성 + 시드#

① 한 줄 설명 — chinook를 건드리지 않기 위해, DML 연습용 book 테이블을 새로 만들고 데이터를 채운다.

② 코드 (출처: Day01_dml_lecture.sql, 원문 그대로)

-- 이미 있으면 지우고 새로 만들어, 몇 번을 실행해도 에러가 안 나게 함
DROP TABLE IF EXISTS book;

CREATE TABLE book (
    id       INTEGER PRIMARY KEY,
    title    TEXT,
    category TEXT,
    price    REAL,     -- 단위: £ (사이트 값, 무작위라 의미는 없음)
    rating   INTEGER,  -- 1~5 (연습용)
    stock    INTEGER   -- 재고 수량 (연습용)
);

INSERT INTO book (id, title, category, price, rating, stock) VALUES
(1,  'A Light in the Attic',                 'Poetry',             51.77, 3, 22),
(2,  'Tipping the Velvet',                   'Historical Fiction', 53.74, 1, 20),
(3,  'Soumission',                           'Fiction',            50.10, 1, 20),
(4,  'Sharp Objects',                        'Mystery',            47.82, 4, 20),
(5,  'Sapiens: A Brief History of Humankind','History',            54.23, 5, 20),
(6,  'The Requiem Red',                       'Young Adult',        22.65, 1, 19),
(7,  'The Dirty Little Secrets of Getting Your Dream Job', 'Business', 33.34, 4, 19),
(8,  'The Black Maria',                       'Poetry',             52.15, 1, 19),
(9,  'Starving Hearts',                       'Fiction',            13.99, 2, 18),
(10, 'Shakespeare''s Sonnets',                'Poetry',             20.66, 4, 18),
(11, 'Scott Pilgrim''s Precious Little Life', 'Sequential Art',     52.29, 5, 16),
(12, 'Rip it Up and Start Again',             'Music',              35.02, 5, 15);

-- 시드가 잘 들어갔는지 확인
SELECT * FROM book;

③ 출력 결과 — 마지막 SELECT * FROM book;에서 12개 행이 모두 출력되면 성공이다.

④ 한 줄씩 뜯어보기

  • DROP TABLE IF EXISTS book : book이 있으면 지운다. 덕분에 몇 번 실행해도 에러가 안 난다(재실행 가능 패턴).
  • CREATE TABLE book (...) : 컬럼과 자료형(INTEGER/TEXT/REAL)을 정의. id INTEGER PRIMARY KEY는 각 행을 구분하는 기본 키.
  • INSERT INTO book ... VALUES (...), (...) : 여러 행을 한 번에 삽입.
  • 'Shakespeare''s Sonnets' : 제목 속 작은따옴표는 **두 번('')**으로 이스케이프.

⑤ 💡 팁 — DROP TABLE IF EXISTS → CREATE → INSERT 순서를 한 스크립트에 묶어두면, 데이터가 꼬여도 위에서부터 다시 실행해 언제든 초기 상태로 복구할 수 있다.

데이터 출처: 제목·가격은 https://books.toscrape.com/ 의 값, 카테고리·평점·재고는 연습용 임의값이다.

09 · INSERT / UPDATE / DELETE#

① 한 줄 설명 — book 테이블에 행을 추가(INSERT)·수정(UPDATE)·삭제(DELETE)한다. (8번을 먼저 실행해 book이 있어야 한다.)

② 코드 (출처: Day01_dml_lecture.sql)

-- 8. INSERT --------------------------------------------------
-- 문제 1. 신간 'It''s Only the Himalayas' (Travel, £45.17, 평점 2, 재고 19) 추가.
INSERT INTO book (id, title, category, price, rating, stock)
VALUES (13, 'It''s Only the Himalayas', 'Travel', 45.17, 2, 19);

-- 문제 2. 컬럼명 생략 방식으로 'Set Me Free' (Young Adult, £17.46, 평점 5, 재고 19) 추가.
INSERT INTO book
VALUES (14, 'Set Me Free', 'Young Adult', 17.46, 5, 19);

SELECT * FROM book;

-- 9. UPDATE --------------------------------------------------
-- 문제 1. 'Soumission' 가격을 50.10 -> 39.99 로 변경.
UPDATE book
SET price = 39.99
WHERE title = 'Soumission';

-- 문제 2. Poetry 책들의 stock 을 기존 값 + 5 로 변경.
UPDATE book
SET stock = stock + 5
WHERE category = 'Poetry';

SELECT * FROM book;

-- 10. DELETE -------------------------------------------------
-- 문제 1. 평점이 1점인 책들을 모두 삭제.
DELETE
FROM book
WHERE rating = 1;

-- 문제 2. 재고(stock)가 16권 미만인 책 삭제.
DELETE
FROM book
WHERE stock < 16;

SELECT * FROM book;

-- ★ 주의: UPDATE / DELETE 에서 WHERE 를 빼면 전체 행이 수정·삭제됩니다.
--         예) DELETE FROM book;  -> book 전체 삭제

③ 출력 결과 — 각 SELECT * FROM book;에서 변화가 확인된다. INSERT 후 14행, UPDATE 후 Soumission 가격·Poetry 재고 변경, DELETE 후 평점 1·재고 16미만 책이 사라진다.

④ 한 줄씩 뜯어보기

  • INSERT INTO book (컬럼...) VALUES (값...) : 컬럼을 명시한 삽입.
  • INSERT INTO book VALUES (...) : 컬럼 생략 → 테이블 정의 순서대로 값이 들어간다.
  • UPDATE book SET price = 39.99 WHERE title = 'Soumission' : 조건에 맞는 행의 price만 변경.
  • SET stock = stock + 5 : 기존 값 기반 연산도 가능.
  • DELETE FROM book WHERE rating = 1 : 조건에 맞는 행 삭제.

⑤ 💡 팁 — UPDATE·DELETE는 반드시 WHERE를 확인하라. WHERE를 빼면 전체 행이 대상이 된다(DELETE FROM book; = 전부 삭제). 실무에서 가장 위험한 실수다.

참고: 판서 기록의 과제 표현(“재고=15 삭제”)과 정답 SQL의 WHERE stock < 16(재고 16 미만)에 표현 차이가 있다. 본 노트는 **정답 파일 기준 stock < 16**을 그대로 따랐다 [원문 확인 필요].

10 · (보너스) book 테이블로 SELECT 연산자 복습#

① 한 줄 설명 — 앞서 chinook으로 배운 연산자들을 book 테이블로 한 번 더 복습한다.

② 코드 (출처: Day01_dml_lecture.sql 하단 보너스)

-- 카테고리 종류만 보기 (DISTINCT)
SELECT DISTINCT category FROM book;

-- 가격이 40 이상인 책 (비교 연산자)
SELECT * FROM book WHERE price >= 40;

-- 제목에 'the' 가 들어간 책 (LIKE, 대소문자 무시됨)
SELECT * FROM book WHERE title LIKE '%the%';

-- 가격이 비싼 순으로 정렬 (ORDER BY)
SELECT title, price FROM book ORDER BY price DESC;

③ 출력 결과 — 카테고리 종류, 40 이상 책, ’the’ 포함 책, 가격 내림차순 목록.

④ 한 줄씩 뜯어보기

  • 위 SELECT 연산자(DISTINCT/WHERE/LIKE/ORDER BY)를 그대로 book에 적용한 것. 단, DELETE 이후라 남은 데이터 기준으로 결과가 나온다.

⑤ 💡 팁 — 같은 연산자도 테이블만 바꾸면 똑같이 동작한다. 작은 테이블(book)로 결과를 눈으로 확인하면 동작이 더 명확하게 보인다.

📚 보충 자료#

  • 강사 정답 SQL: Day01_lecture.sql(SELECT), Day01_dml_lecture.sql(DML) — 본 노트 쿼리의 원본
  • 실습 DB: chinook.db(SQLite Tutorial 샘플)
  • book 데이터 출처: https://books.toscrape.com/ (제목·가격) + 연습용 임의값(카테고리·평점·재고)
  • SQLite 공식 문서 — https://www.sqlite.org/lang.html

다시 강조: 이 노트의 쿼리·예시는 학습용 정리다. 6/8 쿼리는 강사 정답 파일에서 그대로 가져왔으나, 실행 결과는 DB 데이터 버전에 따라 미세하게 다를 수 있다.

마무리#

오늘 실습의 뼈대는 두 가지다. (1) SELECT로 골라보기 — 컬럼 선택, DISTINCT, WHERE·복합조건·BETWEEN/IN, LIKE, ORDER BY를 chinook으로 익혔다. (2) DML로 바꾸기 — 안전을 위해 직접 만든 book 테이블에서 INSERT·UPDATE·DELETE를 연습했다. 핵심 습관 한 가지만 챙기자 — UPDATE·DELETE 실행 전 WHERE를 꼭 확인. 그리고 스크립트는 항상 위에서부터 순서대로 실행하자.
