6/18 pandas & 데이터 시각화 — 표를 가공하는 손과, 데이터를 보여주는 눈

4주차 둘째 날. 어제 NumPy(분석의 손)를 잡았다면 오늘은 그 위에 선 pandas로 실제 표 데이터를 가공하고, 후반부엔 그 결과를 어떻게 보여줄지 — 데이터 시각화 이론을 다룬다. 1부 pandas는 군 데이터셋(서버·군수품·복지 각 11,000행)으로 데이터 로드·점검(shape/info/describe) → DataFrame vs Series → loc/iloc → 조건 필터링(단일·복합·isin·컬럼 간 비교) → 정렬 → groupby/agg/unstack 집계까지 70제 실습. 핵심은 Split-Apply-Combine과 벡터화. 2부 데이터 시각화는 나이팅게일 Rose Diagram과 앤스컴 콰르텟으로 “왜 시각화인가"를 짚고, 시각화 원리(삭제>분리>강조>배열), 미학 요소·좌표계·색상 스케일(CVD-safe), 목적별 차트, 비례 잉크 원칙까지 이론으로 다룬 뒤 matplotlib/seaborn/plotly/streamlit 실습을 후속 차시로 예고했다.

6/16 정규화 & 데이터베이스 구현 — normalization_compare 데모·단계별 CREATE TABLE 실습 노트

같은 학생·수강 데이터를 4단계(비정규화/1NF/2NF/3NF) DB에 똑같이 저장하고, 갱신·삽입·삭제를 해보며 어떤 단계에서 이상현상이 나는지 비교하는 normalization_compare 데모가 하이라이트다. 핵심은 이상 상태 표 — 비정규화·1NF는 이상 존재, 2NF는 학과 갱신 이상(이행 종속)만 잔존, 3NF는 정상. 4가지 시나리오(학과건물 변경·교수연구실 변경·수강 등록·학생 삭제)로 직접 확인한다. 이어서 정규화 SQL 답지(student_course_all → 1nf → 2nf 3테이블 → 3nf 5테이블)를 단계별로 verbatim 수록하고, 각 단계가 어떤 종속을 제거하는지 짚는다. 실습은 SQLite(sqlite3)이고, 슬라이드 DB구현은 MySQL 기준(GRANT/REVOKE·SHOW INDEX)이라는 차이를 라벨로 구분한다.

6/15 데이터베이스 개요 & 구성하기 — school_db 5테이블 CREATE·제약조건·constraint_demo 실습 노트

SQLite로 school_db 5테이블(department/professor/student/course/enrollment)을 제약조건·복합PK·FK까지 직접 CREATE하고, NOT NULL/UNIQUE/DEFAULT/CHECK/PK/FK가 위반 시 어떻게 막히는지 예제로 확인한다. 하이라이트는 constraint_demo — 같은 회원가입 UI인데 good.db는 가입되고 bad.db는 과도한 CHECK와 잘못된 FK+DEFAULT 때문에 가입이 안 되는 사례. SQLite는 FK가 기본 OFF라 PRAGMA foreign_keys=ON이 필수이고, 슬라이드의 ALTER MODIFY/ADD CONSTRAINT/information_schema는 미지원이라 PRAGMA·테이블 재생성으로 우회한다는 점도 라벨로 구분한다.
